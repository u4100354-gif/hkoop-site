### 1. HIGH — Next.js 14.2.5 ниже security-патчей

**Место:** `package.json:12` (`"next": "14.2.5"`).

**Проверка (инспекция, повторяемо):** `grep '"next"' package.json` → `"next": "14.2.5"` (август 2024, ниже последующих патчей ветки 14.2.x). Поиск middleware и роутов: файлов `app/**/route.ts` нет (glob пуст), `middleware.ts` нет, в `next.config.js:9-24` только `redirects` (это не middleware). Полный `npm audit` в песочнице не выполнялся, поэтому список GHSA по выводу аудита не утверждаю. Твёрдо ссылаюсь только на CVE-2025-29927 (обход через заголовок `x-middleware-subrequest`, затрагивает 14.x до 14.2.25): прямого пути эксплуатации здесь сейчас нет — middleware нет, прод — статический экспорт. Severity HIGH — как supply-chain гигиена (публично сканируемая старая версия, риск оживает при добавлении middleware), а не как активный RCE.

**Фикс (без применения):** обновить `next` до последнего патча ветки 14.2.x (проверить `npm view next versions`, не ниже 14.2.25), затем `npx tsc --noEmit` и `STATIC_EXPORT=1 npm run build`, добавить `npm audit` в CI перед каждым деплоем.

### 2. HIGH — Пароли в версионированном `db/README.md`

**Место:** `db/README.md:8-11` и `db/README.md:20,22`.

**Факт:** в git лежат логин и пароль двух пользователей БД (цитата, секреты скрыты): `root / <скрыто>`, `hkoop / <скрыто> (все права на базу hkoop)`. Те же секреты повторяются в shell-примерах строк 20 и 22 вида `mysql -u hkoop -p'<скрыто>' hkoop < ...` — они текут в историю shell и логи даже после зачистки строк 8-11.

**Проверка (инспекция):** `sed -n 8,11p db/README.md` и `sed -n 20,22p db/README.md` показывают оба места.

**Канал утечки (точно):** прод на GitHub Pages отдаёт только содержимое `out/` (`next.config.js:6-7`, `output: export`), историю git он не публикует. Риск — если репозиторий публичен или расшарен: тогда пароли из истории читает любой. Это тот же класс нарушения, что убранный ранее хардкод пароля, но в другом файле.

**Фикс:** убрать секреты из строк 8-11 и заменить примеры в 20,22 на `mysql -u "$DB_USER" -p"$DB_PASS" "$DB_NAME" < ...` (или `mysql --defaults-extra-file="$HOME/.my.cnf"`); сменить оба пароля; вычистить историю (`git filter-repo` или пересоздание); добавить gitleaks в pre-commit/CI.

### 3. MEDIUM — Cookie-баннер: нет отказа, ссылка не на политику

**Факт:**

<a href="/docs">политикой конфиденциальности</a>  // каталог, а не текст политики

### 6. MEDIUM — Превью PDF без sandbox

**Место:** `components/DocsFilter.tsx:42` (`setPreview(safeHref(d.file_local)!)`), `:56` (`<iframe src={preview} ... title="PDF" />` без `sandbox`).

**Факт:** `safeHref` (`lib/url.ts:3-9`, `/^(https?:\/\/|\/[^/\\])/i`, лимит 2000) режет только схему — любой `https://` проходит. При скомпрометированной учётке редактора `file_local=https://evil.example/phish.html` откроется в iframe под шапкой сайта с top-навигацией.

**Фикс:** `sandbox=""` без `allow-top-navigation` и без `allow-scripts` для просмотра; iframe только для site-relative `/docs/*.pdf`, внешнее — ссылкой в новой вкладке `rel="noreferrer"`.

### 7. MEDIUM — Форма вводит в заблуждение; согласие без реквизитов

**Фикс:** подпись «Демо: форма пока никуда не отправляется, звоните 8 (4212) 32-87-18» + ссылка на политику у чекбокса; при бэкенде — полное согласие, success/error, `maxLength` (см. № 11).

### 8. MEDIUM — Книга почёта без видимых согласий

**Место:** `app/honor/page.tsx:11-22` (`SELECT * FROM honor`, рендер `h.fio`, `h.photo`, `h.title || h.text`).

**Факт:** массовая публикация ФИО, фото, биографий; пометок о согласиях в коде нет. Хранение в РФ (БД `hkoop` на 127.0.0.1) — хорошо. Обычные портреты без идентификации техсредствами — не биометрические ПДн, ст. 11 ФЗ-152 не применяется.

**Норма:** ст. 10.1 ФЗ-152 (ПДн, разрешённые для распространения), ст. 152.1 ГК РФ (изображение гражданина), ст. 18.1 ФЗ-152.

**Фикс:** письменные согласия каждого лица (или наследников) по ст. 10.1, срок и отзыв, снятие карточки при отзыве, строка в футере о согласиях.

### 9. MEDIUM — Нет охранных заголовков (статика ограничивает)

**Место:** `next.config.js` (секции `headers` нет).

**Проверка (живой probe):**
```
curl.exe -s -D - -o NUL http://localhost:3100/
→ HTTP/1.1 200 OK; Vary, Cache-Control: no-store, must-revalidate, Content-Type — и всё.
Нет content-security-policy, x-frame-options, x-content-type-options, referrer-policy. X-Powered-By отсутствует (poweredByHeader: false держится).
```
Страница встраивается в чужой iframe (кликджекинг формы). `frame-ancestors` через `<meta http-equiv>` не работает (только HTTP-заголовок), а `headers()` при `output: export` игнорируется — обещать закрытие через meta нельзя.

**Фикс для GitHub Pages:** meta-CSP без `frame-ancestors` (`object-src 'none'`, `base-uri 'self'`, allowlist `mc.yandex.ru`, `yandex.ru/map-widget`), `Referrer-Policy` мета-тегом. JS frame-busting — только частичное смягчение (обходится sandbox у атакующего), не закрытие. Полное закрытие (`frame-ancestors`/`X-Frame-Options`, HSTS за HTTPS) — только на хостинге с заголовками. Уточнение: флаг согласия хранится в localStorage (`hkoop-cookie`, `lib/storage.ts`), cookie в проекте нет — выставлять `SameSite` нечему.

### 10. LOW — `img src` из БД без allowlist (не XSS)

**Место:** `app/honor/page.tsx:14` (`<img src={h.photo}>`), `components/PartnersStrip.tsx:11` (`<img src={p.logo}>`; через `safeHref` там идёт только `p.url`, строка 21).

**Факт (инспекция):** `src` картинок не фильтруется. Честно: в `<img>`-контексте `javascript:` не исполняется — XSS здесь нет, внешнего URL в текущих данных не показано. Остаток условный: если в БД окажется внешний `https:` (скомпрометированная учётка), браузер отдаст чужому серверу IP и User-Agent. Поэтому LOW, а не MEDIUM.

**Норма (условно):** ст. 9, п. 5 ч. 1 ст. 18.1 ФЗ-152 — только если внешний URL появится.

**Фикс:** `h.photo` и `p.logo` через `safeHref` (или `safeImgSrc`: site-relative + доверенные CDN), при `null` — заглушка.

### 11. LOW — Поля без `maxLength` и типов

**Место:** `components/ConsultForm.tsx:5-7`, `components/HeaderSearch.tsx`, `components/DocsFilter.tsx:28`, `components/NewsFilter.tsx`, `app/search/page.tsx:34`.

**Проверки (живые пробы):** `GET /search?q=<script>alert(1)</script>` → в HTML `value="&lt;script&gt;alert(1)&lt;/script&gt;"`, живого `<script>alert` нет (`NO-RAW-SCRIPT`); `GET /search?q=` + 1200 «A» → 200 без падения; `GET /api/test` → 404.

**Фикс:** `maxLength={200}` имя/контакт/поиски, `maxLength={2000}` вопрос, контакту `type="tel"`, лимиты продублировать сервером при появлении приёма.

### 12. LOW — Версия для слабовидящих недожата

**Место:** `components/ViProvider.tsx`, кнопка в шапке. **Факт:** включается (`body.vi-mode`), переживает перезагрузку, шрифт и отключение картинок есть, skip-ссылка есть. Нет: сохранения всех флагов, высококонтрастных схем, `aria-pressed`. **Норма:** ГОСТ Р 52872-2019. **Фикс:** сохранять флаги, 2–3 схемы, `aria-pressed`, контраст WCAG AA 4.5:1.

### 13. LOW — Логотипы и фото (оргмера)

**Факт:** чужие товарные знаки и фото людей; признаков нарушения в коде нет, ссылки без `utm_*` и призывов — простое информирование, не реклама (ст. 16 ФЗ от 13.03.2006 № 38-ФЗ, позиция ФАС). **Норма:** ст. 1229, 1484, 152.1 ГК РФ. **Фикс:** согласия правообладателей и лиц в дело, строка в футере о разрешениях.

## Проверено и держится (с проверками)

- **SQL:** все `q()` в `app/*/page.tsx` — статические SELECT или `WHERE id=?` (`app/news/[id]/page.tsx:17`). Команда `Select-String -Pattern "q\(" app/*/page.tsx` → только `SELECT ...`. Probe `GET /news/nonexistent-id-xyz-123` → `<h1>Не найдено</h1>` без дампа и стектрейса.
- **Отражённый XSS:** `curl.exe -s "http://localhost:3100/search?q=%3Cscript%3Ealert(1)%3C/script%3E"` → `value="&lt;script&gt;alert(1)&lt;/script&gt;"`, проверка на `<script>alert` → `NO-RAW-SCRIPT`.
- **Пути:** `curl.exe -s "http://localhost:3100/news/%2e%2e%2f%2e%2e"` → `<p><a href="/news">← Все новости</a></p><h1>Не найдено</h1>`; причина по коду — `id` идёт только параметром в `WHERE id=?`, чтения файлов по `id` нет.
- **Секреты:** `curl.exe -s -o NUL -w "%{http_code}" http://localhost:3100/.env.local` → `404`; `X-Powered-By` в заголовках `/` отсутствует; `.gitignore` закрывает `.env`, `.env.local`, `.next-export`, `out/` (проверено чтением файла); нарушение сидит в `db/README.md` (см. № 2).
- **API/мутации:** glob `app/**/route.ts` — пусто; `GET /api/test` → `404`; поиск `INSERT|UPDATE|DELETE` по `app/*/*.tsx` — совпадений нет; `ConsultForm.tsx:4` — только `preventDefault`.
- **`safeHref`:** `lib/url.ts:3-9`, regex `/^(https?:\/\/|\/[^/\\])/i`, лимит 2000, режет `javascript:`/`data:`/`//evil`.
- **Импринт (ст. 10 № 149-ФЗ):** адрес (Хабаровск, ул. Муравьёва-Амурского, 4), телефон 8 (4212) 32-87-18, email ksps-priem@mail.ru — в шапке, футере, `/contacts` единообразно.
- **Политика (п. 5 ч. 1 ст. 18.1 ФЗ-152):** `GET /docs/politika.pdf` → `200 application/pdf`, ссылка с `/docs` есть (содержимое PDF — отдельная вычитка).
- **phpMyAdmin:** `GET http://127.0.0.1:8081/` → страница входа `loginform`, закрыт логином.
- **Реклама (38-ФЗ):** партнёрские ссылки — информационные, без маркировки допустимо.
