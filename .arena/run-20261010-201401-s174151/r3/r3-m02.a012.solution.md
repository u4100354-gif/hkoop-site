# Аудит сайта ХКООП: безопасность и соответствие законам РФ (включая 152-ФЗ)

## Вердикт коротко (один абзац)

Сайт устроен как закрытая витрина: SQL везде параметризован, ссылки из БД идут через allowlist, секреты по HTTP не отдаются, форма ничего никуда не отправляет — проверки ниже это подтверждают. Но фундамент скомпрометирован: пароли БД лежат в `db/README.md` и уже закоммичены в историю git, учётка сайта документирована как полнопривилегированная при чисто читающем коде, а Метрика и Яндекс-карта грузятся без согласия, хотя баннер обещает обратное. Плюс два честных белых пятна: машиночитаемый текст политики не извлечён (проверка неполная), прод на статическом экспорте юридически не оценён. Это чинится за дни без переделки архитектуры — и только после этого сайт можно спокойно показывать людям.

Подход: все внешние данные (строка `?q=`, сегмент `/news/<id>`, всё из БД) считались враждебными; чистота подтверждается контрольной точкой на каждой границе. Ниже — границы, где точки нет или она дырявая.

## Допущения

- Аудит по рабочему дереву ветки `backup-2026-10-10` как есть; проект, БД и git не менялись. Только чтение кода, безопасные GET к `http://localhost:3100` и `http://127.0.0.1:8081`, read-only чтение файлов. Прямых подключений к MySQL в этом пересмотре не выполнялось; проверка прав учётки — по документу в репозитории и коду, без соединения с БД.
- Значения паролей и хэши не печатаю (заменены на `<redacted>`).
- Прод (GitHub Pages, статический экспорт) отдельно по HTTP не щупался — выводы о нём только по `next.config.js`.

## Находки (по убыванию важности)

### C1. CRITICAL — пароли БД в `db/README.md`, закоммичены в историю git

- **Место:** `db/README.md:8-11,20-22`.
- **Проверка (инспекция + read-only git):** файл содержит две пары «пользователь / пароль» (root и `hkoop`, пометка «все права на базу hkoop») и команды заливки дампа с паролем в командной строке. Значения не привожу (`<redacted>`). Команды чтения (ничего не меняют): `git ls-files -- db/README.md` → `db/README.md` (трекается); `git log --oneline -- db/README.md` → коммит с заливкой сайта; `git show HEAD:db/README.md` содержит те же строки с паролями; `git ls-files -- .env.local` → пусто, `git check-ignore -v .env.local` → `.gitignore:5:.env.local`.
- **Факт:** секрет уже в истории: каждый клон несёт его с собой, смена пароля в рабочем дереве без зачистки истории доступ не отзывает. Рядом слушает сеть phpMyAdmin — `curl.exe -s -o NUL -w "%{http_code}" http://127.0.0.1:8081/` → `200`, тело содержит `<title>phpMyAdmin</title>` (вход с логином, анонимного доступа нет — но утекший пароль сразу превращается в доступ).
- **Фикс:** считать оба пароля скомпрометированными безусловно: сменить оба; из `db/README.md` оставить только шаблон (`DB_PASS=...`) без значений; зачистить историю (BFG/filter-repo) либо пересоздать репозиторий без секрета и отозвать клоны/форки; проверка секретов в pre-commit.

### M4. MEDIUM — нет защитных HTTP-заголовков; для прод-экспорта фикс только хостинговый

- **Место:** ответы `http://localhost:3100/` (конфиг — `next.config.js`, там только `poweredByHeader: false`; прод — `next.config.js:2,6-7`: `output: "export"` при `STATIC_EXPORT=1`).
- **Проверка (живой probe):** `curl.exe -sSI http://localhost:3100/` возвращает `HTTP/1.1 200 OK`, `Cache-Control: no-store, must-revalidate`, `Content-Type: text/html; charset=utf-8` — нет `Content-Security-Policy`, `X-Frame-Options`/`frame-ancestors`, `Strict-Transport-Security`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`. `X-Powered-By` отсутствует (держится). Сайт встраиваемый в чужой iframe (кликджекинг кнопки «Принять»/формы). Честное ограничение: `headers()` в `next.config.js` при статическом экспорте Next игнорирует, `<meta http-equiv>` не выставляет `X-Frame-Options`, `HSTS`, `frame-ancestors`.
- **Фикс:** заголовки — на уровне хостинга. Вариант А: прод за CDN/хостингом с заголовками (Cloudflare Pages / Netlify `_headers`, либо Cloudflare перед Pages): `frame-ancestors 'self'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy` (минимум), базовый CSP (`default-src 'self'`, `mc.yandex.ru` и `yandex.ru/map-widget` только после согласия). Вариант Б (частичная компенсация в коде): `<meta http-equiv>` для CSP/Referrer-Policy + frame-busting. Без переезда кликджекинг частично открыт — остаточный риск.
