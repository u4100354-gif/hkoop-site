# Аудит сайта ХКООП: безопасность и соответствие законам РФ (включая 152-ФЗ)

Дата: 10.10.2026. Объект: рабочее дерево `hkoop-site` (ветка `backup-2026-10-10`), dev http://localhost:3100. Проект не менялся: только чтение кода и безопасные GET-пробы. Секреты не печатаются. Язык отчёта — русский.

## Допущения

1. Прод — статический экспорт (`output: export` при `STATIC_EXPORT=1`, `next.config.js:6-7`) на GitHub Pages; часть выводов проверена на dev-сервере и явно помечена. Следствие: секция `headers()` из `next.config.js` в проде игнорируется, GitHub Pages средствами репозитория кастомные заголовки не задаёт; дефолтная раздача GH Pages охранных заголовков (CSP, X-Frame-Options, X-Content-Type-Options, Referrer-Policy) также не отдаёт — поэтому отсутствие заголовков, замеренное на dev, предсказывает и прод-состояние, а не только dev-артефакт.
2. В проекте нет `middleware.*` и нет `app/api/**` (мутаций на сервере нет) — это ограничивает эксплуатируемость ряда CVE рантайма в проде, но не снимает supply-chain риска сборки/dev.
3. Счётчик Метрики через `NEXT_PUBLIC_YM_ID` в проверяемом окружении не задан (живая проба ниже): трекер сегодня не грузится; дефект согласия — латентный, сработает при задании переменной.
4. Пароли в `db/README.md` приняты как есть из файла (не вводились никуда); phpMyAdmin проверен только безопасным GET без попыток входа.
5. CVE-данные — по открытым бюллетеням Next.js (проверка версии в `package.json`, без установки пакетов). Ошибочное упоминание чужого CVE-2024-39332 (Webswing) из прошлой редакции удалено; ниже — только бюллетени Next.js.

## Как читать отчёт

Каждая находка: severity → место → проверка (команда и вывод/цитата) → факт → фикс (описать, не применять). Юридические пункты содержат статью НПА. Все находки входят в ranked-список HIGH → MEDIUM → LOW, у каждой есть severity. В конце — чек-лист покрытия требований и вердикт одной строкой.

## HIGH

### H1. Пароли БД открытым текстом в дереве репозитория
- **Место:** `db/README.md:8-11,20,22`; дубль в `docs/ИНСТРУКЦИЯ-ПРЕСС-СЛУЖБЕ.md:28`.
- **Проверка (инспекция):** файлы лежат в рабочем дереве рядом с кодом и содержат логин/пароль root и `hkoop` + готовые команды `mysql -u hkoop -p'...'`. `.gitignore:1-8` закрывает только `.env`/`.env.local`, но не эти `.md`.
- **Факт:** любой `git push`/копия архива уносит секреты; после утечки обязательна ротация. То, что «пароли только локальные», не снимает риска: dev-пароли имеют свойство переезжать в прод.
- **Фикс (долговечный):** вынести секреты из обоих `.md` в `.env.local` (уже gitignored), в документации оставить плейсхолдеры вида `mysql -u $DB_USER -p"$DB_PASS"`; сменить оба пароля; проверить историю git (`git log -p -- db/README.md`) и при наличии ушедших коммитов считать скомпрометированными; добавить pre-commit-хук на секреты (gitleaks).

### H2. Нет охранных HTTP-заголовков (замер на dev; дефолт GH Pages их тоже не отдаёт)
- **Место:** `next.config.js:1-27` (секции `headers()` нет); эффект — все URL сайта.
- **Проверка (живая проба, dev):**
  ```
  GET /news/no-such-id-xyz → 200
  заголовки: Vary, x-nextjs-cache: HIT, Cache-Control: no-store/must-revalidate,
  Content-Type: text/html; charset=utf-8, Date
  → X-Powered-By: нет (держится); Content-Security-Policy: нет;
    X-Frame-Options: нет; X-Content-Type-Options: нет; Referrer-Policy: нет
  ```
- **Факт:** сайт можно встраивать в чужой `iframe` (кликджекинг формы/баннера), нет барьера для инлайн-скриптов и сниффинга типов. Честная оговорка о границах замера: заголовки измерены на dev (`localhost:3100`), но вывод распространяется и на прод, потому что (а) в коде заголовки нигде не задаются и (б) дефолтная раздача GitHub Pages кастомных охранных заголовков средствами репозитория не задаёт — прод по умолчанию тоже без CSP/X-Frame-Options. Сетевая угроза для localhost-минимальна, для публичного прод-домена — реальна.
- **Фикс (два трека):** (А) внутри репозитория, без смены хостинга: `rel="noreferrer noopener"` на внешних ссылках, `sandbox`+`referrerpolicy="no-referrer"` на iframe, клик-ту-загрузка карты (см. M3), `meta http-equiv="Content-Security-Policy"` и `meta referrer` как частичная компенсация (с ограничениями meta-CSP: без frame-ancestors/report-uri). (Б) опционально, вне репозитория: вынести прод за прокси/хостинг с поддержкой заголовков (например Cloudflare Transform Rules): `Content-Security-Policy: default-src 'self'; script-src 'self' https://mc.yandex.ru https://yandex.ru; frame-src https://yandex.ru; img-src 'self' data: https:; object-src 'none'; frame-ancestors 'self'` (уточнить под Метрику/карты), плюс `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, HSTS на прод-домене. Решение о треке Б принимает владелец сайта; трек А выполняется в любом случае.

### H3. Next.js 14.2.5 с известными CVE Next.js — обновить (HIGH, а не CRITICAL: прямого серверного вектора в проде сегодня нет)
- **Место:** `package.json:12` (`"next": "14.2.5"`), рядом `react: 18.3.1`, `mysql2: ^3.24.5`.
- **Проверка (инспекция кода):** версия зафиксирована `14.2.5` (август 2024), Dependabot/renovate-конфига нет. Подтверждено отсутствие `middleware.*` и пустота `app/api/**` — вектора CVE-2025-29927 (обход авторизации через `x-middleware-subrequest`, требует middleware, исправлен в 14.2.25/15.2.3) в проде эксплуатировать негде; собранный статический экспорт — HTML/CSS/JS без Next-сервера, dev слушает только localhost:3100.
- **Факт:** прямое RCE/обход в проде сегодня недоказуемы, поэтому CRITICAL был бы завышением. Но риск реален как supply-chain: сборка и dev-сервер крутятся на уязвимом рантайме (бюллетени ветки 14.2.x — CVE-2025-29927; семейство cache-poisoning/DoS, напр. CVE-2024-46982, закрывавшееся в 14.2.9–14.2.15), а любое будущее middleware/API унаследует дыру молча. CVE-2024-39332 к Next.js не относится (Webswing) и здесь не вменяется.
- **Фикс (долговечный):** поднять `next` минимум до `14.2.33+` (или 15.x LTS), затем `react/react-dom` до свежих 18.x, прогнать `npx tsc --noEmit` и `STATIC_EXPORT=1 npm run build`; включить регулярные обновления (Dependabot monthly + `npm audit` в CI). Диапазон `^` для `next` без lock-контроля не расширять.

## LOW

### L1. Два img-src из БД без allowlist (defense-in-depth, эксплуатируемого PoC нет)
- **Место:** `app/honor/page.tsx:14` (`<img src={h.photo}>`); `components/PartnersStrip.tsx:11` (`<img src={p.logo}>`).
- **Проверка (инспекция):** соседние рендеры фильтруются (`safeHref(p.url)`, `safeHref(file_local)`), а эти два `src` — нет. Честная оговорка: эксплуатируемого XSS здесь не показано — React экранирует атрибуты, а современные браузеры не исполняют `javascript:` в `<img src>`; это отсутствующий второй рубеж на случай компрометации БД (битые/чужие пути, мусор), а не активная дыра. Отдельно проверено по коду `lib/url.ts:7` (`/^(https?:\/\/|\/[^/\\])/i`, строка возвращается как есть): кириллические https-URL вида `https://хабаровсккурорт.рф/` проходят первую альтернативу без изменений и не ломаются.
- **Факт:** при правке БД сюда ляжет чужой/битый путь без валидации, тогда как `<a href>` уже закрыт.
- **Фикс:** ввести `safeSrc` рядом с `safeHref` (тот же allowlist `https?://` + site-relative, без переписывания кириллических https-доменов), при `null` — плейсхолдер со звездой (как уже есть в honor); добавить `referrerPolicy="no-referrer"` для внешних логотипов.

### L2. Внешние ссылки партнёров: явного `noopener` нет (в современных браузерах закрыто через `noreferrer`); партнёрский блок — информационный
- **Место:** `components/PartnersStrip.tsx:29`; `app/page.tsx:95`; проба: `GET /partners → 200; noreferrer=13, noopener=0, _blank=13`.
- **Проверка:** оговорка честно: по спецификации HTML `rel="noreferrer"` в современных браузерах включает поведение `noopener` (reverse-tabnabbing закрыт); явный `noopener` — лишь defense-in-depth для старых движков. `safeHref` пускает любой `https://` — доверенный блок «Полезные ссылки» может увести на фишинг при правке БД.
- **НПА (смежно):** ст. 10 Закона № 149-ФЗ (достоверность); партнёрский блок сейчас информационный (без «купить/скидка», без трекеров), маркировка по ст. 18.1 Закона № 38-ФЗ не требуется, но это надо зафиксировать регламентом.
- **Фикс:** `rel="noreferrer noopener"` везде с `_blank` (дешёвый второй рубеж); в админ-регламенте зафиксировать «партнёрские ссылки — некоммерческие, без вознаграждения»; при появлении платных размещений — пометка «Реклама» + erid по ст. 18.1 Закона № 38-ФЗ.

### L3. PDF-превью без песочницы; внешний https допустим как src iframe
- **Место:** `components/DocsFilter.tsx:42,56` (`<iframe src={preview} width height title>`).
- **Факт:** `preview` отфильтрован `safeHref`, но любой `https://` из `file_local` встанет в iframe без `sandbox` — при компрометации БД это фишинг-окно внутри доверенного домена.
