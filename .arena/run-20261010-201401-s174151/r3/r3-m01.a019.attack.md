ATTACK 1 [FATAL] Гипотеза выдана за находку — №14 без проверки
Where: «14 | LOW | Учётка БД по документации привилегированная при только чтении (условно, требует проверки)» и «Прямая проверка грантов (SHOW GRANTS) не выполнялась, поэтому какие привилегии реально есть (ALL? FILE? GRANT?) — неизвестно» (раздел №14).
Problem: Задача требует для каждой находки место и проверку (инспекция кода или живой probe с командой и выводом), а права mysql-пользователя прямо входят в обязательный перечень («права mysql-пользователя»). Автор признаёт, что проверки нет, но всё равно ставит пункт в ranked-список. Это не находка, а допущение. Контрпример: read-only `SHOW GRANTS` тем же соединением из `.env.local` выполняется без изменения проекта и даёт проверяемый вывод (`GRANT ALL PRIVILEGES ON hkoop.*`), то есть отговорка «требует проверки» не закрывает требование — требование пропущено.

ATTACK 2 [MAJOR] №1 про Next.js без аудита: нет команды, нет CVE-вывода, расплывчатый фикс
Where: «### 1. HIGH — Уязвимый Next.js 14.2.5», «зафиксирован next 14.2.5 (август 2024). С тех пор ветка 14.2.x получала критические патчи, главная — CVE-2025-29927… но остаются более поздние патчи 14.2.x (отравление кеша, DoS-векторы), которых в 14.2.5 нет».
Problem: Задача требует «Зависимости: package.json — известные CVE» и для каждой находки проверку с командой и выводом. В №1 нет ни `npm audit` (или иной команды), ни его вывода, ни списка GHSA. «Отравление кеша, DoS-векторы» названы без номеров CVE/GHSA — непроверяемо. Фикс «минимум до 14.2.25+» занижен и гадателен: реальный доступный фикс на день аудита — 14.2.35 (по выводу аудита), а автор сам признаёт, что для этого сайта «прямой эксплуатации этой CVE здесь нет» (нет middleware, прод — статический экспорт), то есть severity HIGH висит без показанного пути эксплуатации и без доказательств.

ATTACK 3 [MAJOR] Ложный механизм утечки: GitHub Pages якобы отдаёт историю git
Where: «а при публикации на GitHub Pages — потенциально весь интернет через историю git получает доступы» (№2).
Problem: Это фактически неверно. Прод — статический экспорт (Next `output: export`, см. `next.config.js:6-7`), на Pages публикуется содержимое `out/`, а не `.git`-история. Утечка через историю git реальна только если репозиторий публичен/расшарен, а не «через Pages». Механизм перепутан, угроза описана ложно, читатель делает неверный вывод о канале утечки.

ATTACK 4 [MAJOR] Блок «Проверено и держится» — пачка утверждений без команд и выводов
Where: «Проверено и держится (не находки): параметризованные SQL; safeHref … — поведение подтверждено; экранирование ?q=?; дружелюбное „Не найдено“ …; .env.local отдаёт 404; X-Powered-By отсутствует; … API-роутов и мутаций нет» плюс «Что проверялось и признано порядком» (пробы пересказаны без команд для SQLi/XSS/.env/API).
Problem: Задача требует для каждой находки проверку, а для «уже исправлено» — «проверь, что держится», то есть тоже нужен проверяемый след (файл:строка или URL+команда и вывод). Здесь десяток сильных заявлений («SQLi нет», «XSS экранирован», «.env.local 404», «API-роутов нет») даны одной строкой без команд/выводов (единственный probe с выводом — заголовки в №9). Контрпример: утверждение `GET /news/1' OR '1'='1 → „Не найдено“` приведено без команды curl и без фрагмента тела ответа; утверждение «API-роутов и мутаций нет» — без г expanded glob `app/**/route.ts` и без поиска `POST/PUT/DELETE`/`use server`. Пользователь не может перепроверить ни один из этих пунктов.

ATTACK 5 [MAJOR] №2 неполон: пароли в shell-примерах пропущены, место и фикс обрезаны
Where: «Место: db/README.md:8-11» и фикс «убрать пароли из db/README.md».

Локация 8-11 их не покрывает, фикс про `-p'...'` и замену на переменные окружения отсутствует, про проверку истории `git log -p -- db/README.md` и про правило `CONTEXT.md:4` («не коммитить») с отсутствием enforcement (нет хука/CI) — ни слова. Находка недоописана: пользователь зачистит 2 строки и оставит 2 те же пароля ниже в том же файле.

ATTACK 6 [MINOR] Фикс №9 содержит неприменимые меры: несуществующая cookie и JS frame-busting
Where: «cookie только SameSite=Lax» и «плюс JS frame-busting (if (top !== self) top.location = self.location)» (№9).
Problem: В проекте нет cookie с согласием — баннер пишет `localStorage hkoop-cookie` (`components/CookieBanner.tsx:19`), поэтому «SameSite=Lax» не к чему применить. JS frame-busting обходится (`sandbox` у атакующего iframe, `X-Frame-Options` у него же) и не является закрытием кликджекинга, что противоречит собственной верной оговорке автора про `frame-ancestors`. Фикс в этой части невыполним/вводит в заблуждение.

ATTACK 7 [MINOR] №10 — гипотетический трекинг-пиксель подан как MEDIUM по 152-ФЗ без факта
Where: «Реальный остаточный риск — внешний https:-URL из скомпрометированной БД: браузер каждого посетителя запросит чужой сервер» (`app/honor/page.tsx:14`, `components/PartnersStrip.tsx:11`).
Problem: Автор сам признаёт, что «XSS через img src здесь нет», а внешнего URL в сидах/БД не показывает (нет ни строки seed, ни SELECT-вывода, ни живой пробы с таким src). То есть условие («если в БД окажется внешний URL через скомпрометированную учётку») — ненаступившее предположение, а не факт. Подача предположения как MEDIUM-находки с нормой «ст. 9, п. 5 ч. 1 ст. 18.1 ФЗ-152» завышает severity без доказанного состояния данных.
