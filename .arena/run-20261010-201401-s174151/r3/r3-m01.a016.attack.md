ATTACK 1 [FATAL] M1: meta http-equiv «фикс» не даёт заявленной защиты
Where: §M1, фикс п.2: «для статики на Pages — конкретные `<meta http-equiv>` в `app/layout.tsx`: `Content-Security-Policy` с allowlist ..., `Referrer-Policy`, `X-Content-Type-Options`»
Problem: два из трёх пунктов через meta не работают. `X-Content-Type-Options` не имеет meta-эквивалента — браузеры его игнорируют (выставляется только HTTP-заголовком). `Referrer-Policy` задаётся через `<meta name="referrer">`, а не `http-equiv`. `frame-ancestors` внутри meta-CSP игнорируется по спецификации CSP (только HTTP-заголовок) — при том что «Факт» того же M1 пугает clickjacking-обёрткой. Контрпример: применить их фикс и выполнить `curl.exe -sI http://localhost:3100/` — заголовка `X-Content-Type-Options` не появится, а страница с их meta-CSP по-прежнему встраивается в чужой iframe. Читатель, применивший фикс, считает себя закрытым, а защиты нет.

ATTACK 2 [MAJOR] H2: «2 vulnerabilities» не сходятся с 5 перечисленными GHSA, сырой вывод не приведён
Where: §H2: «`node npm-cli.js audit --audit-level=high` → `2 vulnerabilities (1 high, 1 critical)`» и тут же «блок `next 0.9.9 - 16.3.0-preview.10 / Severity: critical` со списком GHSA (в т.ч. `GHSA-gp8f-8m3g-qvj9`, `GHSA-7gfc-8cq8-jh5f`, `GHSA-4342-x723-ch2f`, `GHSA-f82v-jwr5-mffw`)» плюс «`postcss <=8.5.22 / Severity: high`»
Problem: 4 критических GHSA по next + 1 high по postcss — минимум 5 advisory-записей, что противоречит «2 vulnerabilities (1 high, 1 critical)». Сырой вывод аудита не вставлен, поэтому противоречие неразрешимо для читателя. Проверка: `node npm-cli.js audit --audit-level=high` в корне проекта и сверка числа advisory с перечисленными GHSA. Центральный HIGH-вывод непроверяем.

ATTACK 3 [MAJOR] Пропущено требуемое: iframe-превью PDF без sandbox грузит любой https под шапкой сайта
Where: задача требует: «хранимый (всё, что рендерится из БД: ... пути PDF, iframe-превью ...)»; в решении §M5 смотрит только два `img src`, а `components/DocsFilter.tsx:42` (`setPreview(safeHref(d.file_local)!)`) + `:56` (`<iframe src={preview} width="100%" height="600" title="PDF" />` без `sandbox`) не упомянуты нигде
Problem: `safeHref` (`lib/url.ts:3-9`) пропускает любой `https://`, так что контрпример `documents.file_local='https://evil.example/phish.html'` проходит проверку, и кнопка «Смотреть» открывает чужую страницу в iframe внутри оформления сайта под заголовком «Просмотр PDF» — фишинг от имени профсоюзов с top-навигацией. Обязательный подпункт задачи не закрыт.

ATTACK 4 [MAJOR] H4: SHOW GRANTS заявлен, но нет ни команды, ни вывода
Where: §H4: «Проверка (выполнена, read-only, секрет не печатался): `SHOW GRANTS` тем же соединением, что использует сайт (хост/порт/пользователь из `.env.local`, пароль не выводился). Вывод (хеш пароля замазан): `GRANT USAGE ON *.* ...`, `GRANT ALL PRIVILEGES ON hkoop.* ...`»
Problem: задача требует для каждой находки «проверкой (инспекция кода или живой probe с командой и выводом)». Здесь нет ни точной команды (какой вызов — `mysql`, `node -e`, с каким пользователем/хостом), ни сырого вывода — только пересказ с «замазанным» хешом. Воспроизвести и проверить заявление нельзя; честная пометка — «условно, по коду/документации», а не «проверено, контракт закрыт».

ATTACK 5 [MAJOR] H3b: спящая Метрика (скрипта в HTML нет) выдана за живое HIGH-нарушение «данные уходят»
