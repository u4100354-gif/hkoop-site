# Аудит сайта ХКООП: безопасность и соответствие законам РФ (включая 152-ФЗ)

## Допущения

- Аудит по рабочему дереву на ветке `backup-2026-10-10` как есть; проект не менялся.
- Живые пробы — только безопасные GET к `http://localhost:3100` (dev-сервер). БД — только чтением через рендер страниц, секреты не печатаются.
- `NEXT_PUBLIC_YM_ID` локально не задан (в HTML главной нет `mc.yandex.ru`) — поведение при заданном ID читается из кода.
- Точный список CVE сверяется по открытым бюллетеням; вывод ниже опирается на публично известные фиксы ветки 14.2.x.

## Как устроена система (карта связей)

Три цепочки определяют почти всё:

1. **БД → рендер → браузер.** `lib/db.ts (q)` → `app/*/page.tsx` (серверные компоненты) → `components/*` → HTML. Кто пишет в БД (пресс-служба через phpMyAdmin), тот де-факто пишет HTML сайта. Поэтому фильтр `lib/url.ts (safeHref)` — главный шлюз, и важна каждая щель мимо него.
2. **Согласие → сторонние ресурсы.** `CookieBanner` (клиент, `localStorage hkoop-cookie`) против `app/layout.tsx` (Метрика) и `app/contacts/page.tsx` (iframe Яндекс-карты). Баннер обещает одно, код делает другое — это системный разрыв, а не два отдельных бага.
3. **Dev SSR → статический экспорт.** Прод — `output: export` на GitHub Pages: серверных заголовков, редиректов и middleware там нет по архитектуре. То, что «дефолтно» в dev (заголовки Next, редиректы из `next.config.js`), в проде исчезает. Проверять надо обе конфигурации.

## Что уже исправлено и держится (как новое не засчитывается)

SQL-запросы параметризованы (единственный запрос с параметром — `app/news/[id]/page.tsx:17` `WHERE id=?`; остальные без пользовательского ввода); `safeHref` режет `javascript:`/`data:`/`//evil` и применён к партнёрским ссылкам, соцсетям, путям PDF и iframe-превью; `poweredByHeader: false` (заголовка `X-Powered-By` в ответе нет); `.env*` и `.next-export` в `.gitignore`; `.env.local` отдаёт 404; API-роутов и мутаций нет; отражённый XSS в поиске экранируется; инъекции в путях (`../`, `%2e%2e`) дают 404/«Не найдено» без утечек.

## Ранked-список находок

### 1. HIGH — Сторонние трекеры грузятся без согласия: Метрика в layout и Яндекс-карта в контактах

- **Место:** `app/layout.tsx:15,27-31`; `app/contacts/page.tsx:23`; `components/CookieBanner.tsx:5-27`.
- **Проверка:** инспекция + живой probe. Условие вставки Метрики — только `ym && (...)`, флаг `hkoop-cookie` нигде не читается; noscript-пиксель `https://mc.yandex.ru/watch/${ym}` тоже безусловный. Probe: `GET /contacts` → 200, `YMAP True` — iframe `https://yandex.ru/map-widget/...` в HTML до любого клика по баннеру. `GET /` сегодня без `mc.yandex.ru` (счётчик не задан), то есть нарушение спит — но достаточно задать `NEXT_PUBLIC_YM_ID` (пример с ID есть в `.env.example:6`), и трекер с `clickmap:true,trackLinks:true` встанет у всех посетителей.
- **Факт:** текст баннера («сайт использует cookie и Яндекс.Метрику. Продолжая, вы соглашаетесь») обещает согласие, а код его не требует. Посетитель страницы контактов отдаёт IP/User-Agent Яндексу до согласия.
- **НПА:** ст. 9, 18–18.1 Федерального закона № 152-ФЗ (обработка только с согласия, информирование субъекта); требования к cookie-баннерам из практики Роскомнадзора (отказ не сложнее согласия); ст. 10.1 Закона № 149-ФЗ в части информирования.
- **Фикс (описать):** грузить скрипт/пиксель Метрики и iframe карты только после флага согласия (`hkoop-cookie=1`); до согласия — статичная заглушка карты с кнопкой «Показать карту (загрузит Яндекс)»; iframe с `loading="lazy"`, `referrerpolicy="no-referrer"`. Компромисс: клик-заглушка чуть хуже для UX, но это единственный способ честно выполнить обещание баннера; альтернатива «убрать карту и Метрику вообще» — проще по коду, но теряется аналитика и наглядность проезда.

### 2. HIGH — Уязвимый `next 14.2.5`: старше всех security-фиксов ветки

- **Место:** `package.json:12` (`"next": "14.2.5"`).
- **Проверка:** инспекция + сверка с открытыми бюллетенями. Ветка затронута как минимум CVE-2025-29927 (обход middleware-авторизации через заголовок `x-middleware-subrequest`, CVSS 9.1, исправлено в 14.2.25/15.2.3) и бюллетенями 2024 года по кэшу (CVE-2024-39328, CVE-2024-46982 — исправлены в 14.2.8+). Смягчает: своего `middleware.*` и API-роутов в проекте нет (проверено отсутствием файлов), прод — статика, поэтому прямого обхода авторизации нечему бить.
- **Факт:** dev-сервер на `:3100` и сборочный конвейер крутят уязвимый рантайм; любой будущий middleware/API унаследует дыру; сканеры безопасности будут красить сборку в красное.
- **Фикс (описать):** плановое обновление `next` минимум до `14.2.25+` (лучше до последнего 14.2.x / 15.x с проверкой экспорта), `npx tsc --noEmit`, `STATIC_EXPORT=1 npm run build`, пересборка `.next-export` и деплой. Компромисс: обновление несёт риск сломать экспорт (basePath, unoptimized images), поэтому делать отдельным окном с проверкой 390/768/1440, а не «ночью перед показом».

### 3. MEDIUM — Нет защитных заголовков; страницы можно встроить в чужой iframe

- **Место:** весь сайт (нет `headers()` в конфиге); подтверждение — заголовки `GET /`: только `Vary, Cache-Control, Content-Type, Date`, нет `X-Frame-Options/CSP/X-Content-Type-Options/Referrer-Policy`.
- **Проверка:** живой probe заголовков (см. таблицу, П1).
- **Факт:** любой внешний сайт может встроить страницы ХКООП в `<iframe>` (кликджекинг кнопки «Отправить»/баннера); `nosniff` отсутствует; `Referer` с внутренними URL утекает на habprof.ru и в Яндекс.
- **НПА:** напрямую не статья, но отсутствие мер защиты — отягчающее при инциденте по 152-ФЗ (ст. 19 — обеспечение безопасности ПДн).
- **Фикс (описать):** для dev/SSR добавить `headers()` (`X-Frame-Options: SAMEORIGIN` или `frame-ancestors 'self'`, `X-Content-Type-Options: nosniff`, минимальную CSP, `Referrer-Policy: strict-origin-when-cross-origin`); для GitHub Pages — эквивалент на уровне хостинга/CDN-правил плюс `<meta http-equiv>` там, где заголовки недоступны. Компромисс: строгая CSP может сломать инлайн-скрипты (тот же `document.documentElement.classList.add('js')`) и виджет карты — вводить в режиме report-only с белым списком `yandex.ru` при необходимости.

### 4. MEDIUM — Два `img src` из БД идут мимо `safeHref`: фото книги почёта и логотипы партнёров

- **Место:** `app/honor/page.tsx:14` (`<img src={h.photo}>`); `components/PartnersStrip.tsx:11` (`<img src={p.logo}>`; `safeHref` там применён только к `p.url`, строка 21).
- **Проверка:** инспекция. Соседние рендеры фильтруются (`contacts:9-11`, `DocsFilter:42-43`), а эти два — сырые значения `VARCHAR(500)` из БД. Живой HTML сегодня benign, эксплуатации нет.
- **Факт:** любой, кто пишет в `honor.photo`/`partners.logo` через phpMyAdmin, кладёт произвольный `src` (внешний трекер, битый путь, `http://` mixed-content, `data:`-шлейф) на главную и `/partners` — в обход заявленного «allowlist для всего из БД». Готового XSS здесь нет (`javascript:` в `img src` современные браузеры не исполняют, `onerror`-вектора в коде нет), класс — stored-дефейс/трекинг.
- **Фикс (описать):** пропускать `h.photo`/`p.logo` через `safeHref` (или строже — только site-relative `/images/…` + явный allowlist доменов), при `null` — существующая заглушка (как при пустом фото); внешним логотипам добавить `referrerpolicy="no-referrer"` и осмысленный `alt`.

### 5. MEDIUM — PDF-превью в iframe без песочницы; любой `https://` из БД встанет в iframe

- **Место:** `components/DocsFilter.tsx:42,50-56` (`setPreview(safeHref(d.file_local)!)`, затем `<iframe src={preview} width height title>` без `sandbox`).
- **Проверка:** инспекция. `safeHref` режет только схему, домен не проверяет: запись `file_local=https://evil.example/phish.html` пройдёт фильтр и отрендерится внутри chrome сайта с заголовком «Просмотр PDF».
- **Фикс (описать):** для превью разрешать только site-relative `/docs/*.pdf` (проверка префикса + суффикса `.pdf`); внешние `file_old` открывать только новой вкладкой с `rel="noopener noreferrer"` и плашкой «внешний ресурс»; iframe — с `sandbox` без `allow-top-navigation`/`allow-scripts` шире необходимого.

### 6. MEDIUM — Cookie-баннер и форма юридически неполны по 152-ФЗ

- **Место:** `components/CookieBanner.tsx:12-24`; `components/ConsultForm.tsx:4-12`; `app/docs/page.tsx:11-16`.
- **Проверка:** инспекция + probe. У баннера только кнопка «Принять», кнопки «Отклонить» нет; ссылка ведёт на `/docs`, а не прямо на `/docs/politika.pdf` (сам файл на месте — probe 200, 3.2 МБ). Чекбокс согласия в форме — голый текст без ссылки на политику и без указания оператора; после «Отправить» нет сообщения о том, что данные никуда не уходят. Позитив: форма действительно ничего не отправляет (`onSubmit={e.preventDefault()}`, бэкенда нет) — минимизация данных по факту соблюдена, трансграничной передачи нет, локализация не нарушена.
- **НПА:** ст. 9, 18–18.1 Закона № 152-ФЗ (согласие должно быть конкретным, информированным; субъект вправе отозвать; оператор обязан разъяснить последствия); ст. 10.1 Закона № 149-ФЗ и позиция РКН: отказ от cookie не должен быть сложнее согласия.
- **Фикс (описать):** добавить кнопку «Отклонить» (без Метрики/карты при отказе); ссылку баннера и чекбокса вести прямо на `/docs/politika.pdf`; рядом с формой — строку «Оператор: Союз ХКООП, адрес, email; данные из формы никуда не отправляются (демо-режим)»; в политику вписать cookie/Метрику/карту и срок согласия. Компромисс: кнопка «Отклонить» чуть снижает долю согласия в аналитике, но снимает главный юридический риск; альтернатива «тихий трекинг всех» дешевле, но прямо нарушает 152-ФЗ.

### 7. LOW — Внешние ссылки `target="_blank"` без явного `noopener`

- **Место:** `components/PartnersStrip.tsx:29`, `app/page.tsx:95`, `components/DocsFilter.tsx:43` — везде `rel="noreferrer"` без `noopener`. Probe главной/контактов: `noopener` — 0.
- **Проверка:** инспекция + подсчёт в живом HTML.
- **Факт:** современные браузеры трактуют `noreferrer` как `noopener`, риск остаточный (старые движки, reverse-tabnabbing). Плюс `safeHref` пропускает любой `https://` — опечатка в URL партнёра в БД уведёт с доверенной страницы на фишинг.
- **Фикс (описать):** заменить на `rel="noopener noreferrer"` во всех местах с `_blank`; в регламент пресс-службы вписать проверку URL партнёров из двух рук.

### 8. LOW — `NEXT_PUBLIC_YM_ID` интерполируется в инлайн-скрипт без проверки формата

- **Место:** `app/layout.tsx:15,29` (`` ym(${ym},"init",...) `` внутри `dangerouslySetInnerHTML`).
- **Проверка:** инспекция. Переменная серверная, не пользовательская — XSS только при компрометации окружения, поэтому LOW. Второй `dangerouslySetInnerHTML` (строка 19, `classList.add('js')`) — статическая строка, чисто.
- **Фикс (описать):** валидировать ID (`/^\d+$/`, иначе не рендерить), вставлять через `JSON.stringify(String(ym))`; заодно убрать реальный ID из комментария в `.env.example:6` (оставить пустое значение).

### 9. LOW — Мелочи, которые чинить последним

- `app/page.tsx:37`: фолбэк `docHref` клеит `https://habprof.ru + old_url` по одному `startsWith("/")` — доверенный домен, React экранирует атрибут, дыры нет; при желании добавить проверку `^/[a-z0-9/_\-.]*$`i.
- `HeaderSearch.tsx:44` корректно использует `encodeURIComponent`; но ни в одном поле поиска/фильтров/формы нет `maxLength` — вставка 100-КБ строки делает лишнюю работу клиента (DoS уровня браузера, не сервера). Добавить `maxLength={200}`.
- В шапке/подвале импринт полный (адрес, телефон, email, часы — `Header.tsx:52-54`, `Footer.tsx:7-10`) — ст. 10 Закона № 149-ФЗ соблюдена. Версия для слабовидящих работает (`ViProvider`, кнопка в шапке, режимы шрифта/картинок) — ГОСТ Р 52872-2019 по наличию закрыт; для полного соответствия добавить видимый фокус и проверку контраста панели — точечная задача, не блокер.
- Партнёрские ссылки — информационные (органы власти, ФНПР, вузы): признаков немаркированной рекламы нет, пометка «Реклама»/erid по ст. 18.1 Закона № 38-ФЗ не требуется, пока размещения бесплатны; при появлении платных — маркировать. Логотипы/фото третьих лиц используются информационно — зафиксировать письменные разрешения (ст. 1274 ГК РФ, право на товарный знак) отдельным реестром.

## Компромиссы — что выбрано и что отдано

1. **Строгость severity vs честность.** Метрика/карта и Next 14.2.5 стоят HIGH, хотя эксплуатации сегодня нет (счётчик не задан; middleware нет). Отдано: «красивый» отчёт без красных пунктов. Выиграно: читатель не включит счётчик одной строкой и не получит сюрприз.
2. **Целостность системы vs точечные патчи.** Главный вывод — чинить связку «согласие → загрузка» целиком (баннер + layout + карта), а не каждый файл отдельно. Отдано: больше работы за раз. Выиграно: не останется «починили баннер, а карта всё равно стучит в Яндекс».
3. **Dev-удобство vs прод-безопасность.** Заголовки и CSP настраиваются под dev, но прод — статика без серверных заголовков. Отдано: часть защит в проде возможна только через хостинг/CDN. Выиграно: честная карта ограничений вместо иллюзии «добавили headers — и готово».

## Вердикт

Показывать людям можно только после пунктов 1 и 6 (согласие должно реально управлять Метрикой/картой, у баннера и формы — отказ и прямые ссылки на политику); первым чинить связку согласия целиком, вторым — обновить Next и закрыть `img src`/iframe-песочницу.
