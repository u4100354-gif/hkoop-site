## CRITICAL

### C1. Next.js 14.2.5 с известными критическими CVE — обновить в первую очередь
- **Место:** `package.json:12` (`"next": "14.2.5"`), рядом `react: 18.3.1`, `mysql2: ^3.24.5`.
- **Проверка (инспекция кода):** версия зафиксирована `14.2.5` (август 2024), Dependabot/renovate-конфига нет. Живой заголовок подтверждает Next (`Vary: RSC, Next-Router-State-Tree...`).
- **Факт:** ветка 14.2.x до 14.2.25/15.2.3 уязвима к **CVE-2025-29927** (обход авторизации через заголовок `x-middleware-subrequest`, CVSS 9.1, критический), а 14.2.5 дополнительно покрывается бюллетенями 2024 года (cache-poisoning/DOS семейства CVE-2024-46982, CVE-2024-39332 — устранялись в 14.2.9–14.2.15). Даже статическому экспорту это важно: сборка и dev-сервер используют уязвимый рантайм, а будущие middleware/API унаследуют дыру.
- **Фикс (долговечный):** поднять `next` минимум до `14.2.33+` (или 15.x LTS), затем `react/react-dom` до свежих 18.x, прогнать `npx tsc --noEmit` и `STATIC_EXPORT=1 npm run build`; включить регулярные обновления (Dependabot monthly + `npm audit` в CI). Не фиксировать диапазон `^` для `next` шире патчей без lock-контроля.

## HIGH

### H1. Яндекс.Метрика грузится без согласия — нарушение модели consent
- **Место:** `app/layout.tsx:15,27-31`; `components/CookieBanner.tsx:1-27`.
- **Проверка (инспекция):** цитата из layout:
  ```tsx
  const ym = process.env.NEXT_PUBLIC_YM_ID;
  {ym && (<><script dangerouslySetInnerHTML={{... "https://mc.yandex.ru/metrika/tag.js" ... ym(${ym},"init",{clickmap:true,...}) }} /> ...</>)}
  ```
  Условия `lsGet("hkoop-cookie")` здесь нет. Баннер лишь ставит `lsSet("hkoop-cookie","1")` и никак не связан с `ym`.
- **Факт:** достаточно задать `NEXT_PUBLIC_YM_ID`, и трекер с `clickmap/trackLinks` встанет у всех посетителей до клика «Принять». Это прямо противоречит тексту самого баннера («сайт использует cookie и Метрику… соглашаетесь») и требованиям согласия на обработку/cookies.
- **НПА:** ст. 9 Федерального закона от 27.07.2006 № 152-ФЗ (условия согласия на обработку ПДн); ст. 18 Федерального закона от 13.03.2006 № 38-ФЗ (реклама/аналитика — по аналогии практика требует согласия); п. 1 ст. 10 Федерального закона от 27.07.2006 № 149-ФЗ (достоверная информация об условиях использования сайта).
- **Фикс:** инвертировать зависимость: по умолчанию `ym` не рендерить; грузить скрипт Метрики только после `hkoop-cookie=1` (событие/контекст consent), добавить кнопку «Отклонить» с `hkoop-cookie=0` и повторный выбор; счётчик вынести в отдельный `ConsentMetrica` клиентский компонент с `next/script strategy="afterInteractive"`.

### H2. Пароли БД открытым текстом в дереве репозитория
- **Место:** `db/README.md:8-11,20,22`; дубль в `docs/ИНСТРУКЦИЯ-ПРЕСС-СЛУЖБЕ.md:28`.
- **Проверка (инспекция):** файлы лежат в рабочем дереве проекта рядом с кодом и содержат логин/пароль root и `hkoop` + готовые команды `mysql -u hkoop -p'...'`. `.gitignore:1-8` закрывает только `.env`/`.env.local`, но не `db/README.md`.
- **Факт:** любой `git push`/копия архива уносит секреты; ротация после утечки обязательна. То, что «пароли только локальные», не снимает риска: dev-пароли имеют свойство переезжать в прод.
- **Фикс:** вынести секреты из обоих `.md` в `.env.local` (уже gitignored), в документации оставить плейсхолдеры вида `mysql -u $DB_USER -p"$DB_PASS"`; сменить оба пароля; проверить историю git на предмет уже ушедших коммитов (`git log -p -- db/README.md`) и при наличии — считать скомпрометированными; добавить pre-commit-хук на секреты (gitleaks).

### H3. Нет охранных HTTP-заголовков (CSP, frame-ancestors, XCTO, Referrer-Policy, HSTS)
- **Место:** `next.config.js:1-27` (нет секции `headers()`); эффект — все URL сайта.
- **Проверка (живая проба):**
  ```
  python: urllib.request.urlopen('http://localhost:3100/').headers
  → [('Vary',...), ('Cache-Control','no-store, must-revalidate'),
     ('Content-Type','text/html; charset=utf-8'), ('Date',...)]
  → X-Powered-By: нет (держится); CSP: нет; X-Frame-Options/frame-ancestors: нет; X-Content-Type-Options: нет
  ```
- **Факт:** сайт можно встраивать в чужой `iframe` (кликджекинг формы/баннера), нет барьера для инлайн-скриптов и сниффинга типов. Для dev-сервера это ожидаемо, но для prod-экспорта на Pages заголовки надо задавать на уровне хостинга — сейчас их нет нигде.
- **Фикс:** задать политику надолго: `Content-Security-Policy: default-src 'self'; script-src 'self' https://mc.yandex.ru https://yandex.ru; frame-src https://yandex.ru; img-src 'self' data: https:; object-src 'none'; frame-ancestors 'self'` (уточнить под Метрику/карты), плюс `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options: SAMEORIGIN` (для dev), HSTS — на прод-домене. Для GitHub Pages — через `_headers`/Cloudflare-правила, для dev — `headers()` в `next.config.js`.

### M3. Два места рендерят src из БД без allowlist (разрыв в обороне от хранимого XSS)
- **Место:** `app/honor/page.tsx:14` (`<img src={h.photo}>`); `components/PartnersStrip.tsx:11` (`<img src={p.logo}>`).
- **Проверка (инспекция):** соседние рендеры фильтруются (`safeHref(p.url)`, `safeHref(file_local)`), а эти два `src` — нет. Цитата: `{h.photo ? <img src={h.photo} alt={h.fio} .../> : ...}` и `<img src={p.logo} alt="" .../>`.
- **Факт:** React экранирует текст/кавычки, поэтому это не «дыра сегодня», а отсутствующий второй рубеж: при компрометации БД (например, через phpMyAdmin) сюда ляжет `//evil`, `data:`-мусор или кириллический/битый путь; для `<a href>` аналогичный вектор уже закрыт, а тут — нет. Дополнительно: партнёр `хабаровсккурорт.рф` (IDN) — легитимен, но подтверждает, что внешние/юникод-URL реально идут из БД и должны валидироваться везде одинаково.
- **Фикс:** пропускать `photo`/`logo` через тот же `safeHref` (расширив при нужде на кириллические пути через `encodeURI`-нормализацию), при `null` — плейсхолдер со звездой (как уже есть в honor); добавить `referrerPolicy="no-referrer"` для внешних логотипов. Долговечно: один хелпер `safeSrc` рядом с `safeHref`, а не точечные правки.

2. XSS отражённый (`?q=`, фильтры) — проверено: `GET /search?q=<script>alert(1)</script> → 200`, сырого `<script>alert` нет, есть `&lt;script` (React экранирует) → закрыто.
3. XSS хранимый (партнёры, соцсети, PDF, iframe, книга почёта) — проверено: href/iframe закрыты `safeHref`, два `src` без него → M3, L1, L2.
4. Схемы `javascript:/data:` — проверено: regex `lib/url.ts:7` их режет, `//evil` тоже → закрыто (остаток — M3).
5. Path traversal (`../`, `%2e%2e`) — проверено: `%2e%2e → 404`, файловых чтений по `id` нет → закрыто.
6. Секреты/`.env`/хардкод/`.gitignore`/`X-Powered-By` — проверено: `.env* → 404`, заголовка нет, `.gitignore` ок, но пароли в `db/README.md`+инструкции → H2, L5.
7. Формы/странные вводы/длинные строки — проверено: `preventDefault` держится, `maxLength` нет → M4.
8. Зависимости/CVE (next 14.2.5) — проверено → C1.
9. Заголовки/API/phpMyAdmin/права mysql — проверено: заголовков нет → H3; `app/api` пуст → держится; phpMyAdmin/mysql — допущение №2.
10. Ошибки/стектрейсы — проверено: 500/трейсов нет, но soft-404 → M5.
11. 152-ФЗ (согласие, политика, баннер, минимизация, локализация, контакты оператора) — проверено: чекбокс есть, `politika.pdf → 200`, баннер есть, отправки данных нет (плюс), но согласие/баннер/Метрика/карта — мимо → H1, M1, M2, M4.
