# Аудит сайта ХКООП: безопасность и соответствие законам РФ (включая 152-ФЗ)

Дата: 10.10.2026. Объект: рабочее дерево `hkoop-site` на ветке `backup-2026-10-10` (проект не менялся, только чтение + безопасные GET к `http://localhost:3100` и `http://127.0.0.1:8081`). Стек: Next.js 14.2.5 App Router + React 18 + TypeScript, mysql2, MariaDB `hkoop`, dev-сервер на :3100, прод — статический экспорт.

## Допущения

1. Секреты не печатаются; содержимое `.env.local` и `db/README.md` не цитируется, проверено только наличие/покрытие gitignore.
2. БД не менялась: только чтение кода и SELECT-подобные выводы через уже запущенный сайт; прямых запросов к MySQL из аудита не делалось.
3. `public/docs/politika.pdf` проверен только на доступность (HTTP 200, `application/pdf`); юридическая экспертиза текста политики — по месту ссылки, а не по содержанию.
4. Каталога `app/honor/[id]` в дереве нет (есть только `app/honor/page.tsx`); пункт задания про `honor/[id]` проверен на `app/honor/page.tsx` как ближайшем аналоге.
5. Версии CVE сверены с публичными бюллетенями Next.js; полный `npm audit` не запускался (запрет менять пакеты/ставить процессы).

## Проверено и держится (уже исправленное — как новое не засчитывается)

- SQL-запросы параметризованы: `app/news/[id]/page.tsx:17` — `WHERE id=?` с `[params.id]`; остальные `q()` — статические SELECT без конкатенации пользовательского ввода.
- `lib/url.ts:3-8` — allowlist `safeHref` для href/iframe из БД; применяется в `app/page.tsx:37`, `app/contacts/page.tsx:9-11`, `components/DocsFilter.tsx:42-43`, `components/PartnersStrip.tsx:21`.
- `next.config.js:5` — `poweredByHeader: false`; живой probe `curl.exe -sI http://localhost:3100/` не показывает `X-Powered-By`. Вывод: `HTTP/1.1 200 OK`, заголовки только `Vary`, `Cache-Control: no-store, must-revalidate`, `Content-Type`, `Date`.
- `.env.local` по HTTP отдаёт 404: `curl.exe -s -o NUL -w "%{http_code}" http://localhost:3100/.env.local` → `404`.
- `.gitignore:2-5` покрывает `node_modules/`, `.next/`, `.next-export/`, `.env`, `.env.local`. Хардкода пароля БД в коде нет (`lib/db.ts:3-11` — только `process.env` с пустыми дефолтами).
- Отражённый XSS в поиске не воспроизводится: `curl.exe -s "http://localhost:3100/search?q=%3Cscript%3Ealert(1)%3C/script%3E"` возвращает `value="&lt;script&gt;alert(1)&lt;/script&gt;"` — React экранирует. Тот же вывод в RSC-потоке: `searchParams":{"q":"\u003cscript\u003e...`. Фильтры `NewsFilter`/`DocsFilter`/`HeaderSearch` рендерят совпадения как текст, без `dangerouslySetInnerHTML` (кроме двух легитимных мест в `app/layout.tsx`, см. ниже).
- Ошибки стек не светят: `curl.exe -s http://localhost:3100/news/no-such-id-xyz123` → `<h1>Не найдено</h1>` (ветка `app/news/[id]/page.tsx:19`), без трассировки.
- API-роутов/мутаций нет: `route.ts` и `middleware` в `app/` не найдены; `ConsultForm` делает только `e.preventDefault()` (`components/ConsultForm.tsx:4`), сеть ничего не отправляет.
- phpMyAdmin отвечает `200` страницей входа (закрыт логином), что соответствует требованию.

## Ranked-список находок (новое)

### F1. HIGH — Уязвимый Next.js 14.2.5 (известные CVE, включая обход авторизации)
- Место: `package.json:12` (`"next": "14.2.5"`).
- Проверка (инспекция): зафиксированный пин 14.2.5 старше патчей 14.2.25+/14.2.32. Публично известно: CVE-2025-29927 (обход middleware-авторизации, CVSS 9.1 — заголовок `x-middleware-subrequest` позволяет пропустить проверки), CVE-2024-39328 (SSRF/кэш-пойзонинг через `/_next/image`), CVE-2025-55182/54794 (RSC Flight, DoS/RCE-векторы в линейке 14.x). Проект своего middleware не имеет (см. «держится»), но сам рантайм уязвим: любой будущий middleware/redirect (`next.config.js:9-24` уже содержит redirects) унаследует дыру, а SSRF/Image затрагивает и статику.
- Фикс (без применения): обновить `next` минимум до `14.2.32` (лучше — последний 14.x или 15.x), затем `package-lock.json`, `npx tsc --noEmit`, `STATIC_EXPORT=1 npm run build`, перепроверить экспорт; в прод-памятке зафиксировать политику обновления в течение 30 дней после security-релиза.

### F2. HIGH — Нет ни одного заголовка безопасности
- Место: URL `http://localhost:3100/` (весь сайт).
- Проверка (живой probe): `curl.exe -sI http://localhost:3100/` → только `Vary`, `Cache-Control`, `Content-Type`, `Date`. Отсутствуют: `Content-Security-Policy`, `X-Frame-Options`/`frame-ancestors`, `X-Content-Type-Options`, `Referrer-Policy`, `Strict-Transport-Security`, `Permissions-Policy`.
- Факт: сайт встраивается в чужой `iframe` (кликджекинг формы консультации), MIME-sniffing не запрещён, хотлинк карт/метрики ничем не ограничен. Для информационного сайта с формой это главный дешёвый выигрыш защиты.
- Фикс: добавить `async headers()` в `next.config.js` (для dev/SSR) + `<meta http-equiv>`/HTTP-заголовки на хостинге статики (GitHub Pages `_headers`-аналог через `out/`): `X-Frame-Options: SAMEORIGIN`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy: camera=(), microphone=(), geolocation=()`, CSP вида `default-src 'self'; img-src 'self' data: https:; script-src 'self' https://mc.yandex.ru; frame-src https://yandex.ru; style-src 'self' 'unsafe-inline'` (уточнить под фактические чанки), HSTS — только после перехода прода на HTTPS.

### F3. HIGH — Яндекс.Метрика грузится без согласия (нарушение 152-ФЗ)
- Место: `app/layout.tsx:15,27-31` + `components/CookieBanner.tsx:1-27`.
- Проверка (инспекция + живой probe): в layout `const ym = process.env.NEXT_PUBLIC_YM_ID; {ym && (<script …tag.js…>…)}` — условие только «задан ли счётчик», флага согласия нет. `CookieBanner` лишь пишет `lsSet("hkoop-cookie","1")` по кнопке «Принять» и ни на что не влияет. Сейчас в dev `ym` не задан (в HTML главной `mc.yandex` отсутствует — `curl.exe -s http://localhost:3100/ | findstr mc.yandex` пуст), то есть де-факто трекинга нет, но стоит задать `NEXT_PUBLIC_YM_ID` (а `.env.example:6` это прямо предлагает) — трекинг включится у всех, включая тех, кто баннер не принимал. Текст баннера «Продолжая, вы соглашаетесь» — это implied consent, который ст. 9 152-ФЗ и разъяснения Роскомнадзора не признают согласием (нужно явное, предметное, информированное).
- НПА: ст. 9 Федерального закона от 27.07.2006 № 152-ФЗ «О персональных данных» (согласие должно быть конкретным, предметным, информированным, сознательным и однозначным); ст. 18 152-ФЗ (информирование субъекта); передача IP/cookie в Метрику — обработка ПДн и поручение по ст. 6 152-ФЗ.
- Фикс: грузить скрипт Метрики только после `lsGet("hkoop-cookie")==="1"` (или отдельного ключа `hkoop-ym`), добавить в баннер вторую кнопку «Отклонить» и ссылку на политику; до согласия — никакого `tag.js` и `watch/`. Зафиксировать в политике: цель (аналитика), перечень данных, срок, отзыв согласия.

### F4. MEDIUM — `src` картинок из БД не проходит `safeHref` (хранимый XSS/трекинг-вектор)
- Места: `components/PartnersStrip.tsx:11` (`<img src={p.logo} …>` без проверки) и `app/honor/page.tsx:14` (`<img src={h.photo} …>` без проверки). Контраст: `href` партнёров в том же файле проверяется (`:21` `safeHref(p.url)`), а `logo` — нет.
- Проверка (инспекция): тип `P = {…; logo: string }`, `Logo` рендерит `p.logo` напрямую; `honor` рендерит `h.photo` напрямую. В современных браузерах `javascript:` в `img src` не исполняется, но `data:text/html`, `data:image/svg+xml` с активным контентом (в некоторых контекстах), внешний `https://evil` (слив Referer/IP посетителей, подмена логотипа на фишинг), `//evil` и длинные строки проходят без фильтра. Источник данных — БД, куда пишет человек через phpMyAdmin (риск компрометации/ошибки оператора).
- Фикс: `const src = safeHref(p.logo)` / `safeHref(h.photo)`; при `null` — плейсхолдер (как уже сделано для пустого фото в `honor/page.tsx:14` через `★`-заглушку) и `alt={p.name}`/`alt={h.fio}`; в админ-инструкции запретить внешние URL логотипов (только `/images/*`, `/docs/*`).

### F5. MEDIUM — Cookie-баннер: нет отказа, ссылка ведёт не на политику, нет состава согласия
- Место: `components/CookieBanner.tsx:12-24`.
- Проверка (инспекция + живой probe): ссылка «политикой конфиденциальности» ведёт на `/docs` (каталог), а не на `/docs/politika.pdf` (который существует: `curl …/docs/politika.pdf` → `200 application/pdf`). Кнопка одна — «Принять»; отказа/«только необходимые» нет; нет перечисления целей, сроков, оператора. `role="dialog"` есть, но фокус не переводится, повторный вызов после отказа невозможен.
- НПА: ст. 9, 18 152-ФЗ; п. 2 ч. 1 ст. 10 149-ФЗ в части информирования; разъяснения Роскомнадзора о cookie (cookie — ПДн при идентификации).
- Фикс: ссылка `href="/docs/politika.pdf"`, две кнопки «Принять»/«Отклонить», текст «Мы используем необходимые cookie; аналитику (Метрику) — только с вашего согласия», хранение выбора с датой/версией политики, кнопка «Настройки cookie» в футере для отзыва.

### F6. MEDIUM — Чекбокс согласия в форме — без ссылки на политику, цели и реквизитов оператора
- Место: `components/ConsultForm.tsx:8-10` (используется на `/` и `/contacts`).

Форма сейчас данные никуда не отправляет (минимизация — плюс), но пользователь этого не знает: плейсхолдеры «Телефон или email», «Вопрос» приглашают ввести ПДн, а дисклеймера «форма демонстрационная, данные никуда не отправляются» нет. Человек может вписать паспорт/медданные.
- НПА: ст. 9 152-ФЗ (содержание согласия: цель, перечень, срок, порядок отзыва, наименование оператора); ст. 18 152-ФЗ.

Форма демонстрационная: данные не покидают ваш браузер» + указать оператора (Союз «ХКООП», адрес из футера) либо — когда появится бэкенд — полный текст согласия по ч. 4 ст. 9 152-ФЗ. Дополнительно: `maxLength` на поля, `autocomplete="tel email"` вместо `off` у контакта — мелочь, но снижает ошибки.

### F7. MEDIUM — Сторонний iframe Яндекс.Карт и внешние соцсети грузятся без согласия

## Чеклист требований задания (где закрыто)

1. SQL-инъекции (`q()`, `news/[id]`) — закрыто: «держится» + F1 (рантайм, не запросы).
2. XSS отражённый (`?q=`, фильтры) — закрыто: «держится», probe с `<script>` экранирован.
3. XSS хранимый (партнёры, соцсети, PDF, iframe, книга почёта) — закрыто частично: href/iframe через `safeHref`, остаток — F4.
4. `javascript:`/`data:` в href/src — закрыто для href, для `logo`/`photo` src — F4.
5. Инъекции путей (`../`, `%2e%2e`) — закрыто: `news/[id]` параметризован, `curl …/news/..%2f..%2fetc%2fpasswd` → 200 без раскрытия (нормализованный 404/«Не найдено»).
6. Секреты (`.env.local` по HTTP, хардкод, gitignore, `X-Powered-By`) — закрыто: «держится».
7. Формы (ConsultForm, HeaderSearch, фильтры, странные/длинные вводы) — закрыто: F6 + F9.
8. Зависимости/CVE (next 14.2.5) — закрыто: F1.
9. Заголовки безопасности — закрыто: F2.
10. Отсутствие API-роутов/мутаций — закрыто: «держится».
11. phpMyAdmin с логином — закрыто: «держится» (200 = форма входа).
12. Права mysql-пользователя — частично: права не проверялись (запрет менять БД; секреты не печатаются); рекомендация — права только SELECT на `hkoop` для сайта, без GRANT/FILE (проверить локально `SHOW GRANTS`).
13. Ошибки 500/стектрейсы — закрыто: «держится».
