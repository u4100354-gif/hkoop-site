# Аудит сайта ХКООП: безопасность и соответствие законам РФ (включая 152-ФЗ)

Дата: 10.10.2026. Объект: `hkoop-site`, ветка `backup-2026-10-10` (рабочее дерево как есть). Стек: Next.js 14.2.5 + React 18 + TS, mysql2, MariaDB `hkoop` на 127.0.0.1:3306, dev http://localhost:3100, phpMyAdmin http://127.0.0.1:8081, прод — статический экспорт на GitHub Pages. Проект не менялся: только чтение кода и безопасные GET-пробы. Секреты не печатаются (проверялись только имена ключей и факты наличия).

## Допущения

1. Прод = статический экспорт (`output: export`): весь SQL выполняется только в момент сборки, в браузере пользователя SQL и секретов БД нет.
2. БД доверенная: писать в неё может только аппарат через phpMyAdmin, поэтому внешние https-ссылки из БД — не уязвимость сами по себе, но поверхность для stored-XSS/трекинга проверена.
3. Проверены имена ключей `.env.local` (значения не читались и не печатаются).
4. Версии CVE для next сверены с публичными бюллетенями; там, где точный номер не подтвержден, это оговорено.

### F2. HIGH — Уязвимый Next.js 14.2.5 (`package.json:12`)

- Место: `package.json:12` (`"next": "14.2.5"`), зависимостей всего 4 (`next`, `react`, `react-dom`, `mysql2`), поверхность маленькая, но ядро уязвимо.
- Проверка (инспекция): версия запинена ровно `14.2.5` (август 2024). Публично известно: CVE-2025-29927 (обход авторизации через заголовок `x-middleware-subrequest`, CVSS 9.1, исправлено в 14.2.25), CVE-2024-46982 (cache-poisoning), CVE-2024-47831 (DoS). Живая проба заголовка не делалась (в проекте нет `middleware.ts` — нечему обходиться, см. ниже).

- Фикс: поднять `next` минимум до `14.2.25` (или актуальный 14.x), прогнать `npx tsc --noEmit` + `STATIC_EXPORT=1 npm run build`, зафиксировать lock-файл; дальше — Dependabot/регулярное обновление.

### F3. MEDIUM — Яндекс.Метрика подключается без согласия (латентное нарушение, сработает при включении)

- Место: `app/layout.tsx:15,27-32`.
- Проверка (инспекция + живой факт): код `const ym = process.env.NEXT_PUBLIC_YM_ID; {ym && (<script …src https://mc.yandex.ru/metrika/tag.js…> + <noscript><img watch…>)}` — скрипт и пиксель вставляются безусловно, чтения `hkoop-cookie` из `CookieBanner` нет. Живой факт: на главной сейчас следов Метрики нет (`metrika`/`mc.yandex` отсутствуют в HTML — проверено сохранённой страницей), потому что в `.env.local` есть только ключи `DB_*`, ключа `NEXT_PUBLIC_YM_ID` нет. То есть нарушение спит до первого включения счётчика (а он «запланирован», `CONTEXT.md:65`), причём `NEXT_PUBLIC_*` запекается в статику при сборке — отозвать согласие потом нельзя без пересборки.
- Факт: текст баннера уже сегодня обещает «сайт использует cookie и Яндекс.Метрику», хотя Метрики нет (вводит в заблуждение), а когда счётчик включат — аналитика поедет до клика «Принять», без кнопки «Отклонить». Это противоречит требованию явного согласия на аналитику (ст. 9, ч. 1 ст. 18.1 152-ФЗ; позиция Роскомнадзора: метрика — обработка ПДн, нужен opt-in; ст. 18 Закона «О рекламе» в части cookie-уведомлений — по аналогии практики).
- Фикс: грузить `tag.js` и пиксель только после `lsGet("hkoop-cookie")==="1"` (состояние в `CookieBanner`, событие `hkoop-...` уже есть как образец); добавить кнопки «Принять»/«Отклонить» и ссылку прямо на `/docs/politika.pdf`; честный текст баннера до включения счётчика — без упоминания Метрики.

### F5. MEDIUM — Cookie-баннер: подразумеваемое согласие, нет отказа, ссылка ведёт не на политику

- Место: `components/CookieBanner.tsx:11-25`.
- Проверка (инспекция): кнопка одна — «Принять»; текст «Продолжая, вы соглашаетесь…» (implied consent); ссылка «политикой конфиденциальности» ведёт на `/docs` (общий каталог документов!), а не на `/docs/politika.pdf`; согласие хранится в `localStorage` (`hkoop-cookie`), отдельных тумблеров «необходимые/аналитика» нет.

Ссылка на каталог вместо политики затрудняет реализацию ч. 2 ст. 18.1 152-ФЗ (свободный доступ к документу об обработке ПДн).

### F6. MEDIUM — Чекбокс согласия в форме — без ссылки на политику, цели и реквизитов оператора

- Место: `components/ConsultForm.tsx:8-10` (используется в `app/page.tsx:112` и `app/contacts/page.tsx:28`).

Политика (`public/docs/politika.pdf`, 3,3 МБ, отдаётся 200 `application/pdf`) существует, с главной/документов на неё ведут 3 ссылки, но с формы — ни одной.
- Факт: ч. 4 ст. 9 152-ФЗ требует в согласии: цель, перечень данных, действия, срок/способ отзыва; ч. 2 ст. 18.1 — опубликовать документ об обработке и обеспечить доступ. Отдельно: форма `onSubmit={e => e.preventDefault()}` (подтверждено, `ConsultForm.tsx:4`, ни одного `fetch`/`axios`/`action` в `app/` и `components/` — grep пуст) — данные никуда не уходят, что хорошо для минимизации (ч. 2 ст. 5 152-ФЗ, минимум данных), но кнопка «Отправить» без сообщения об успехе вводит в заблуждение: пользователь думает, что обращение отправлено.

### F7. MEDIUM — Нет security-заголовков: CSP, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, HSTS

- Место: `next.config.js` (нет секции `headers`), живой ответ dev-сервера.
- Проверка (живая): `curl -s -D - http://localhost:3100/ -o NUL` → только `Vary / Cache-Control: no-store / Content-Type`; `X-Powered-By` отсутствует (держится, `poweredByHeader:false`), но `Content-Security-Policy`, `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, `Strict-Transport-Security` — ни одного.
- Факт: сайт можно встроить в чужой iframe (кликджекинг формы/баннера), нет защиты от MIME-sniffing и утечек referrer на внешние PDF/соцсети; для статики на GitHub Pages заголовки сервера недоступны — значит, нужны meta-компенсации и архитектура без iframe-зависимостей.
- Фикс: для dev/будущего Node — `headers()` в `next.config.js` (frame-ancestors 'self', nosniff, строгий referrer, Permissions-Policy без камеры/микрофона/гео); для Pages — `<meta http-equiv>` минимум + `frame-ancestors` через `<meta>` нельзя → держать критичные действия вне iframe-контекста и добавить JS frame-busting для страниц с формой; HSTS — только когда появится свой домен с HTTPS.

### F8. MEDIUM — `safeHref` не покрывает `img src`: фото книги почёта и логотипы партнёров грузятся как есть

- Место: `app/honor/page.tsx:14` (`<img src={h.photo}>`), `components/PartnersStrip.tsx:11` (`<img src={p.logo}>`). Для сравнения покрыто: `PartnersStrip.tsx:21` (`href=safeHref`), `DocsFilter.tsx:42-43`, `app/contacts/page.tsx:9-11`, `app/page.tsx:37`.
- Проверка (инспекция + данные): текущие данные безвредны (7 фото — все `/images/honor/…`, 13 логотипов — все `/images/…`, URL партнёров — обычные https, внешних `img src` нет — сверено по `data/*.json`). Но поле `photo`/`logo` из БД идёт в `src` без `safeHref`: запись вида `https://tracker.evil/p.png` превратит каждую страницу в маяк (IP/UA посетителей третьему лицу, без согласия — см. F3–F5), а будущий рендер через PDF-превью/соцсети расширит поверхность.
- Факт: React экранирует атрибуты (разрыв из `src="…"` невозможен, `javascript:` в `<img>` современные браузеры не исполняют), поэтому это не stored-XSS сегодня, а privacy-дверь + мина на будущее.
- Фикс: `src={safeHref(h.photo) ?? "/images/placeholder.png"}`, то же для `p.logo`; в идеале — allowlist только site-relative для картинок (внешние hosts запретить вовсе) + `referrerPolicy="no-referrer"` на `<img>`.

## Что проверено и держится (уже исправленное — как новое не засчитывается)

- SQL-инъекции: все 8 вызовов `q()` — статический SQL, единственный параметр (`news/[id]`, `page.tsx:17`) связан через `?`. Живые пробы `'…OR 1=1--`, `%2e%2e`-траверс, несуществующий id — везде аккуратное «Не найдено», ошибок/трейсов нет.
- Отражённый XSS: `/search?q=<script>alert(1)</script>` — в HTML только `value="&lt;script&gt;…"` и `\u003c` в RSC-потоке, сырого отражения нет (React-экранирование + `encodeURIComponent` в `HeaderSearch.tsx:44`).
- `safeHref` (`lib/url.ts:3-9`): allowlist `https?://` + site-relative, `javascript:`/`data:`/`//evil` режутся (разобрано по регексу, граничные случаи `//`, `/\`, `JaVaScRiPt:` — все отклоняются); применён везде для href/iframe из БД, кроме `img src` (см. F8).
- Секреты: `.env.local` по HTTP → `404`, `package.json` → `404`, `.git/HEAD` → `404`; `X-Powered-By` отсутствует; хардкода паролей в коде нет (`lib/db.ts:6-7` — только env с пустыми дефолтами).
