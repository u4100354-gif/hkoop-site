## Как устроена система (карта цепочек — читать первой)

Находки ниже — не разрозненные баги, а разрывы в четырёх цепочках. Чинить надо цепочки целиком, иначе фикс одного звена обойдут через соседнее:

- **Цепочка A «БД → рендер → браузер»**: `lib/db.ts (q)` → `app/*/page.tsx` → `components/*` → HTML. Параметризация SQL держится везде, allowlist `safeHref` покрывает href/iframe из БД — но НЕ покрывает `img src` (фото книги почёта, логотипы партнёров). Тот, кто пишет в БД (пресс-служба через phpMyAdmin), — де-факто автор HTML сайта.
- **Цепочка B «согласие → Метрика → передача данных»**: `CookieBanner` (флаг `hkoop-cookie` в localStorage) никак не связан с загрузчиком Метрики в `app/layout.tsx`. Сегодня счётчик выключен (переменной нет в dev), но включение по инструкции из `.env.example` запустит передачу данных в Яндекс до и без согласия.
- **Цепочка C «dev → export → Pages»**: dev-раздача Next не отдаёт security-заголовки; статический экспорт на Pages их тоже не добавит сам. То, что не заложено в код/конфиг сейчас, не появится в проде.
- **Цепочка D «админ → БД → сайт»**: phpMyAdmin 5.2.2 за логином (держится), но светит версией, работает по HTTP, в форме виден `user: root`. Взлом админки = запись в БД = stored-контент на всех страницах через цепочку A.

- **Место:** HTTP-ответы `http://localhost:3100/` (источник — отсутствие конфига заголовков в `next.config.js`, там только `poweredByHeader: false` и `redirects`).
