# Аудит сайта ХКООП: безопасность и соответствие законам РФ (включая 152-ФЗ)

Дата: 10.10.2026. Объект: рабочее дерево `hkoop-site` (ветка `backup-2026-10-10`), dev-сервер http://localhost:3100, phpMyAdmin http://127.0.0.1:8081. Проект не менялся: только чтение кода и безопасные GET-пробы.

## Допущения

1. Прод — статический экспорт на GitHub Pages (интерактив БД там отсутствует, часть рисков касается только dev/локальной сборки).
2. Пароли в `db/README.md` считаются локальными тестовыми, но сам факт их хранения в git — находка.
3. Права mysql-пользователя и содержимое `politika.pdf` глубже обложки не проверялись (БД — только чтение, PDF — наличие/доступность/ссылки).

## Проверено, держится (не засчитывать как новое)

- Все SQL-запросы параметризованы (`WHERE id=?`, ни одной конкатенации): `app/news/[id]/page.tsx:17`, `app/page.tsx:33-35`, остальные `app/*/page.tsx`. Живой probe `/news/x' OR '1'='1` → 200 «Не найдено», без ошибок и утечек.
- `lib/url.ts:3-9` — allowlist http(s)/site-relative для href/iframe из БД; применяется в контактах, партнёрских ссылках, PDF-превью.
- `poweredByHeader: false` (`next.config.js`) — заголовка `X-Powered-By` в ответах нет (проверено).
- `.env.local` и `.env` по HTTP → 404 (проверено). `.gitignore` покрывает `.env`, `.env.local`, `.next-export`.
- Отражённый XSS через `?q=` нейтрализован экранированием React: probe `?q="><svg onload=alert(2)>` отразился как `value="&quot;&gt;&lt;svg..."` — скрипт не выполняется.
- Инъекции пути `/news/../etc/passwd`, `/%2e%2e/...` → чистый 404 без стектрейса. Несуществующий id → 200 «Не найдено», без деталей ошибки.
- API-роутов нет (`app/api` отсутствует) — мутаций серверной стороны нет. ConsultForm только `preventDefault` — сеть молчит.
- phpMyAdmin отвечает страницей входа (200 с формой логина) — без логина не пускает.
- Импринт есть: адрес, телефон, email в шапке, футере и на `/contacts`. Версия для слабовидящих работает (`ViProvider`, классы `vi-mode`/`vi-big`/`vi-noimg` в `app/globals.css:206-212`).
- Партнёрские ссылки — информационные (госорганы, ФНПР, фонды, вузы), признаков скрытой рекламы нет.

## Ранked-список находок (от важного к мелкому)

### 1. HIGH — Пароли БД лежат в git-репозитории
- **Место:** `db/README.md` (отслеживается git: `git ls-files` содержит `db/README.md`; `.gitignore` его не покрывает).
- **Проверка:** инспекция кода — файл содержит два логина/пароля в открытом виде; команда `git ls-files | findstr README` показывает файл в индексе.
- **Факт:** любой клон/форк/утечка репозитория отдаёт доступы к MariaDB. Даже «локальные» пароли затем переиспользуются.
- **Фикс (описательно):** убрать пароли из файла, заменить на плейсхолдеры; историю git переписать (`git filter-repo`/BFG) или как минимум сменить оба пароля; добавить `db/README.md`-секреты в env-файл, файл в репозитории оставить как шаблон.

### 2. HIGH — Next.js 14.2.5 с известными CVE не обновлён
- **Место:** `package.json:10` (`"next": "14.2.5"`).
- **Проверка:** инспекция + сверка с бюллетенями Next.js: ветка 14.2 до ~14.2.25 содержит CVE-2025-29927 (обход авторизации через middleware, CVSS 9.1), CVE-2024-46982, CVE-2024-47877 (DoS/кэш). Проект middleware не использует и прод — статика, поэтому эксплуатация затруднена, но dev-сервер уязвим.
- **Факт:** зависимость с публичными эксплойтами.
- **Фикс:** обновить `next` до последнего 14.x (≥14.2.25) или 15.x, прогнать `npx tsc --noEmit` и пересобрать; зафиксировать lock-файл.

### 3. HIGH — Яндекс.Метрика грузится без привязки к согласию (152-ФЗ, когда счётчик включат)
- **Место:** `app/layout.tsx:27-32` (`{ym && (... mc.yandex.ru ...)}`).
- **Проверка:** инспекция — скрипт вставляется безусловно при заданном `NEXT_PUBLIC_YM_ID`, чтение `CookieBanner.tsx` подтверждает: согласие (`hkoop-cookie`) нигде не проверяется перед вставкой. Сейчас `NEXT_PUBLIC_YM_ID` закомментирован (`.env.example`), живой probe `/` не содержит `mc.yandex` — то есть нарушение «спящее», сработает в день включения счётчика.
- **Факт:** передача данных в Метрику до согласия нарушает ч. 1 ст. 6, ст. 9 152-ФЗ (обработка только с согласия) и разъяснения Роскомнадзора о cookie/аналитике.
- **НПА:** 152-ФЗ ст. 6, 9, 18.1; Постановление Правительства № 5128 (состав согласия — не применяется напрямую, но ориентир).
- **Фикс:** в `layout.tsx` вставлять блок Метрики только если `localStorage hkoop-cookie === "1"` (клиентский gate-компонент вместо серверного условия), плюс кнопка «Отклонить» в баннере.

### 4. MEDIUM — Cookie-баннер без кнопки отказа и с неточной ссылкой
- **Место:** `components/CookieBanner.tsx:11-25`.
- **Проверка:** инспекция + живой рендер — только кнопка «Принять», отказа нет; ссылка «политикой конфиденциальности» ведёт на `/docs` (каталог), а не на `/docs/politika.pdf`.
- **Факт:** нет реального выбора; пользователь не попадает сразу на политику.
- **НПА:** 152-ФЗ ст. 9 (добровольность согласия); ст. 18.1 (информирование).
- **Фикс:** добавить «Отклонить», ссылку поправить на `/docs/politika.pdf`, согласие/отказ хранить отдельно от аналитики.

### 5. MEDIUM — `<img src>` из БД без allowlist: фото книги почёта и логотипы партнёров
- **Место:** `app/honor/page.tsx:15` (`<img src={h.photo}>`), `components/PartnersStrip.tsx:11` (`<img src={p.logo}>`).
- **Проверка:** инспекция — в отличие от href/iframe, эти два `src` не проходят через `safeHref`. Вектор — только через правку БД (phpMyAdmin/админка), т.е. хранимый XSS второго порядка (`data:text/html`, внешний трекер в `src`). Живой `/honor` сейчас отдаёт локальные картинки — чисто.
- **Факт:** разрыв в иначе аккуратной allowlist-стене; `javascript:` в `<img>` современные браузеры не выполняют, но `data:`-SVG/внешние URL для трекинга возможны.
- **Фикс:** пропускать `h.photo` и `p.logo` через `safeHref` (или строже: только site-relative `/images/...`), при `null` — плейсхолдер как сейчас при `err`.

### 6. MEDIUM — Нет security-заголовков
- **Место:** URL `http://localhost:3100/` (ответы dev-сервера).
- **Проверка:** живой probe `Invoke-WebRequest http://localhost:3100/` — в заголовках только `Vary, Connection, Cache-Control: no-store, Content-Type`; отсутствуют `Content-Security-Policy`, `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`. Проверка заголовка `X-Powered-By` — отсутствует (хорошо).
- **Факт:** сайт без CSP/clickjacking-защиты; для статического прода на Pages часть заголовков тоже не выставляется по умолчанию.
- **Фикс:** добавить `headers()` в `next.config.js` для dev/SSR-стенда; для GitHub Pages — `<meta http-equiv>`-минимум и `referrer`/`frame-ancestors` через CSP-meta; iframe карты оставить в allowlist CSP (`frame-src https://yandex.ru`).

### 7. MEDIUM — Чекбокс согласия в форме без ссылки на политику и без данных оператора
- **Место:** `components/ConsultForm.tsx:8-10`.
- **Проверка:** инспекция — текст «Даю согласие на обработку персональных данных», `required` есть, но ссылки на `politika.pdf` и строки «оператор: Союз ХКООП, адрес, email» рядом нет.
- **Факт:** формальное согласие есть, информирование по ст. 18.1 слабое. Смягчает: форма ничего не отправляет (минимизация соблюдена).
- **НПА:** 152-ФЗ ст. 9, 18.1.
- **Фикс:** добавить под чекбоксом ссылку «Политика конфиденциальности (PDF)» и строку оператора; когда появится бэкенд — отдельное согласие + цели/сроки хранения.

### 8. LOW — Нет `robots.txt` / `sitemap.xml`
- **Место:** URL `http://localhost:3100/robots.txt` → 404.
- **Проверка:** живой probe — 404; `public/` содержит только `docs/`, `images/`, QR-файлы.
- **Факт:** поисковики без подсказок; 404-страницы отдают `meta robots noindex` (хорошо), но весь сайт индексируется по умолчанию.
- **Фикс:** добавить `app/robots.ts` и `app/sitemap.ts` (статический экспорт их поддерживает).

### 9. LOW — Форма «Отправить» ничего не делает и вводит в заблуждение
- **Место:** `components/ConsultForm.tsx:4` (`onSubmit={e => e.preventDefault()}`), без `success`-состояния; в `app/page.tsx`/`app/contacts/page.tsx` подпись «Бесплатная консультация».
- **Проверка:** инспекция — нет `fetch`/`mailto`/`action` (grep по компонентам пуст); CONTEXT.md упоминает «mailto-заглушку», но в коде её нет.
- **Факт:** пользователь жмёт «Отправить» — данные исчезают молча. Юридически безопасно (минимизация, 152-ФЗ ст. 5 — данные не собираются), но UX вводит в заблуждение.
- **Фикс:** до появления бэкенда показывать под формой честный дисклеймер («форма не отправляет данные — звоните/пишите: телефон, email») и success-текст не показывать; либо вернуть mailto.

### 10. LOW — Внешние ссылки без `noopener`, iframe карты без `sandbox`/`loading`
- **Место:** `components/PartnersStrip.tsx:29` (`rel="noreferrer"`), `app/contacts/page.tsx:23` (iframe yandex).
- **Проверка:** инспекция — `noreferrer` в современных браузерах покрывает `noopener`, но явного `noopener` нет; iframe без `loading="lazy"` и `sandbox`.
- **Факт:** риск минимальный (React экранирует href, allowlist режет схемы), но гигиена неполная.
- **Фикс:** `rel="noreferrer noopener"`, iframe — `loading="lazy"`, по возможности `sandbox="allow-scripts allow-same-origin"` с проверкой работы виджета.

### 11. LOW — В полях формы нет `maxLength`/валидации
- **Место:** `components/ConsultForm.tsx:5-7`.
- **Проверка:** инспекция — `input`/`textarea` без ограничений длины и типов (`contact` — `autoComplete="off"` вместо `tel`/`email` с паттерном).
- **Факт:** сейчас безвредно (нет бэкенда), но при появлении бэкенда длинные/HTML-вводы станут его проблемой.
- **Фикс:** `maxLength` (имя 100, контакт 120, вопрос 2000), `inputMode`/`type`, серверная валидация при появлении бэкенда.

### 12. INFO — Импринт: добавить ИНН/ОГРН и наименование оператора

- **НПА:** 149-ФЗ ст. 10; для НКО желательно полное наименование + ОГРН.
- **Фикс:** дописать в футер строку «Союз "ХКООП", ОГРН/ИНН ...» после уточнения у руководства.

### 13. INFO — Логотипы партнёров и фото: подтвердить права
- **Место:** `data/partners.json` (13 локальных логотипов в `/images/...`), `app/honor/page.tsx` (фото).

- **Факт:** признаков нарушения нет (информационное использование, ст. 1274 ГК РФ — цитирование/информирование), но письменных подтверждений в репозитории нет.

- **Фикс:** собрать в `docs/` реестр согласий на логотипы/фото; фото персон — согласия по 152.1 ГК РФ хранить у оператора.

## Что чинить первым

1. Убрать пароли из `db/README.md` и сменить их; 2. обновить Next.js; 3. привязать Метрику к согласию и починить баннер/ссылку на политику.

## Вердикт

Показывать сайт людям можно после трёх шагов выше — критических дыр в коде (SQLi/XSS/пути/секреты по HTTP) нет, форма данные не собирает, импринт и версия для слабовидящих на месте; первым чинить пароли в git, обновление Next.js и гейт Метрики за согласие.
