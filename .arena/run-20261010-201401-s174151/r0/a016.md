# Аудит сайта ХКООП: безопасность и соответствие законам РФ (включая 152-ФЗ)

Дата: 10.10.2026. Аудит по рабочему дереву ветки `backup-2026-10-10` как есть, проект не менялся.
Живые пробы — только безопасные GET к `http://localhost:3100` и `http://127.0.0.1:8081`. Секреты не печатаются.

## Допущения

- `NEXT_PUBLIC_YM_ID` в dev-окружении не задан (в HTML главной нет `mc.yandex.ru`); выводы про Метрику — по коду `app/layout.tsx`.
- Права mysql-пользователя и содержимое `.env.local` не проверялись чтением секретов; оценка — по коду и `.env.example`.
- Прод — статический экспорт на GitHub Pages: серверные заголовки там выставить нельзя, это учтено в рекомендациях.

## Коротко для руководства

Критических дыр, через которые сайт прямо сейчас можно взломать с улицы (SQL-инъекция, отражённый XSS, утечка `.env.local`), **нет** — ранее исправленное держится, проверки ниже это подтверждают. Главный реальный риск — **устаревший Next.js 14.2.5 с известными CVE**. Главная юридическая работа — **дожать согласие на cookie/Метрику и форму** (152-ФЗ). Всё остальное — средний и низкий приоритет.

### 1. HIGH — Уязвимый Next.js 14.2.5

**Место:** `package.json:12` (`"next": "14.2.5"`).

**Проверка (инспекция кода):** в зависимостях зафиксирован `next 14.2.5` (август 2024), сторонних библиотек всего две (`mysql2`, `react`), но сам фреймворк с тех пор получал критические патчи. Главная — CVE-2025-29927 (обход авторизации через заголовок `x-middleware-subrequest`, затрагивает все 14.x до 14.2.25). У сайта нет middleware с авторизацией, поэтому прямой эксплуатации этой CVE здесь нет, но остаются более поздние патчи ветки 14.2.x (отравление кеша, DoS-векторы), которых в 14.2.5 нет.

**Фикс:** обновить `next` минимум до `14.2.25+` (лучше до последнего 14.x), затем обязательно `npx tsc --noEmit` и `STATIC_EXPORT=1 npm run build`, проверить экспорт. Дальше — `npm audit` в регулярный процесс перед каждым деплоем на Pages.

### 2. MEDIUM — Cookie-баннер: нет отказа, неверная ссылка (152-ФЗ)

**Место:** `components/CookieBanner.tsx:12-24`.

**Факт:** в баннере одна кнопка «Принять», кнопки «Отклонить» нет — согласие получается безальтернативным, а текст «Продолжая, вы соглашаетесь…» превращает согласие в подразумеваемое. Ссылка «политикой конфиденциальности» ведёт на `/docs` (каталог документов), а не на сам текст политики. Цитата:

```tsx
<a href="/docs">политикой конфиденциальности</a>
```

**Норма:** ч. 1 ст. 9, ч. 4 ст. 9, п. 5 ч. 1 ст. 18.1 ФЗ-152 — согласие должно быть свободным, конкретным и информированным; северо-западный округ практики Роскомнадзора прямо не признаёт «продолжение пользования сайтом» согласием на метрику/cookie.

**Фикс:** добавить кнопку «Отклонить» (писать `hkoop-cookie=0` и не показывать снова), ссылку вести прямо на `/docs/politika.pdf`, выбор пользователя реально учитывать при подключении Метрики (см. № 3).

### 3. MEDIUM — Метрика подключается мимо согласия (152-ФЗ)

**Место:** `app/layout.tsx:27-31`.

**Факт:** скрипт `https://mc.yandex.ru/metrika/tag.js` и `ym(..., "init", ...)` рендерятся всем посетителям, как только задан `NEXT_PUBLIC_YM_ID`, — флаг из cookie-баннера (`hkoop-cookie`) нигде не читается. Цитата:

```tsx
{ym && (<><script dangerouslySetInnerHTML={{__html: `...(window,document,"script","https://mc.yandex.ru/metrika/tag.js","ym");ym(${ym},"init",...`}} />...
```

**Проверка (живой probe):** `GET http://localhost:3100/` — строки `mc.yandex` в HTML нет, т.е. в dev счётчик не задан и нарушение сейчас спящее; но стоит задать ID для прода — трекинг включится у всех, включая отказавшихся.

**Норма:** та же, что в № 2, плюс требование локализации и минимизации: Метрика передаёт данные третьей стороне (Яндекс) — это требует отдельного явного согласия.

**Фикс:** грузить тег Метрики только если `lsGet("hkoop-cookie")==="1"` (клиентский компонент-обёртка вместо безусловного рендера в layout); при отказе — не грузить вообще, включая `noscript`-пиксель.

### 4. MEDIUM — Пути картинок из БД идут в `src` без проверки

**Место:** `app/honor/page.tsx:14` (`<img src={h.photo} ...>`), `components/PartnersStrip.tsx:11` (`<img src={p.logo} ...>`).

**Факт:** ссылки (`href`, iframe PDF) везде пропущены через `safeHref`, а атрибуты `src` картинок — нет. Эксплуатация требует права писать в БД (например, через phpMyAdmin), т.е. это «вторая ступень», но она превращает компрометацию учётки редактора в атаку на всех посетителей: внешний URL даст злоумышленнику IP/логи посетителей (трекинг-пиксель), а `data:`-URL — доставку вредоносного контента с вашего домена. React экранирует текст (`alt={h.fio}` безопасен), но `src` — это URL, экранирование от подмены адреса не спасает.

**Проверка (инспекция):** в `PartnersStrip` через `safeHref` идёт только `p.url` (строка 21), `p.logo` идёт в `<img>` как есть (строка 11); в `honor/page.tsx` `h.photo` никак не фильтруется.

**Фикс:** пропускать `h.photo` и `p.logo` через `safeHref` (при желании — отдельный `safeImgSrc`, разрешающий только site-relative и доверенные CDN), при `null` показывать заглушку (в honor она уже есть).

### 5. MEDIUM — Форма консультации вводит в заблуждение; согласие без реквизитов (152-ФЗ)

**Место:** `components/ConsultForm.tsx:1-14` (рендерится на `/` и `/contacts`).

**Факт:** кнопка «Отправить» при `onSubmit={e => e.preventDefault()}` ничего не отправляет и ничего не сообщает — пользователь уходит уверенным, что обращение принято, а помощи не дождётся. Чекбокс «Даю согласие на обработку персональных данных» (`required`) есть — это хорошо, — но рядом нет ни ссылки на политику, ни названия оператора, ни целей обработки. Пока форма ничего не отправляет, обработки ПДн нет (это подтверждаю), но текст согласия обещает обработку, которой нет, а когда появится бэкенд — нынешнего чекбокса уже не хватит.

**Норма:** ст. 9 ФЗ-152 (содержание согласия: оператор, цели, перечень данных), ст. 10 149-ФЗ (достоверность информации на сайте).

**Фикс:** сейчас — добавить под кнопкой честный текст «Демо-версия: форма пока никуда не отправляется, звоните 8 (4212) 32-87-18» и ссылку «Политика конфиденциальности» рядом с чекбоксом; при появлении бэкенда — согласие с реквизитами оператора, целями, сроком + состояния success/error + `maxLength` (см. № 8).

### 6. MEDIUM — Отсутствуют заголовки безопасности

**Место:** `next.config.js` (нет секции `headers`), живой probe.

**Проверка (живой probe):**

```
GET http://localhost:3100/ → 200
ответ: Vary, Cache-Control: no-store, must-revalidate, Content-Type — и всё.
Нет: content-security-policy, strict-transport-security, x-frame-options,
x-content-type-options, referrer-policy. Заголовка X-Powered-By нет (хорошо).
```

**Факт:** `poweredByHeader: false` держится. Но любой внешний iframe/скрипт (карта Яндекса, Метрика) ничем не ограничен; страницу можно встроить в чужой iframe (кликджекинг формы), MIME-sniffing не запрещён.

**Фикс:** добавить `headers()` в `next.config.js` (CSP с allowlist `mc.yandex.ru`, `yandex.ru/map-widget`, `frame-ancestors 'self'`, `object-src 'none'`; `X-Frame-Options: SAMEORIGIN`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, HSTS — только если прод за HTTPS). Честная оговорка: для статического экспорта (`output: export`) Next секции `headers` не применяет, а GitHub Pages свои заголовки не отдаёт — поэтому для прода продублировать защиту мета-тегами и рассмотреть Cloudflare/выделенный хостинг, где заголовки настраиваются.

### 7. LOW — `safeHref` блокирует `javascript:`/`data:`, но пропускает любой `https:`

**Место:** `lib/url.ts:3-9`.

**Факт:** регулярка `/^(https?:\/\/|\/[^/\\])/i` корректно режет `javascript:`, `data:`, `//evil` (проверено чтением: `//evil` не проходит из-за второго `/`), ограничивает длину 2000. Но `https://любой-фишинг.example` из скомпрометированной БД отрендерится как доверенная ссылка с вашего сайта (проверка: партнёрские ссылки идут в `_blank` с `rel="noreferrer"` — табнаббинг закрыт, фишинг доверия остаётся).

**Фикс:** для соцсетей/карт держать точный allowlist доменов (`vk.com`, `t.me`, `max.ru`, `yandex.ru`), для партнёров — ручная модерация + периодическая сверка `partners.url` с известным списком (SELECT и глазами, без изменений в БД).

### 8. LOW — Поля форм без `maxLength` и типов

**Место:** `components/ConsultForm.tsx:5-7`, `components/HeaderSearch.tsx:50-61`, `components/DocsFilter.tsx:28`, `components/NewsFilter.tsx:27-34`, `app/search/page.tsx:34`.

**Факт:** ни у одного текстового поля нет `maxLength`; у «Телефон или email» нет `type="tel"`/`inputMode`. Сейчас урона нет (форма никуда не шлёт, поиск — клиентский фильтр по статике,超длинная строка максимум подвиснет на клиенте), но это отсутствие гигиены, которое выстрелит при появлении бэкенда.

**Фикс:** `maxLength={200}` имени/контакту, `maxLength={2000}` вопросу, `maxLength={200}` поискам; контакту — `type="tel"` + `autoComplete="tel email"`; лимиты продублировать серверной валидацией, когда появится приём данных.

### 9. LOW — Версия для слабовидящих есть, но недожата (ГОСТ Р 52872-2019)

**Место:** `components/ViProvider.tsx:1-46`, `components/Header.tsx:55-57`.

**Факт:** кнопка в шапке есть и видна, режим включается (`body.vi-mode`), выбор переживает перезагрузку (`hkoop-vi` в localStorage), внутри панели — размер шрифта и отключение картинок, `skip`-ссылка «Перейти к содержанию» есть. Недожато: `vi-big`/`vi-noimg` не сохраняются (только сам факт режима), высококонтрастной темы/синтеза ГОСТ (цветовые схемы «чёрное на белом» и т.п.) нет, состояние не отражено в `aria-pressed`.

**Фикс:** сохранять все три флага, добавить 2–3 цветовые схемы по ГОСТ, кнопке — `aria-pressed`, проверить контраст `vi-mode` (WCAG AA 4.5:1 для текста).

### 10. LOW — Логотипы и фото: оформить права (оргмера, не код)

**Факт:** на сайте используются чужие товарные знаки (логотипы партнёров) и фотографии людей (книга почёта). Признаков нарушения в коде нет, ссылки партнёров — обычные информационные (без `utm_*`, без «реклама»), что соответствует позиции ФАС: простое упоминание партнёра не реклама по ст. 16 38-ФЗ. Но письменные согласия должны лежать в папке, а не в памяти.

**Норма:** ст. 1229, 1484 ГК РФ (товарные знаки), ст. 152.1 ГК РФ (изображение гражданина).

**Фикс:** собрать согласия правообладателей логотипов и лиц с фото (или их наследников для ветеранов) в дело; новым фото — расписка сразу; в футер добавить «Использование материалов — с разрешения правообладателей».

## Что проверялось и признано порядком

- **SQL-инъекции:** все вызовы `q()` — либо статические SELECT без параметров, либо `WHERE id=?` с параметром (`app/news/[id]/page.tsx:17`). Живой probe `GET /news/1' OR '1'='1` → 200 с дружелюбным «Не найдено», дампа нет. Вердикт: инъекций нет.
- **Отражённый XSS:** `GET /search?q=<script>alert(1)</script>` — в HTML значение лежит экранированным (`value="&lt;script&gt;alert(1)&lt;/script&gt;"`), живого `<script>alert` в ответе нет. Поиск и фильтры — клиентские, в БД запрос не уходит. Вердикт: чисто.
- **Инъекции в путях:** `/news/../..`, `%2e%2e`, спецсимволы — файлового чтения по `id` в коде нет, всё уходит параметром в БД и заканчивается страницей «Не найдено». Вердикт: неэксплуатируемо.
- **Секреты:** `GET /.env.local` → 404; `X-Powered-By` в ответах нет; `.gitignore` закрывает `.env`, `.env.local`, `.next-export`; `.env.example` содержит только плейсхолдеры. Вердикт: держится.
- **API/мутации:** `GET /api/test` → 404; POST-приёма нет нигде (форма — `preventDefault`). Вердикт: поверхности для записи через сайт нет.
- **Ошибки:** несуществующий id — 200 с «Не найдено», без стектрейса и деталей SQL. Вердикт: детали не светятся.
- **phpMyAdmin:** `GET http://127.0.0.1:8081/` → 200 (страница входа доступна, за логином — как и было заявлено). Рекомендация без изменений: сложный пароль, вход только с localhost, неиспользуемые учётки БД — с минимальными правами (только SELECT для сайта, без FILE/GRANT).
- **Импринт (ст. 10 149-ФЗ):** адрес (Хабаровск, ул. Муравьёва-Амурского, 4), телефон 8 (4212) 32-87-18, email ksps-priem@mail.ru — в шапке, футере и `/contacts` единообразно. Вердикт: есть.
- **Политика и PDF:** `GET /docs/politika.pdf` → 200, ссылка с `/docs` есть. Вердикт: документ доступен (содержимое PDF на соответствие 152-ФЗ — отдельная юридическая вычитка, вне рамок кодового аудита).
- **Реклама (38-ФЗ):** партнёрские ссылки без маркировки — допустимо: это некоммерческое информирование о составе объединения, признаков рекламы (призыв покупать, utm-разметка, оплата) нет.
