## Ranked-список находок (новое)

### HIGH-1. Next.js 14.2.5 содержит известные критические CVE (особенно CVE-2025-29927)
- Место: `package.json:12` (`"next": "14.2.5"`).
- Проверка: инспекция кода. Версия августа 2024, младше исправлений линейки 14.2.x. По открытым бюллетеням: CVE-2025-29927 (обход middleware-авторизации, CVSS ~9.1, исправлено в 14.2.25 / 15.2.3), плюс смежные бюллетени по кэшу и Server Functions для 14.x; для React-экосистемы — CVE-2025-55182 (RSC, декабрь 2025). Уверенность средняя-высокая: точный список зависит от бэкпортов, но 14.2.5 почти наверняка уязвима минимум к CVE-2025-29927.
- Факт: единственная сетевая зависимость с историей критических дыр, а сайт собирается и отдаётся именно ею.
- Фикс: обновить `next` минимум до последней 14.2.x (14.2.25+), прогнать `npx tsc --noEmit`, пересобрать экспорт, затем плановый переезд на поддерживаемую ветку. Отдельно проверить `react/react-dom 18.3.1` и `mysql2 ^3.24.5` через `npm audit`.

### HIGH-2. Яндекс.Метрика в `layout` подключается безусловно, без проверки согласия
- Место: `app/layout.tsx:15,27-31`.
- Проверка: инспекция кода + живой probe. Сейчас `NEXT_PUBLIC_YM_ID` не задан (в `.env.example:6` закомментирован), и probe страницы `/contacts` не нашёл `ym()`/`metrika` — то есть счётчик молчит. Но код `ym && (...)` вставляет скрипт `https://mc.yandex.ru/metrika/tag.js` сразу при наличии ID, а `CookieBanner.tsx:7-9,17-22` лишь пишет флаг `hkoop-cookie` в localStorage, который `layout` (серверный компонент) никогда не читает. Стоит задать ID — Метрика поедет до клика «Принять». Уверенность высокая.
- НПА: 152-ФЗ ст. 9 (согласие), ст. 18 (информирование); требования о cookie-согласии; позиция Роскомнадзора о метрике как обработке ПДн.
- Фикс: грузить скрипт Метрики только после согласия (клиентский компонент-обёртка читает `hkoop-cookie`, при отсутствии — не вставляет; `noscript`-пиксель — так же). Либо включить режим `defer` после Accept. Минимально: gating из трёх строк вокруг существующего блока.

### HIGH-3. Нет security-заголовков: CSP, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, HSTS
- Место: `next.config.js` (нет блока `headers()`), `app/layout.tsx`.
- Проверка: живой probe `curl.exe -sI http://localhost:3100/` → только `Vary`, `Cache-Control: no-store, must-revalidate`, `Content-Type`. Нет `Content-Security-Policy`, `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy-Policy`, `Strict-Transport-Security`. Уверенность высокая.
- Факт: сайт уязвим к кликджекингу (нет запрета фреймов), к MIME-sniffing и к подстановке сторонних скриптов (нет CSP). Для информационного сайта это главный дешёвый выигрыш.
- Фикс: добавить `async headers()` в `next.config.js` (для dev/прод-сервера) и/или `<meta http-equiv>` + `export`-совместимые meta для статики GitHub Pages: `X-Frame-Options: DENY` (или `frame-ancestors 'none'` в CSP), `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, базовый `CSP: default-src 'self'; img-src 'self' data:; script-src 'self' https://mc.yandex.ru; frame-src https://yandex.ru`. HSTS — на уровне хостинга при наличии HTTPS.

### MEDIUM-1. `img src` из БД не проходят `safeHref`: логотипы партнёров и фото книги почёта
- Место: `components/PartnersStrip.tsx:11` (`<img src={p.logo}>`), `app/honor/page.tsx:14` (`<img src={h.photo}>`). Для сравнения: ссылки там же фильтруются (`PartnersStrip.tsx:21`).
- Проверка: инспекция кода + SELECT текущих значений (только чтение): все 13 `partners.logo` — вида `/images/...` (benign), все 7 `honor.photo` — `/images/honor/...` (benign). То есть сегодня эксплуатации нет, но ближайшая правка через phpMyAdmin (пресс-служба правит контент именно там) может положить в поле `javascript:...`/подозрительный `data:` или внешний URL. Уверенность в отсутствии текущей эксплуатации высокая; в хрупкости — высокая.
- Факт: `javascript:` в `img src` современные браузеры не исполняют, но `data:image/svg+xml` с JS, `onError`-векторы через битые URL и подмена картинки на внешний трекер — реальны. Плюс утечка referer на внешний хост.
- Фикс: пропускать `p.logo` и `h.photo` через `safeHref` (расширив его при нужде кириллицей/пробелами в именах — сегодня в БД есть `Скакун_1.jpg` и `Сушко_Г.jpg`, убедиться, что фильтр их не режет), при `null` — плейсхолдер как уже сделано для пустого фото.

### MEDIUM-2. Согласие 152-ФЗ есть (чекбокс), но без ссылки на политику и без реквизитов оператора рядом с формой
- Место: `components/ConsultForm.tsx:8-10` (чекбокс «Даю согласие...» без ссылки), `components/CookieBanner.tsx:14-15` (ссылка ведёт на `/docs`, а не на `politika.pdf`), `app/contacts/page.tsx` (на странице с формой вообще нет ссылки на политику — probe не нашёл `politika` в HTML `/contacts`).
- Проверка: инспекция кода + живой probe `/contacts` (нет `politika`, нет `ymetrika`, есть `cookie`). Файл `public/docs/politika.pdf` существует (probe `/docs/politika.pdf` → `200`), ссылка на него есть только на `/docs` (`app/docs/page.tsx:13`). Уверенность высокая.
- НПА: 152-ФЗ ст. 9 ч. 4 (согласие должно быть информированным), ст. 18.1 (оператор обязан опубликовать политику и обеспечить доступ к ней), ст. 22 (уведомление Роскомнадзора).
- Фикс: добавить в `ConsultForm` под чекбоксом ссылку «Политика конфиденциальности (/docs/politika.pdf)», ту же ссылку — в cookie-баннер вместо generic `/docs`; на `/contacts` добавить строку с реквизитами оператора (наименование, адрес, email — уже есть — плюс ИНН/ОГРН и ссылка на политику). Саму форму не менять по поведению (по-прежнему ничего не отправляет + пометка «демо, данные никуда не уходят»).

### MEDIUM-3. Cookie-баннер без отклонения и без привязки к Метрике; согласие хранится в localStorage
- Место: `components/CookieBanner.tsx:1-27`, `lib/storage.ts:1-17`.
- Проверка: инспекция кода. Одна кнопка «Принять», кнопки «Отклонить» нет; отказ возможен только закрытием вкладки. Флаг `hkoop-cookie=1` в localStorage не является согласием по смыслу для серверных вставок (см. HIGH-2). `lsGet/lsSet` глушат исключения приватного режима — это хорошо для надёжности, но решение «показать снова» при запрете cookies отсутствует как состояние. Уверенность высокая.
- НПА: 152-ФЗ ст. 9, 18; практика Роскомнадзора: согласие должно быть добровольным и отзывным.
- Фикс: добавить кнопку «Отклонить» (пишет `hkoop-cookie=0`, Метрику не грузить), ссылку на политику (см. MEDIUM-2), повторный вызов баннера из футера («Настройки cookie»). Поведение при `localStorage недоступен` — считать как «нет согласия».

### MEDIUM-4. Iframe предпросмотра PDF и карта без `sandbox`/ограничений; preview-URL зависит только от `safeHref`
- Место: `components/DocsFilter.tsx:56` (`<iframe src={preview}>` без `sandbox`), `app/contacts/page.tsx:23` (Яндекс-карта, статичный URL — ок).
- Проверка: инспекция кода. `preview` берётся из `safeHref(d.file_local)` — `javascript:`/`data:` отсечены, но `https://evil/...` пройдёт, и iframe откроет чужой сайт в контексте страницы (топ-уровень не сменится, но фишинг возможен). Песочницы нет. Уверенность средняя-высокая.
- Фикс: добавить `sandbox="allow-same-origin"` (без `allow-scripts`/`allow-top-navigation`) к preview-iframe; для внешних `file_old` оставить обычную ссылку вместо iframe; карту оставить как есть (хардкод доверенного хоста) + `loading="lazy"`.

### LOW-1. Внешние ссылки партнёров: `rel="noreferrer"` без явного `noopener`, любой `https://` разрешён
- Место: `components/PartnersStrip.tsx:29`, `app/page.tsx:95`, `lib/url.ts:7`.
- Проверка: инспекция кода. Современные браузеры трактуют `noreferrer` как `noopener`, но явного `noopener` нет; `safeHref` пропускает любой `https://` (включая фишингоподобные при опечатке в БД). Один URL — IDN `https://хабаровсккурорт.рф/` — легитимен, но опечатки в таких доменах вероятны. Уверенность средняя.
- Фикс: `rel="noreferrer noopener"`, при желании — allowlist доверенных доменов партнёров поверх `safeHref`.

### LOW-2. `safeHref` режет пробелы/кириллицу косвенно и не нормализует IDN; `docHref`-фолбэк клеит `habprof.ru + old_url` без валидации
- Место: `lib/url.ts:3-9`, `app/page.tsx:37`.
- Проверка: инспекция кода. Лимит 2000 и trim есть; но не-ASCII пути (`/images/honor/Скакун_1.jpg` в БД лежат как есть в другом месте, через `h.photo` без фильтра — см. MEDIUM-1) при прогоне через `safeHref` могут вести себя неожиданно в разных браузерах; `old_url` проверяется только на `startsWith("/")` — `"/x\" onmouseover=..."` пройдёт как строка, хотя React её экранирует в атрибуте. Реальной дыры сегодня нет. Уверенность средняя.
- Фикс: нормализовать через `encodeURI` + явный IDN→punycode на вставке; фолбэк `habprof.ru` строить через `new URL(old_url, "https://habprof.ru")` с проверкой `origin`.

### LOW-3. Раскрытие структуры Next.js в HTML (`self.__next_f`, имена чанков) + `Cache-Control: no-store` на всё
- Место: живой probe главной и `/search` (flight-данные в теле), заголовок `Cache-Control: no-store, must-revalidate` на все страницы.
- Проверка: живой probe. Flight-пейлоад раскрывает имена роутов и структуру — не секрет, но облегчает разведку; `no-store` везде — безопасно, но медленно и без нужды для статики. Уверенность высокая.
- Фикс: ничего срочного; при экспорте на Pages убедиться, что flight-мусор отсутствует в статике (экспорт — чистый HTML); кэш-политику для статики (`/_next/static`, `/images`) выставить долгую, для HTML — короткую.

## Часть 2. Законы РФ — сводка по пунктам

- **152-ФЗ, согласие (ст. 9):** чекбокс в форме есть (`ConsultForm.tsx:9`), но без ссылки на политику и без разъяснения (MEDIUM-2). Cookie-согласие — одна кнопка без отказа (MEDIUM-3). Метрика при появлении ID поедет без согласия (HIGH-2).
- **152-ФЗ, политика (ст. 18.1):** `politika.pdf` существует и отдаётся (`/docs/politika.pdf` → 200), ссылка есть на `/docs`, но не у формы и не в баннере напрямую. Реквизитов оператора (ИНН/ОГРН) на сайте не найдено — добавить.
- **152-ФЗ, минимизация и хранение:** форма ничего не отправляет (подтверждено кодом) — нарушений нет; серверного хранения ПДн нет; локализация неприменима пока нет сбора. Уведомление в Роскомнадзор — проверить по факту будущего запуска сбора.
- **Импринт (ст. 10 149-ФЗ):** адрес, телефон, email, часы есть в `Header.tsx:52-54` и `Footer.tsx:7-10` — соответствует.
- **Версия для слабовидящих (ГОСТ Р 52872-2019):** есть и работает (`ViProvider.tsx`, кнопка в `Header.tsx:55-57`, классы `vi-mode/vi-big/vi-noimg`, панель с размером шрифта и отключением картинок). Замечание: настройка только в localStorage — при его запрете сбрасывается; критичным не является.
- **Метрика:** сейчас выключена (ID не задан) — претензий нет; при включении — только через согласие (HIGH-2).
- **Реклама (38-ФЗ ст. 18.1):** партнёрские ссылки — информационные (лого+название, без призывов и трекеров), маркировка «реклама» и токен не требуются. Уверенность средняя-высокая.
- **Авторские права:** логотипы партнёров и фото почёта используются как информационные; открытых претензий нет. Рекомендуется собрать письменные разрешения правообладателей в папку (не в коде).
