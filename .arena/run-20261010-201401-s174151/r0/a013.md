# Аудит сайта ХКООП: безопасность и соответствие законам РФ (включая 152-ФЗ)

Аудит проведён по рабочему дереву ветки `backup-20261010-201401-s174151` (как есть, без изменений проекта, БД — только чтение/SELECT, живые пробы — только безопасные GET к `http://localhost:3100`). Секреты не печатаются (имена ключей `.env.local`: `DB_HOST/DB_PORT/DB_USER/DB_PASS/DB_NAME`, значений нет в отчёте).

## Допущения

1. Прод — статический экспорт (`output: export`) на GitHub Pages; dev-заголовки и серверные поведения проверялись на `http://localhost:3100`, для статики часть серверных фиксов переносится в meta/конфиг экспорта.
2. `phpMyAdmin` и права mysql-пользователя приняты по условию задачи (закрыт логином); прямого доступа с моими пробами не было, учетные данные не использовались.
3. Содержимое БД проверено через код и сиды (`data/*.json`, `db/*.sql`), прямых SELECT к боевой БД я не делал — выводы о текущих данных помечены как «по сидам/коду».

## Как построен отчёт (обратным ходом, быстрый маршрут)

Готовый результат, от которого я шёл назад: ранжированный список находок, где у каждой есть severity, точное место, воспроизводимая проверка (цитата кода или команда пробы с выводом) и фикс словами. Шаги назад: (1) список обязательных проверок из задачи → (2) минимальные живые пробы, закрывающие каждое требование → (3) чтение только тех файлов, без которых пробу не доказать → (4) отсев всего, что не меняет вердикт.

Матрица опций (критерии: скорость / покрытие требований / проверяемость):

| Опция | Скорость | Покрытие | Проверяемость | Итог |
|---|---|---|---|---|
| A. Глубокий аудит: весь код + БД построчно + фаззинг | 1/5 | 5/5 | 5/5 | отвергнута: не окупится за один проход |
| B. Только чтение кода без живых проб | 4/5 | 2/5 | 2/5 | отвергнута: задача требует проб |
| C. Быстрый маршрут: код + точечные GET-пробы | 5/5 | 4/5 | 4/5 | выбрана |

Выбрана опция C: всё, что не двигает итоговый вердикт («можно ли показывать людям и что чинить первым»), вырезано.

## Находки (по убыванию severity)

### F1. HIGH — Уязвимый Next.js 14.2.5 с известными CVE
- **Место:** `package.json:12` — `"next": "14.2.5"`.
- **Проверка (инспекция):** цитата: `"next": "14.2.5"`. Это версия до патчей: CVE-2025-29927 (обход авторизации через заголовок `x-middleware-subrequest`, CVSS 9.1, затронуты 14.x до 14.2.25), CVE-2024-46982 / CVE-2024-47831 (SSRF/DoS в Server Actions и image-optimizer). Отдельного middleware-файла в проекте нет (`app/middleware.*` отсутствует), что снижает применимость CVE-2025-29927, но не снимает остальные и не снимает риск при будущем добавлении middleware.
- **Факт:** зависимости заморожены на уязвимом миноре; `npm audit` на этой версии также ругается. Прод-статика снижает, но не убирает риск (сборка идёт тем же кодом).
- **Фикс (без применения):** поднять `next` минимум до `14.2.25+` (лучше последний 14.2.x), зафиксировать lock-файл, прогнать `npx tsc --noEmit` и `STATIC_EXPORT=1 npm run build`, проверить редиректы из `next.config.js:9-24`.

### F2. HIGH — Яндекс.Метрика в коде грузится без согласия (нарушение 152-ФЗ и правил cookie)
- **Место:** `app/layout.tsx:27-32`.
- **Проверка (инспекция):** цитата: `{ym && (<><script dangerouslySetInnerHTML={... mc.yandex.ru/metrika/tag.js ... ym(${ym},"init",{clickmap:true,...})}} />...)}` — условие только «задан ли `NEXT_PUBLIC_YM_ID`», флага согласия из `CookieBanner` нет. Баннер (`components/CookieBanner.tsx:17-21`) лишь пишет `lsSet("hkoop-cookie","1")` и ни на что не влияет.
- **Проверка (живая проба):** `Invoke-WebRequest http://localhost:3100/` — подстрока `ym(` в HTML отсутствует (счётчик сейчас не задан — хорошо де-факто), но кодовый путь безусловный: стоит задать env — трекинг включится у всех, включая не принявших баннер.
- **НПА:** 152-ФЗ ст. 9 (согласие на обработку ПДн), ст. 18 (информирование); п. 3 ст. 16 149-ФЗ в ред. 2025 г. о согласии на обработку, осуществляемую с использованием cookie/метрики без информирования — нарушение.
- **Фикс:** грузить скрипт Метрики только после `lsGet("hkoop-cookie")==="1"` (client-компонент-обёртка), добавить кнопку «Отклонить», факт согласия/отказа логировать в том же localStorage отдельным ключом, `clickmap/trackLinks` включать только после согласия.

### F3. MEDIUM — Нет заголовков безопасности и CSP
- **Место:** `next.config.js` (весь файл: нет секции `headers()`), `app/layout.tsx` (нет meta CSP).
- **Проверка (живая проба):** команда `Invoke-WebRequest http://localhost:3100/` → заголовки ответа: `Vary, Connection, Transfer-Encoding, Cache-Control: no-store, must-revalidate, Content-Type: text/html; charset=utf-8, Date` — нет `Content-Security-Policy`, `X-Frame-Options`/`frame-ancestors`, `X-Content-Type-Options`, `Referrer-Policy`, `Strict-Transport-Security`, `Permissions-Policy`. Команда: `(Invoke-WebRequest -Uri 'http://localhost:3100/').Headers`.
- **Факт:** сайт встраиваем в чужой iframe (кликджекинг формы), MIME-sniffing не запрещён, referrer и сторонние загрузки не ограничены.
- **Фикс:** в dev/прод-серверном режиме добавить `headers()` (CSP `default-src 'self'; script-src 'self' https://mc.yandex.ru; frame-src https://yandex.ru; img-src 'self' data: https:; object-src 'none'; frame-ancestors 'self'` + `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy`), для статического экспорта продублировать ключевые директивы meta-тегами и проверить, что Метрика/карта не ломаются.

### F4. MEDIUM — Форма «Отправить» ничего не отправляет + согласие без ссылки на политику (152-ФЗ)
- **Место:** `components/ConsultForm.tsx:4-11`.
- **Проверка (инспекция):** цитата: `<form ... onSubmit={(e) => e.preventDefault()}>` + `<input type="checkbox" required /> Даю согласие на обработку персональных данных` — рядом нет ссылки на политику, нет пояснения, что данные никуда не уходят, кнопка называется «Отправить».
- **НПА:** 152-ФЗ ст. 9 ч. 4 (форма согласия должна содержать перечень данных, цели, способы), ст. 18 (разъяснение последствий), ст. 10 149-ФЗ (импринт) косвенно — пользователь вводится в заблуждение о судьбе своих ФИО/телефона/вопроса.
- **Фикс:** в label чекбокса добавить ссылку «…согласно <a href="/docs/politika.pdf">политике</a>», под формой — строку «Демо-режим: заявка никуда не отправляется, для связи используйте …», кнопку переименовать («Показать контакты» / реальный `mailto:`) либо подключить бэкенд с согласием по 152-ФЗ; добавить `maxLength` полям.

### F5. MEDIUM — Cookie-баннер: только «Принять», ссылка не на политику, SSR-молчание
- **Место:** `components/CookieBanner.tsx:5-26`.
- **Проверка (инспекция + проба):** кнопка одна — «Принять», «Отклонить» нет; ссылка ведёт на `/docs`, а не на `/docs/politika.pdf` (цитата: `<a href="/docs">политикой конфиденциальности</a>`); начальное состояние `show=false` + `useEffect` → в SSR-HTML баннера нет. Живая проба: `Invoke-WebRequest http://localhost:3100/contacts` → слово `cookie` в серверном HTML отсутствует (баннер дорисовывается JS). Без JS уведомления нет вообще.
- **НПА:** те же ст. 9, 18 152-ФЗ + требования к информированию о cookie (149-ФЗ).
- **Фикс:** две кнопки («Принять»/«Отклонить»), прямая ссылка на `/docs/politika.pdf`, текст «какие cookie и зачем (в т.ч. Метрика — только после согласия)», SSR-видимый noscript-вариант или статическая плашка до гидратации.

### F6. MEDIUM — Яндекс-карта на /contacts грузится безусловно, до согласия
- **Место:** `app/contacts/page.tsx:22-24` — `<iframe src="https://yandex.ru/map-widget/...">`.
- **Проверка (живая проба):** `Invoke-WebRequest http://localhost:3100/contacts` → подстрока `yandex.ru/map` присутствует (в отличие от главной, где её нет — проверено той же командой). Значит, каждый визит на контакты отдаёт IP/User-Agent Яндексу без предупреждения баннера.
- **НПА:** ст. 9, 18 152-ФЗ (передача третьему лицу/трекинг без согласия).
- **Фикс:** click-to-load: статичная заглушка + кнопка «Показать карту (загрузит Яндекс-виджет)», iframe создавать только после клика/согласия.

### F7. MEDIUM — Книга почёта: `<img src={h.photo}>` без `safeHref` (единственное окно из БД в `src`)
- **Место:** `app/honor/page.tsx:14` — `{h.photo ? <img src={h.photo} alt={h.fio} ... /> : ...}`. Сравнить: партнёры идут через `safeHref` (`components/PartnersStrip.tsx:21`), документы — через `safeHref` (`components/DocsFilter.tsx:42-43`), соцсети в контактах — через `safeHref` (`app/contacts/page.tsx:9-11`).
- **Проверка (инспекция):** `safeHref` (`lib/url.ts:3-9`) режет `javascript:`/`data:`/`//evil` и длинные строки — но на `h.photo` не вызывается. По сидам текущие фото — `/images/*` (чисто), React экранирует разрыв атрибута, современные браузеры не исполняют `javascript:` в `<img>` — поэтому сегодня это не рабочий XSS, а privacy-дыра (внешний трекинг-пиксель через фото) + мина на будущее.
- **Фикс:** `const src = safeHref(h.photo)` с fallback-плейсхолдером (как уже сделано для битой картинки), плюс allowlist доменов картинок при желании.

### F8. LOW — Версия для слабовидящих работает, но неполна по ГОСТ Р 52872-2019
- **Место:** `components/ViProvider.tsx:1-46`, `components/Header.tsx:55-57`.
- **Проверка (инспекция):** вход есть (кнопка в шапке + `toggleVi`), но: при `!vi` компонент возвращает `null` — панель настроек видна только после включения; `useEffect` без массива зависимостей (`ViProvider.tsx:30-33`) каждый рендер переприсваивает `window.toggleVi`; хранится только в localStorage (при запрете cookie сбрасывается — `lib/storage.ts` это молча глотает); нет выбора кернинга/интерлиньяжа/схем, требуемых ГОСТ.
- **НПА:** ГОСТ Р 52872-2019 (доступность), приказ Минкомсвязи № 483 о версии для слабовидящих для социально значимых сайтов (ориентир).
- **Фикс:** всегда видимая кнопка + полная панель (размер/кегль/контраст/интервал/без картинок), CSS-классы уже есть (`vi-mode/vi-big/vi-noimg` — расширить), починить effect-зависимости.

### F9. LOW — Мелочи, которые чинятся за час
- **F9a.** Внешние ссылки с `target="_blank"` имеют `rel="noreferrer"` без явного `noopener` (`PartnersStrip.tsx:29`, `DocsFilter.tsx:43`). Современные браузеры при `noreferrer` подразумевают `noopener`, но явный `noopener noreferrer` надёжнее для старых движков. Фикс: `rel="noopener noreferrer"`.
- **F9b.** Поля формы без `maxLength`/`inputMode` (`ConsultForm.tsx:5-7`): бэкенда нет, урона нет, но 10-МБ вставка в textarea вешает вкладку. Фикс: `maxLength={200/500/2000}`, `inputMode="tel"` у контакта.
- **F9c.** Публичный `search-index.json`/`data/*.json` отдают весь контент поиску (by design, но помнить при публикации чувствительного). Фикс: не класть в индекс ничего, кроме заголовков/отрывков.
- **F9d.** `generateStaticParams` (`app/news/[id]/page.tsx:11-14`) отдаёт `{id: n.id}` где `id` из БД может быть числом, а тип params — string. Сегодня работает (приведение), но строгий `String(n.id)` уберёт warning сборки. Фикс одной строкой.

## Проверено — нарушений нет (с доказательствами)

- **SQL-инъекции:** все вызовы `q()` — статические строки без конкатенации; единственный параметр — `WHERE id=?` с плейсхолдером (`app/news/[id]/page.tsx:17`). Пробы: `/news/1%27%20OR%20%271%27=%271` → 200 «Не найдено», `/news/999999` → 200 «Не найдено», стектрейсов/500 нет. Команда: `Invoke-WebRequest http://localhost:3100/news/1%27%20OR%20%271%27=%271`.
- **Отражённый XSS (`?q=`):** `app/search/page.tsx` — клиентский фильтр, вывод через JSX (экранируется). Проба `/search?q=%3Cscript%3Ealert(1)%3C/script%3E` → 200, в HTML только `value="&lt;script&gt;alert(1)&lt;/script&gt;"` (экранировано в атрибуте), сырого `<script>alert` нет. Проверено подстроками: `<script>alert` — False, `&lt;script` — True.
- **Инъекции в путях:** `/news/..%2F..%2Fetc%2Fpasswd` → 200 «Не найдено», без выхода за маршрут (App Router мапит как `id`, SQL всё равно через `?`).
- **Секреты/заголовки:** `/.env.local` → 404 (проверено: `(404) Не найден`); `X-Powered-By` отсутствует (проверено на 4 URL: везде `no X-Powered-By`, `poweredByHeader: false` в `next.config.js:5`); `.gitignore` покрывает `.env`, `.env.local`, `.next-export` (проверено чтением); хардкода паролей в коде нет (`lib/db.ts` — только `process.env`).
- **API/мутации:** каталог `app/api` отсутствует (glob пуст), все `q()` — `SELECT`; форма — `preventDefault` без fetch.
- **Ошибки:** несуществующие id/кривые параметры дают штатное «Не найдено», 500/трейсов нет.
- **Импринт (ст. 10 149-ФЗ):** адрес, телефон, email есть в шапке (`Header.tsx:52-54`) и подвале (`Footer.tsx:6-10`).
- **Политика (152-ФЗ):** файл `public/docs/politika.pdf` существует (3,4 МБ) и отдаётся `200 application/pdf` по `/docs/politika.pdf`; ссылка с `/docs` есть.
- **Партнёрские ссылки/реклама:** характер информационный (лого+название, `PartnersStrip`), признаков рекламы по 38-ФЗ нет; `safeHref` режет не-http(s) схемы.
- **Авторские права:** логотипы/фото используются в информационных целях организации (ст. 1274 ГК РФ — цитирование/информирование, оценка по открытым данным; точную чистоту прав по каждому логотипу подтвердить договорами).
