# Аудит сайта ХКООП: безопасность и законы РФ (включая 152-ФЗ)

Дата: 10.10.2026. Аудит по рабочему дереву ветки `backup-2026-10-10` как есть, проект не менялся. Живые пробы — только безопасные GET к `http://localhost:3100`. Секреты не печатаются (пароли из `db/README.md` и `.env.local` в отчёт не копировались).

## Допущения

- Прод — статический экспорт (`output: export`) на GitHub Pages; часть серверных мер (заголовки через `next.config.js`) там не работает — это учтено в фиксах.
- БД трогали только чтением через HTTP-рендер; содержимое таблиц судим по тому, что сайт отдаёт в HTML.

## Разобранный сквозной пример (образец проверки)

Беру одно конкретное место и веду его от кода до живого поведения: cookie-баннер против трекеров. `components/CookieBanner.tsx:12-24` обещает «сайт использует cookie и Яндекс.Метрику. Продолжая, вы соглашаетесь», согласие хранится в `localStorage` (`hkoop-cookie`). Но `app/layout.tsx:27-31` встраивает скрипт Метрики при любом установленном `NEXT_PUBLIC_YM_ID` без проверки согласия, а `app/contacts/page.tsx:23` всегда грузит `iframe` с `yandex.ru/map-widget`. Живая проба подтверждает: `GET /contacts` → 200, подстрока `yandex.ru/map-widget` есть; `GET /` при неустановленном счётчике скрипта Метрики нет (`metrika-present: False` — сейчас повезло, счётчик не задан, но путь кода безусловный). Вывод, из которого обобщаю остальной аудит: разрыв между текстом согласия и фактической загрузкой сторонних ресурсов — это и есть главный класс проблем сайта. Остальные находки ниже проверены так же: цитата из кода + команда и вывод.

## Что проверено и держится (не находки)

- SQL: все `q()` без конкатенации, `app/news/[id]/page.tsx:17` — `WHERE id=?` с параметром. Проба `GET /news/nonexistent-id-xyz` → 200, «Не найдено», без стектрейса.
- `lib/url.ts:3-9` — allowlist `https?://` и site-relative; `javascript:`/`data:`/`//evil` режутся. Партнёрские `href`, ссылки документов, соцсети идут через `safeHref`.
- `.env.local` по HTTP → 404 (`GET /.env.local` → 404, тело — стандартная 404-страница). Заголовка `X-Powered-By` в ответе `/` нет (`poweredByHeader: false`, `next.config.js:5`).
- Поиск: `GET /search?q=%3Cscript%3Ealert(1)%3C/script%3E` → 200, в HTML только `value="&lt;script&gt;alert(1)&lt;/script&gt;"`, сырого `<script>alert(1)</script>` нет. Запрос нигде не вставляется через `dangerouslySetInnerHTML` (таких вставок с пользовательскими данными в коде нет; два `dangerouslySetInnerHTML` в `app/layout.tsx:19,29` — статический код и env-переменная, см. находку 8).
- Путь `GET /news/%2e%2e%2f` → «Не найдено», без ошибок. API-роутов нет (`app/api/**` отсутствует), `middleware.*` отсутствует, мутаций нет — формы клиентские.
- `public/docs/politika.pdf` отдаётся: `GET /docs/politika.pdf` → 200, `application/pdf`.

## Ranked-список находок

### 1. HIGH — Пароли БД лежат в git: `db/README.md`
- Место: `db/README.md:8-12` (логин/пароль root и пользователя БД открытым текстом) + `.gitignore:1-8` (файл не покрыт исключениями — там только `.env`/`.env.local`).
- Проверка: инспекция кода. `CONTEXT.md:4` сам требует «пароли только в `db/README.md` и `.env.local` (не коммитить)» — но `db/README.md` это коммитимый файл репозитория, а `.gitignore` его не исключает. Репозиторий публичный (`u4100354-gif/hkoop-site`), значит пароли попадают в историю git и на GitHub.
- Фикс (без применения): сменить оба пароля в MariaDB; вычистить файл и историю (`git filter-repo`/`BFG`), добавить `db/README.md` в `.gitignore`, оставить в репозитории только шаблон без значений; доступы держать только в `.env.local`.

### 2. HIGH — Устаревший Next.js 14.2.5 с известными критическими CVE
- Место: `package.json:12` (`"next": "14.2.5"`).
- Проверка: инспекция кода + сверка с бюллетенями. В 14.2.5 открыты: CVE-2025-29927 (обход авторизации через заголовок `x-middleware-subrequest`, критический, исправлен в 14.2.25), CVE-2024-46982 / CVE-2024-39332 (cache-poisoning/DoS, исправлены в 14.2.9+), CVE-2025-55182 (RCE через RSC-десериализацию, исправлен в 14.2.33 / 15.x, декабрь 2025). Смягчает то, что `middleware.*` в проекте отсутствует (проверено — файлов нет) и прод — статика, но dev-сервер (`localhost:3100`) и будущий SSR всё равно уязвимы.
- Фикс: обновить `next` минимум до последнего 14.2.x (14.2.33+), затем `npx tsc --noEmit`, пересобрать экспорт, следить за бюллетенями.

### 3. MEDIUM — Трекеры грузятся без согласия: карта на «Контактах», Метрика по коду — безусловна
- Место: `app/contacts/page.tsx:23` (`iframe https://yandex.ru/map-widget/...`), `app/layout.tsx:27-31`, `components/CookieBanner.tsx:5-27`.
- Проверка: код + живая проба. `GET /contacts` → 200, `yandex-map-iframe: True` — виджет (и его cookie) подтягивается до любого клика по баннеру. Скрипт Метрики в `layout` проверяет только наличие `NEXT_PUBLIC_YM_ID`, согласия (`hkoop-cookie`) не смотрит. Сейчас счётчик не задан (`metrika-present: False` на `/`), т.е. нарушения по факту нет, но включение счётчика одной переменной окружения сразу включит слежку без согласия — вопреки тексту баннера. НПА: ст. 9, 18–18.1 152-ФЗ (обработка только с согласия, информирование), ст. 10.1 149-ФЗ и практика РКН по cookie-баннерам (отказ должен быть таким же лёгким, как согласие).
- Фикс: грузить `iframe` карты (клик-заглушка «показать карту») и скрипт/пиксель Метрики только после `lsGet("hkoop-cookie")==="1"`; без согласия — ни одного запроса к `yandex.ru`/`mc.yandex.ru`.

### 4. MEDIUM — Баннер: нет кнопки «Отклонить», согласие в localStorage, ссылка ведёт не на политику
- Место: `components/CookieBanner.tsx:11-25` (только кнопка «Принять»), ссылка `href="/docs"`.
- Проверка: инспекция + живой рендер главной (баннер клиентский, в SSR его нет — проверен кодом). Отказ от cookie так же просто, как согласие, не реализован; хранение флага в `localStorage` вместо cookie затрудняет серверный учёт; ссылка ведёт на каталог документов, а не на `/docs/politika.pdf` — пользователь не попадает на политику в один клик.
- Фикс: добавить «Отклонить», писать выбор в cookie (`SameSite=Lax`, срок), ссылку вести прямо на `/docs/politika.pdf`, текстом перечислить цели (аналитика/карта).

### 5. MEDIUM — Форма консультации: вводит в заблуждение и согласие не по ч. 4 ст. 9 152-ФЗ
- Место: `components/ConsultForm.tsx:1-14` (`onSubmit={(e) => e.preventDefault()}`, чекбокс `строка 9` — голый текст без ссылки), используется в `app/page.tsx:112`, `app/contacts/page.tsx:28`.
- Проверка: инспекция + живой рендер `/` (форма есть, обработчик только `preventDefault`). Кнопка «Отправить» ничего не отправляет и ничего не сообщает — пользователь думает, что вопрос ушёл юристу, а данные молча теряются (в `CONTEXT.md:62` упомянута mailto-заглушка, но в коде её нет). Текст согласия не содержит требуемых ч. 4 ст. 9 152-ФЗ элементов: наименование оператора, цель, перечень данных, срок. Смягчает то, что данные никуда не уходят (минимизация соблюдена по факту), но форма обещает услугу.
- Фикс: либо убрать форму до появления бэкенда (оставить телефон/email/часы), либо честно подписать «демо, никуда не отправляется» + `mailto:`; добавить под чекбоксом ссылку на `/docs/politika.pdf` и полный текст согласия (оператор — Союз ХКООП, цель — обратная связь, состав — имя+контакт+вопрос, срок), состояния success/error, `maxLength` полям.

### 6. MEDIUM — Нет защитных заголовков; сайт можно встроить в чужой iframe (кликджекинг)
- Место: `next.config.js:1-27` (нет секции `headers`), живой ответ `/`.
- Проверка: `GET /` → заголовки только `Vary/Cache-Control/Content-Type`, нет `Content-Security-Policy`, `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Strict-Transport-Security`. `X-Powered-By` отсутствует — хорошо. Учесть: прод — статический экспорт, где `headers()` из конфига игнорируются.
- Фикс: для dev/SSR добавить `headers()` (DENY/SAMEORIGIN, `nosniff`, минимальная CSP, `Referrer-Policy`), для GitHub Pages — эквивалент через `<meta http-equiv>` и/или Cloudflare-правила; проверить, что `yandex.ru/map-widget` при allowlist-iframe не ломается.

### 7. LOW — `safeHref` покрывает `href`/`iframe`, но не `img src` из БД: `honor.photo`, `partners.logo`
- Место: `app/honor/page.tsx:14` (`<img src={h.photo}>`), `components/PartnersStrip.tsx:11` (`<img src={p.logo}>`) — ср. `components/PartnersStrip.tsx:21`, где `href` фильтруется.
- Проверка: инспекция. React экранирует атрибуты (разрыв в `onerror="..."` невозможен), а `javascript:` в `img src` современные браузеры не исполняют — поэтому только LOW. Риск остаточный: мусорные/внешние `src` (трекинг-пиксель, тяжёлые URL) от привилегированного редактора БД.
- Фикс: пропускать `h.photo` и `p.logo` через `safeHref` (разрешить site-relative + `https:`), при `null` — плейсхолдер как сейчас при `err`.

### 8. LOW — `NEXT_PUBLIC_YM_ID` интерполируется в inline-скрипт без проверки формата
- Место: `app/layout.tsx:15,29` (`` ym(${ym},"init",...) `` внутри `dangerouslySetInnerHTML`).
- Проверка: инспекция. Переменная серверная, не пользовательская, — XSS только при компрометации окружения, поэтому LOW. Но это единственный `dangerouslySetInnerHTML` с переменной.
- Фикс: перед вставкой проверять `/^\d{4,10}$/`, иначе скрипт не рендерить; значение прогонять через `String(Number(...))`.

### 9. LOW — В импринте нет ОГРН/ИНН (ст. 10 149-ФЗ соблюдена частично)
- Место: `components/Header.tsx:52-54`, `components/Footer.tsx:6-11`, `app/contacts/page.tsx:18-20` — адрес, телефон, email, часы есть.
- Проверка: инспекция + рендер `/contacts`. Обязательный минимум владельца сайта (наименование, адрес, email — ст. 10 149-ФЗ) присутствует. Для НКО-профсоюза следующим шагом уместны ОГРН/ИНН из ЕГРЮЛ.
- Фикс: добавить строкой в футер и на `/contacts` ОГРН, ИНН, полное наименование оператора ПДн (оно же нужно находке 5).

### 10. LOW — Версия для слабовидящих работает, но настройки шрифта/картинок не сохраняются
- Место: `components/ViProvider.tsx:6-33`, стили `app/globals.css:206-212`, кнопка `components/Header.tsx:55-57`.
- Проверка: инспекция + рендер (кнопка в шапке, `skip`-ссылка `app/layout.tsx:20`, CSS-классы `vi-mode/vi-big/vi-noimg` на месте — ГОСТ Р 52872-2019 по крупному шрифту, контрасту, отключению картинок закрыт). Зазор: `lsSet` сохраняет только вкл/выкл (`hkoop-vi`), а `big`/`noimg` живут в состоянии и слетают при перезагрузке.
- Фикс: сохранять `big`/`noimg` в `localStorage`, восстанавливать в том же `useEffect`, что и `vi`.

### 11. LOW (информационные, без отдельных мест)
- Поля формы без `maxLength` (`ConsultForm.tsx:5-7`) — сейчас безопасно (нет бэкенда), при появлении бэкенда нужны лимиты и серверная валидация.

- Партнёрские ссылки — информационные (органы власти, ФНПР, вузы), признаков немаркированной рекламы нет; `rel="noreferrer"` корректен. Логотипы/фото третьих лиц используются информационно со ссылкой на правообладателя — желательно зафиксировать письменные разрешения, норма — ст. 1274 ГК РФ и право на товарный знак.
