Аудит по рабочему дереву (`backup-2026-10-10`, как есть, проект не менялся; БД — только чтение кода/сидов и безопасные GET к http://localhost:3100 и http://127.0.0.1:8081; секреты не печатаются — только имена ключей `DB_HOST/DB_PORT/DB_USER/DB_PASS/DB_NAME`). Прочитаны `CONTEXT.md`, `AGENTS.md` и ключевые файлы из задачи. Прод — статический экспорт (`output: export`, `next.config.js:6-7`) на GitHub Pages; серверные поведения проверялись на dev `http://localhost:3100`.

## Находки (по убыванию severity)

### N1. HIGH — Пароли к БД открытым текстом в рабочем дереве, файл не покрыт .gitignore
- **Место:** `db/README.md:8-12,20-23`; `.gitignore:1-8`.
- **Проверка (инспекция):** цитата README: `## Доступы (только локально, не коммитить никуда)` — `root / ...` — `hkoop / ... (все права на базу hkoop)`, далее `mysql -u hkoop -p'...' hkoop < db/schema.sql`. `.gitignore` покрывает `node_modules/ .next/ .next-export/ .env .env.local *.log db/phpmyadmin/ out/` — `db/README.md` не покрыт. История git не проверялась (задача запрещает трогать git), поэтому факт ухода секретов из машины НЕ установлен — пометка «не коммитить» держится только на дисциплине.
- **Факт:** credentials полного доступа лежат в файле рабочего дерева; один случайный коммит/копия — и они уйдут вместе с историей. Тяжелее текущего `.env.local` по HTTP (тот отдаёт 404: `curl.exe -s -o NUL -w "%{http_code}" http://localhost:3100/.env.local` → `404`).
- **Фикс (без применения):** убрать пароли из `db/README.md` (оставить `mysql -u hkoop -p hkoop < db/schema.sql` с интерактивным вводом), добавить `db/README.md` в `.gitignore` или перенести доступы в локальный gitignored-файл; сменить (rotate) оба пароля; историю переписывать (`filter-repo` + force-push) ТОЛЬКО после read-only проверки, что файл действительно коммитился/пушился, иначе ограничиться сменой и gitignore.

### N5. MEDIUM — Iframe-превью документов принимает произвольный https (фишинг от имени сайта)
- **Место:** `components/DocsFilter.tsx:42,50-56` + `lib/url.ts:3-9`.
- **Проверка (инспекция):** цитата: `{safeHref(d.file_local) && <button ... onClick={() => setPreview(safeHref(d.file_local)!)}>Смотреть</button>}` → `{preview && (... <strong>Просмотр PDF</strong> ... <iframe src={preview} ... />)}`. `safeHref` проверяет только схему (`https?://` или `/[^/\\]`), домен не проверяет. Контрпример: `file_local=https://evil.example/phish.html` проходит фильтр и рендерится в iframe внутри доверенного chrome страницы с заголовком «Просмотр PDF». `javascript:`/`data:` режутся (хорошо), но это не спасает от https-фишинга.
- **Фикс:** allowlist префикса: принимать в iframe только site-relative `/docs/*.pdf` (плюс явно перечисленные домены при нужде), всё остальное — только ссылкой с пометкой внешнего ресурса, не iframe.

### N6. MEDIUM — Два сырых `src` из БД без safeHref: логотипы партнёров и фото книги почёта (трекинг-пиксель)
- **Место:** `components/PartnersStrip.tsx:11` — `<img src={p.logo} ... onError={...}>` (сырой; `safeHref` на строке 21 покрывает только `href`, не `src`); `app/honor/page.tsx:14` — `{h.photo ? <img src={h.photo} ... /> : ...}`.
- **Проверка (инспекция):** `safeHref` (`lib/url.ts:3-9`) режет `javascript:`/`data:` и длинные строки, но на оба `src` не вызывается. По сидам текущие значения — `/images/*` (чисто: `db/seed.sql:13-25` логотипы `/images/...`, `:26-32` фото `/images/honor/...`). Современные браузеры не исполняют `javascript:` в `<img>`, React экранирует разрыв атрибута — сегодня это не рабочий XSS, а privacy-дыра: строка с `logo=https://evil-tracker/1px.gif` отдаёт IP/Referer/User-Agent третьему лицу без согласия, а при будущих изменениях — мина.
- **Фикс:** `const src = safeHref(p.logo)` / `safeHref(h.photo)` с fallback-плейсхолдером (как уже сделано для битой картинки через `onError`), плюс allowlist доменов картинок при желании.

### N7. MEDIUM — Нет заголовков безопасности и CSP
- **Место:** `next.config.js` (нет секции `headers()`), `app/layout.tsx` (нет meta CSP).
- **Проверка (живая проба):** `curl.exe -sI http://localhost:3100/` → `HTTP/1.1 200 OK`, `Vary`, `Cache-Control: no-store, must-revalidate`, `Content-Type: text/html; charset=utf-8` — нет `Content-Security-Policy`, `X-Frame-Options`/`frame-ancestors`, `X-Content-Type-Options`, `Referrer-Policy`, `Strict-Transport-Security`, `Permissions-Policy`, нет `X-Powered-By` (хорошо, `poweredByHeader: false` в `next.config.js:5`).
- **Факт:** сайт встраиваем в чужой iframe (кликджекинг формы), MIME-sniffing не запрещён, сторонние загрузки не ограничены.
- **Фикс (с учётом статики и инлайн-скриптов):** сайт держит два инлайн-скрипта (`app/layout.tsx:19` `document.documentElement.classList.add('js')`, `:29` загрузчик Метрики), поэтому `script-src 'self'` без `'unsafe-inline'` их заблокирует — корректный CSP обязан разрешить инлайн (например `script-src 'self' 'unsafe-inline' https://mc.yandex.ru; style-src 'self' 'unsafe-inline'; img-src 'self' data: https:; frame-src https://yandex.ru; object-src 'none'`, либо nonce/sha256-хэши вместо `'unsafe-inline'`). `headers()` Next при `output: export` на GitHub Pages игнорируется и `<meta http-equiv>` НЕ задаёт `frame-ancestors`/`X-Frame-Options`/`nosniff`/`HSTS` (браузерами игнорируется), поэтому заголовки выставлять на уровне хостинга (GitHub Pages их не даёт — прод на хостинг с заголовками либо за reverse-proxy/CDN: `frame-ancestors 'self'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy`, `HSTS`); `<meta http-equiv="Content-Security-Policy">` и JS frame-busting — только слабый второй рубеж (frame-busting обходится `sandbox="allow-scripts"` во вражеском iframe, защитой от кликджекинга не считать); проверить, что Метрика/карта не ломаются.

Вывод: продвижение товаров на рынке отсутствует — это справочно-навигационный блок, маркировка не требуется. НПА для пункта: ст. 3, ст. 18.1 38-ФЗ.
- **Авторские права: оценка по открытым данным — нарушений не выявлено, нужна документальная доводка.** Проверено: 13 логотипов (`db/seed.sql:13-25`, файлы `/images/...`, ссылки на официальные сайты правообладателей выше) и 7 фото книги почёта (`db/seed.sql:26-32`, файлы `/images/honor/...`, ФИО + «Профиль перенесён со старого сайта»). Характер использования — некоммерческий информационный (партнёрский справочник + портреты награждённых своей же организацией), объём — превью-уменьшенные изображения со ссылкой на источник. Условия ст. 1274 ГК РФ (информационная цель, оправданный объём, указание автора/источника): источник указан именем партнёра и ссылкой на его официальный сайт, но явное указание автора фото/правообладателя логотипа в разметке отсутствует. Открытых споров/претензий по этим материалам в проверяемом дереве нет. НПА: ст. 1229, 1259, 1274 ГК РФ. Фикс: хранить письменные разрешения/соглашения по каждому логотипу и согласия на публикацию фото (152-ФЗ ст. 9 + ст. 152.1 ГК РФ для изображений граждан), добавить подписи «Логотип: © <правообладатель>» и alt/подписи авторов фото.
- **phpMyAdmin:** только с логином (проба выше: `loginform`, `logged_in:false`).

## Замечания вне ранжирования (не находки безопасности)

- `rel="noreferrer"` без явного `noopener` (`PartnersStrip.tsx:29`, `DocsFilter.tsx:43`): по спецификации `noreferrer` подразумевает `noopener`; явный `rel="noopener noreferrer"` — гигиена для старых движков, правится одной строкой.
- `generateStaticParams` (`app/news/[id]/page.tsx:11-14`): `id` из БД может быть числом при типе params `string` — строгий `String(n.id)` уберёт warning сборки, на безопасность не влияет.
- Публичный `search-index.json`/`data/*.json` отдают контент поиску by design — не класть туда ничего, кроме заголовков/отрывков.
