# Аудит сайта ХКООП: безопасность и соответствие законам РФ (включая 152-ФЗ)

## Для кого этот отчёт и как им пользоваться

Вы — руководитель или пресс-секретарь ХКООП, не обязательно программист. Сначала короткий итог, затем ranked-список находок от самой опасной к мелким. Каждая находка содержит severity, место (файл:строка или URL), проверку (команда живого probe с выводом либо цитата кода) и предлагаемый фикс (описан, не применён — проект не менялся). В конце — чек-лист приёмки из 10 пунктов и вердикт. Проверка велась по рабочему дереву ветки `backup-2026-10-10` как есть, только чтением кода и безопасными GET-запросами к `http://localhost:3100` и `http://127.0.0.1:8081`; секреты не печатаются.

## Короткий итог для занятых

1. Каркас держится: SQL параметризован, отражённый XSS экранируется (живой probe подтверждает), `.env.local` отдаёт 404, `X-Powered-By` отсутствует, API-роутов нет (подтверждено glob-поиском, а не одним probe), phpMyAdmin за логином, хранимые тексты книги почёта экранируются React.
2. Показывать сайт людям рано: три барьера — стареющая версия Next.js, пароли БД в двух файлах репозитория и загрузка Яндекс.Метрики без привязки к согласию (152-ФЗ).
3. Порядок действий: обновить Next.js → убрать пароли из обоих файлов и сменить их → привязать Метрику к кнопке «Принять» → закрыть остальное по чек-листу.

## Что уже исправлено и держится (как новое не засчитывается, перепроверено)

- SQL-инъекции: все `q()` — статические `SELECT` без конкатенации; параметр только в `app/news/[id]/page.tsx:17` (`WHERE id=?`, `[params.id]`). Пробы `…/news/1' OR '1'='1` и `..%2F..` вернули «Не найдено» без дампа — файлового доступа по `id` нет.
- Отражённый XSS: живой probe `GET /search?q=<img src=x onerror=…>` возвращает экранированное значение в `value="&lt;img src=x onerror=alert(1)&gt;"` (серверный HTML dev-режима рендерит `defaultValue={sp.get("q")}` из `app/search/page.tsx:34`, React экранирует по построению); сырого исполняемого HTML нет. `dangerouslySetInnerHTML` с пользовательскими данными нет — только статика `app/layout.tsx:19` (класс `js`) и код Метрики.
- `lib/url.ts:3-9` (`safeHref`): allowlist `https?://` и site-relative, `javascript:`/`data:`/`//evil` режутся; применяется к партнёрским ссылкам, файлам документов, соцсетям (`PartnersStrip.tsx:21`, `DocsFilter.tsx:42-43`, `app/contacts/page.tsx:9-11`).
- `poweredByHeader: false` (`next.config.js:5`): заголовка `X-Powered-By` нет (П6). `.env`/`.env.local` в `.gitignore` есть, по HTTP — 404. API-роутов нет: каталог `app/api/` отсутствует, файлов `route.ts` нет, поиска `POST|PUT|DELETE` в `app/` совпадений по мутациям не даёт; `/api/test` — 404. phpMyAdmin требует логин (П9).

## Находки (ranked)

### 1. HIGH — Next.js 14.2.5 с известными уязвимостями; применимость главного CVE ограничена, но обновление нужно

- Место: `package.json:12` (`"next": "14.2.5"`).
- Проверка (инспекция; вывод сканера не снимался — допущение): версия зафиксирована жёстко, без патч-диапазона, стареет с июля 2024 года. По открытым бюллетеням ветка 14.2.x ниже 14.2.25 флагуется сканерами (Dependabot/`npm audit`/Snyk) по CVE-2025-29927 (обход авторизации через `x-middleware-subrequest`, CVSS 9.1, исправлено в 14.2.25), CVE-2024-39328 (отравление кеша), CVE-2024-46982. Уточнение применимости: в проекте нет `middleware.ts` (проверено поиском по корню — совпадают только чужие skill-файлы в `.agents/`), поэтому именно обход middleware эксплуатировать негде; прод — статический экспорт, где Next не исполняется. Остаточный риск реален: dev-сервер на 3100 и сборка работают на уязвимом коде, отчёт сканера с CRITICAL будет резать глаз проверяющему, часть старых CVE касается кеша/рантайма независимо от middleware.
- Факт: прод-статика смягчает, но не снимает требование гигиены зависимостей.
- Фикс: обновить `next` минимум до последнего патча 14.2.x (14.2.25+, лучше самый свежий), затем `npx tsc --noEmit`, `STATIC_EXPORT=1 npm run build`, smoke-тест страниц; держать `npm audit` в предполётном чек-листе. Самопроверка: `npm audit` должен быть без CRITICAL.

### 2. HIGH — Пароли от БД лежат в двух файлах репозитория открытым текстом

- Место: `db/README.md:10-11` (две строки вида `root / …` и `hkoop / …`, плюс `db/README.md:20,22` с подстановкой пароля в командную строку) и `docs/ИНСТРУКЦИЯ-ПРЕСС-СЛУЖБЕ.md:28` (`mysqldump -u hkoop -p'…' hkoop > backup.sql`); оба файла отслеживаются git, `.gitignore` (8 строк) их не покрывает; `db/README.md:12` декларирует «все права на базу hkoop».
- Проверка (инспекция, секреты не цитируются): `git ls-files` возвращает `db/README.md`; чтение обоих файлов показывает секрет в открытом виде. Любой получатель репозитория получает ключи от базы; удаление только одного файла секрет не уберёт.
- Факт: хардкода в коде нет (`lib/db.ts:3-11` берёт всё из окружения — хорошо), но секреты всё равно в дереве и истории git, что сводит защиту на нет.
- Фикс: `git rm --cached` для обоих файлов, добавить оба в `.gitignore`, вычистить секрет из истории (`git filter-repo`/BFG, скоординировать с ветками), **сменить оба пароля** везде, перевыпустить `.env.local`; в репо оставить только `db/README.example.md` и инструкцию с плейсхолдерами вместо паролей.

### 3. HIGH — Яндекс.Метрика подключается без привязки к согласию (риск нарушения 152-ФЗ)

- Место: `app/layout.tsx:27-31` (`{ym && (… mc.yandex.ru/metrika/tag.js …)}`), `components/CookieBanner.tsx:1-27`.
- Проверка (инспекция + живой probe): условие показа — лишь наличие `NEXT_PUBLIC_YM_ID`, флага `hkoop-cookie` в условии нет. Баннер только пишет `lsSet("hkoop-cookie","1")` и прячется. Живой probe главной локально пуст по `metrika` только потому, что переменная не задана; как только счётчик зададут (запланирован — `CONTEXT.md:65`), трекинг включится у всех, включая не нажимавших «Принять».
- Факт: cookie и данные Метрики при идентифицируемости — персональные данные; передача третьему лицу до согласия нарушает ч. 1 ст. 6, ст. 9 152-ФЗ и разъяснения Роскомнадзора о cookie.
- Фикс: грузить скрипт только если `lsGet("hkoop-cookie")==="1"` (клиентская обёртка, серверный `ym &&` заменить на монтирование по согласию); добавить кнопку «Отклонить»; в политике описать состав cookie, срок и порядок отзыва согласия.

### 5. MEDIUM — Локализация персональных данных не подтверждена: БД локальна, а прод-статика и бэкапы — под вопросом

- Место: `lib/db.ts:4` (`127.0.0.1:3306`, база `hkoop`), `next.config.js:6-7` (`output: export` для прода), `db/README.md` (инструкция по дампам), URL прода — статика на GitHub Pages.
- Проверка (инспекция кода): `lib/db.ts:4` — хост `127.0.0.1`, то есть первичная БД в РФ — хорошо; `next.config.js:6-7` — прод собирается статикой; пока форма с `preventDefault` ничего не отправляет и серверного поиска нет, трансграничной передачи ПДн из статики нет (подтверждено кодом `ConsultForm.tsx:4`). Допущение (помечено, не факт): серверы GitHub Pages находятся за пределами РФ — устанавливается по документации хостинга, живых замеров маршрутов не делалось; включение Метрики без согласия (находка 3) создаст передачу третьему лицу; места хранения бэкапов опросом администратора не зафиксированы.

- Фикс: зафиксировать регламент — первичные ПДн (обращения, согласия, логи) только в РФ (локальная БД/российский хостинг), бэкапы только в РФ с шифрованием; на Pages держать только публичную статику без ПДн; перед включением Метрики/бэкенда формы — обновить политику разделом о локализации и трансграничной передаче; опросить администратора о местах бэкапов и записать итог.

### 6. MEDIUM — Нет охранных заголовков: сайт можно встроить в чужой iframe (кликджекинг); meta frame-ancestors не годится

- Место: URL `http://localhost:3100/` (конфигурация — `next.config.js`, секции `headers` нет вовсе).
- Проверка (живой probe): `curl.exe -sS -D - -o NUL http://localhost:3100/` возвращает только `Vary`, `Cache-Control: no-store, must-revalidate`, `Content-Type`; `Content-Security-Policy`, `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Strict-Transport-Security` отсутствуют все пять.
- Факт: без `frame-ancestors`/`X-Frame-Options` страницу «Бесплатная консультация» можно встроить невидимым фреймом (кликджекинг); без `nosniff` старые браузеры могут сниффить MIME у PDF. Исправление к прежней рекомендации: директива `frame-ancestors` игнорируется браузерами в `<meta http-equiv>` (работает только в HTTP-заголовке), поэтому meta с `frame-ancestors` уязвимость не закроет; при `output: export` (`next.config.js:6-7`) Next игнорирует и `async headers()`. HSTS отдельно выставлять не нужно — Pages уже отдаёт HTTPS (его HSTS наследуется от хостинга).
- Фикс: выставлять заголовки на уровне раздачи, а не meta: `Content-Security-Policy: frame-ancestors 'self'` (плюс при желании `X-Frame-Options: SAMEORIGIN`, `X-Content-Type-Options: nosniff`, `Referrer-Policy`) через reverse-proxy/CDN перед Pages либо переезд на хостинг с кастомными заголовками; defense-in-depth в коде — JS-защита от фрейма (frame-busting) и скрытие формы вне топ-окна; в `<meta>` допустимы только `Referrer-Policy` (`<meta name="referrer" …>`) и CSP-директивы кроме `frame-ancestors`/`report-uri`/`sandbox`; остаточный риск без серверных заголовков зафиксировать в документации.

### 7. MEDIUM — Форма «бесплатной консультации» вводит в заблуждение + чекбокс без ссылки на политику

- Место: `components/ConsultForm.tsx:1-14`, используется в `app/page.tsx:112` и `app/contacts/page.tsx:28`.
- Проверка (инспекция + живой HTML): `onSubmit={(e) => e.preventDefault()}` — данных никуда не уходит (в компоненте нет `fetch`/`mailto:`/`action`); кнопка «Отправить» при этом обещает отправку, поля без `maxLength`/`required`. Текст чекбокса (`ConsultForm.tsx:9`) — «Даю согласие…» без ссылки; баннер (`CookieBanner.tsx:15`) ссылается на `/docs`, а не на `/docs/politika.pdf`. НПА: ст. 9 152-ФЗ (согласие информированное — со ссылкой на документ), ч. 2 ст. 18.1 152-ФЗ (доступ к политике).
- Факт: минимизация соблюдена (ничего не уходит — плюс), но посетитель ждёт ответа и не получит его — вводящий в заблуждение UX и reputational-риск с поводом для жалобы. Странные вводы серверу не вредят (бэкенда нет), что подтверждено кодом.
- Фикс: в label — ссылку «…с политикой конфиденциальности» (`/docs/politika.pdf`); под формой — строку «Форма пока не отправляет данные — звоните 8 (4212) 32-87-18»; полям `maxLength` (имя 100, контакт 100, вопрос 2000) и `required`; стратегически — либо бэкенд с хранением согласий, либо явный `mailto:`/телефон.

### 8. MEDIUM — PDF-превью в iframe без sandbox: чужой URL из БД откроется в дизайне сайта

### 9. MEDIUM — Правовое основание публикации книги почёта не видно на сайте: требуется орг-проверка, а не вывод о нарушении

- Место: URL `http://localhost:3100/honor`, `app/honor/page.tsx:4-27` (рендер 7 карточек с `{h.fio}`, `{h.title || h.text}`, `{h.photo}`), таблица `honor` (`db/schema.sql:29-36`: `fio`, `photo`, `text`).

Доступность `politika.pdf` — 200, но его текст юридически не экспертизировался (допущение). ### 10. LOW — Внешние ссылки с `target="_blank"` без `noopener`; кириллический IDN у партнёра

- Место: `components/PartnersStrip.tsx:29`, `components/DocsFilter.tsx:43`, `app/page.tsx:95` — везде `rel="noreferrer"` без `noopener`; данные: `https://хабаровсккурорт.рф/`.

### 11. LOW — Мягкий 404, нет `robots.txt`/sitemap; поля ввода без лимитов (поведением проверено — серверу не вредит)

То есть отсутствие `maxLength` подтверждено инспекцией, но поведением вреда нет — нагрузка только на сам браузер.
