# Аудит сайта ХКООП: безопасность и соответствие законам РФ (включая 152-ФЗ)

Дата: 10.10.2026. Объект: рабочее дерево `hkoop-site` на ветке `backup-2026-10-10` (проект не менялся: только чтение кода и безопасные GET к `http://localhost:3100` и `http://127.0.0.1:8081`). Стек: Next.js 14.2.5 App Router + React 18 + TypeScript, mysql2, MariaDB `hkoop`, dev-сервер на :3100, прод — статический экспорт (`output: export` при `STATIC_EXPORT=1`) на GitHub Pages.

Допущения: секреты не печатаются и не цитируются; БД не менялась (запись запрещена; чтение — только код, `db/README.md`, живые GET); текст `public/docs/politika.pdf` машинно не извлекался (ридер вернул пусто), проверены доступность (`200 application/pdf`) и места ссылок — содержательные заявления политики считаются неподтверждёнными и как нарушение не заявляются; версии CVE сверены с публичными бюллетенями Next.js.

## Проверено и держится (уже исправленное — как новое не засчитывается)

- SQL-запросы параметризованы: `app/news/[id]/page.tsx:17` — `WHERE id=?` с `[params.id]`; остальные `q()` — статические SELECT без конкатенации ввода.
- `lib/url.ts:3-8` — `safeHref` режет `javascript:`, `data:`, `//evil`; применяется к href/iframe из БД в `app/page.tsx:37`, `app/contacts/page.tsx:9-11`, `components/DocsFilter.tsx:42-43`, `components/PartnersStrip.tsx:21`.
- `next.config.js:5` — `poweredByHeader: false`; probe `curl.exe -sI http://localhost:3100/` не показывает `X-Powered-By` (только `Vary`, `Cache-Control: no-store, must-revalidate`, `Content-Type`, `Date`).
- `.env.local` по HTTP отдаёт 404: `curl.exe -s -o NUL -w "%{http_code}" http://localhost:3100/.env.local` → `404`.
- Отражённый XSS не воспроизводится: `curl.exe -s "http://localhost:3100/search?q=%3Cscript%3Ealert(1)%3C/script%3E"` → `value="&lt;script&gt;alert(1)&lt;/script&gt;"`, в RSC-потоке `searchParams":{"q":"\u003cscript\u003e...` — React экранирует.
- Хранимые тексты из БД рендерятся JSX-текстом и экранируются: `app/honor/page.tsx:18-19` (`{h.fio}`, `{h.title || h.text}`), `app/page.tsx:57-58` (`{n.title}`, `{n.excerpt}`), `components/PartnersStrip.tsx:12` (`{p.name}`). Поиск по дереву даёт только два `dangerouslySetInnerHTML`, оба без данных БД: `app/layout.tsx:19` (статичный `classList.add('js')`) и `app/layout.tsx:29` (инициализация Метрики по env). Хранимого XSS через тексты при текущем коде нет.
- Ошибки стек не светят: `curl.exe -s http://localhost:3100/news/no-such-id-xyz123` → `<h1>Не найдено</h1>` (`app/news/[id]/page.tsx:19`), без трассировки. Инъекции путей (`/news/..%2f..%2fetc%2fpasswd`) нормализуются в «Не найдено», раскрытия нет.
- API-роутов/мутаций нет: `route.ts`/`middleware` в `app/` отсутствуют; `components/ConsultForm.tsx:4` — только `e.preventDefault()`, сеть ничего не отправляет (минимизация данных подтверждена).
- phpMyAdmin отвечает `200` страницей входа (закрыт логином).
- Ссылки на соцсети в `components/Footer.tsx:21-23` — голые `<a href="https://vk.com/...">`, `<a href="https://t.me/...">`, `<a href="https://max.ru/...">` без `<img>`, скриптов и prefetch: до клика запросов к VK/Telegram/MAX нет, претензий к ним нет.

## Проверено, нарушений нет (не находки)

- Партнёрские ссылки и логотипы: обычные информационные ссылки (ФНПР, край, фонды, вузы) в `components/PartnersStrip.tsx:29` (`target="_blank" rel="noreferrer"`) и `app/partners/page.tsx:9` — без `utm`/рекламных текстов/вознаграждения, маркировка по 38-ФЗ не требуется (ст. 2, 16 «О рекламе»); логотипы — информационное использование НКО со ссылкой на правообладателя (ст. 1274 ГК РФ). Это констатация отсутствия проблемы, а не находка: severity не присваивается, фикс не требуется; при появлении платных размещений — пометка «Реклама» + erid.

## Ranked-список находок (новое)

### F1. CRITICAL — Пароли БД открытым текстом в git-трекаемом файле
- Место: `db/README.md:8-12` (+ `.gitignore:1-8`).
- Проверка (инспекция, без цитирования секретов): раздел «Доступы» содержит два пароля открытым текстом и командную строку с паролем. `git ls-files -- db/README.md` возвращает `db/README.md`; `git check-ignore -v .env.local db/README.md` игнорирует только `.env.local`; в `.gitignore` записи `db/README.md` нет. `.env`-покрытие (`.env`, `.env.local`) файл не спасает.
- Факт: любой пуш/публикация репозитория увозит пароли; ротация после удаления из истории обязательна. Пункт «уже исправлено» (убран хардкод в коде) этот файл не покрывает.
- Фикс: удалить секреты из файла (оставить `root / <см. локальный менеджер паролей>`), вычистить из истории (`git filter-repo`/`BFG`), ротировать оба пароля, вынести доступы в локальный vault; в CI добавить gitleaks/secretlint.

### F2. HIGH — Уязвимый Next.js 14.2.5
- Место: `package.json:12` (`"next": "14.2.5"`).
- Проверка (инспекция): пин старше патчей 14.2.25+/14.2.32. Публично: CVE-2024-39328 (SSRF/кэш-пойзонинг `/_next/image`), CVE-2025-55182/54794 (RSC Flight). Уточнение: CVE-2025-29927 (обход через `x-middleware-subrequest`, CVSS 9.1) здесь сейчас не эксплуатируется — `middleware.ts`/`route.ts` в `app/` отсутствуют, а `redirects` в `next.config.js:9-24` — это не middleware и уязвимой поверхности не создают; они не «унаследуют» эту дыру, риск появится только если/когда добавят middleware.
- Факт: рантайм уязвим по остальным CVE независимо от middleware.
- Фикс: обновить `next` минимум до `14.2.32` (лучше последний 14.x/15.x), обновить lockfile, `npx tsc --noEmit`, `STATIC_EXPORT=1 npm run build`, зафиксировать политику обновлений в 30 дней после security-релиза.

### F3. HIGH — Яндекс.Метрика включается без согласия
- Место: `app/layout.tsx:15,27-31` + `components/CookieBanner.tsx:1-27`.
- Проверка: условие вставки — только `ym = process.env.NEXT_PUBLIC_YM_ID`; флага согласия нет. Баннер лишь пишет `hkoop-cookie=1` и ни на что не влияет. В dev `ym` не задан (`curl.exe -s http://localhost:3100/ | findstr mc.yandex` пуст), но стоит задать `NEXT_PUBLIC_YM_ID` (`.env.example:6` предлагает) — трекинг включится у всех. Текст «Продолжая, вы соглашаетесь» — implied consent, не признаваемый согласием.
- НПА: ст. 9 152-ФЗ (согласие конкретное, предметное, информированное, сознательное, однозначное); п. 2 ч. 1 ст. 18.1 152-ФЗ (публикация политики и разъяснение); передача IP/cookie — обработка и поручение по ст. 6 152-ФЗ.
- Фикс: встраивать `tag.js`/`watch/` только после явного согласия (ключ `hkoop-ym=1`); в баннере кнопки «Принять»/«Отклонить» + ссылка на `/docs/politika.pdf`; в политике — цель, перечень, срок, отзыв.

### F4. MEDIUM — Нет заголовков безопасности; прод на статике заголовками не закрыть
- Место: URL `http://localhost:3100/` (весь сайт).
- Проверка: `curl.exe -sI http://localhost:3100/` → только `Vary`, `Cache-Control`, `Content-Type`, `Date`. Нет CSP, `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`.
- Факт и ограничение площадки: прод — статический экспорт на GitHub Pages (`next.config.js:2-7`): `async headers()` в dev имеет смысл, но в прод не эмитится; Pages не отдаёт кастомные заголовки; директива `frame-ancestors` в `<meta>` игнорируется по спецификации (только из заголовка) — кликджекинг заголовками на проде не закрыть.
- Фикс (без поломок и без противоречия с клик-ту-плей для карты): `async headers()` для dev/SSR (`X-Frame-Options: SAMEORIGIN`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`) + в `app/layout.tsx` meta-CSP без `frame-ancestors` и без разрешения Яндекса по умолчанию: `<meta httpEquiv="Content-Security-Policy" content="default-src 'self'; script-src 'self' 'unsafe-inline' https://mc.yandex.ru; img-src 'self' data: https:; frame-src 'self'; style-src 'self' 'unsafe-inline'">`. Разрешение `frame-src https://yandex.ru` и `script-src https://mc.yandex.ru` добавлять только после согласия (вместе с F3/F8): иначе CSP по умолчанию разрешит то, что F8 требует грузить только по клику. `'unsafe-inline'` оставлен сознательно, чтобы не сломать собственные инлайн-скрипты `app/layout.tsx:19` и `:29`; долгосрочно — заменить их на хеши и убрать `'unsafe-inline'`. Для кликджекинга на проде заголовков нет — добавить JS frame-buster как смягчение и зафиксировать в документации, что полного закрытия на Pages нет. HSTS — только после HTTPS в проде.

### F5. LOW — Документация фиксирует избыточные права mysql-пользователя; живые гранты не проверены

Оговорка: `SHOW GRANTS` не выполнялся, а `db/README.md:25` говорит, что «Сайт пока читает `data/*.json`» — какая учётка реально используется в проде и каковы живые гранты, не установлено. Поэтому это не доказанный факт компрометации («перезапись/удаление таблиц»), а гигиена документации и принципа наименьших привилегий.
- Фикс: при переходе на MySQL выдать `GRANT SELECT ON hkoop.*` (+ при нужде отдельные `INSERT/UPDATE` на конкретные таблицы после появления бэкенда), без `ALL`, `GRANT OPTION`, `FILE`, `SUPER`; проверить чтением `SHOW GRANTS FOR 'hkoop'@'...'`; хранить DDL-привилегии только у отдельного миграционного пользователя; убрать из README формулировку про полные права.

### F10. LOW — `src` картинок из БД без `safeHref`
