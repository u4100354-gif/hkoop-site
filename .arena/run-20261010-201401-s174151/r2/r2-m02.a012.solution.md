# Аудит сайта ХКООП: безопасность и соответствие законам РФ (включая 152-ФЗ)

## Вердикт коротко (один абзац)

Сайт устроен как киоск с закрытой витриной: SQL везде параметризован, ссылки из БД идут через allowlist, секреты по HTTP не отдаются, форма ничего никуда не отправляет — живые пробы это подтверждают (команды и выводы ниже). Но витрина стоит на скомпрометированном фундаменте: пароли БД лежат в `db/README.md` и уже закоммичены в историю git (коммит `d619937`), живая учётка имеет `ALL PRIVILEGES`, а Метрика и Яндекс-карта грузятся без согласия, хотя баннер обещает обратное. Плюс два честных белых пятна: текст политики — скан без текстового слоя (содержание не проверено), прод на статическом экспорте (раздача вне РФ) юридически не оценён. Это чинится за дни без переделки архитектуры — и только после этого сайт можно спокойно показывать людям.

Подход к проверке: все внешние данные (строка поиска `?q=`, сегмент `/news/<id>`, вообще всё, что приехало из БД через phpMyAdmin) считались потенциально враждебными: чистота подтверждается контрольной точкой на каждой границе. Каждая находка ниже — конкретная граница, где контрольной точки нет или она дырявая.

## Допущения

- Аудит по рабочему дереву ветки `backup-2026-10-10` как есть; проект, БД и git не менялись (только чтение кода, безопасные GET и read-only инспекции: `git ls-files/log/show`, `SHOW GRANTS`, `SELECT`-подобные пробы через HTTP).
- Живые пробы — только `curl.exe` GET к `http://localhost:3100` и `http://127.0.0.1:8081`. Секреты и хэши паролей не печатаю (значения заменены на `<redacted>`).
- Прод (GitHub Pages, статический экспорт) отдельно не щупался — выводы о нём только по `next.config.js` и документации Next.

## Находки (по убыванию важности)

### C1. CRITICAL — пароли БД в `db/README.md`, уже закоммичены в историю git

- **Место:** `db/README.md:10-11` (там же `:20,22` — пароль в командной строке).
- **Проверка (инспекция + read-only git):** файл содержит две пары «пользователь / пароль» (root и `hkoop`, пометка «все права на базу hkoop») и команду заливки дампа с паролем в командной строке. Значения не привожу. Read-only команды (ничего не меняют):
  `git ls-files -- db/README.md` → `db/README.md` (трекается);
  `git log --oneline -- db/README.md` → `d619937 hkoop site`;
  `git show HEAD:db/README.md | Select-String "mysql -u"` → строки с паролями есть в коммите (проверено с маскированием);
  `git ls-files -- .env.local` → пусто (не трекается), `git check-ignore -v .env.local` → `.gitignore:5:.env.local` (игнорируется).
- **Факт:** секрет не просто «рядом с кодом», а уже в истории: каждый клон несёт его с собой, смена пароля в рабочем дереве без зачистки истории не отзывает доступ. Рядом слушает сеть phpMyAdmin — `curl.exe -s -o NUL -w "%{http_code}" http://127.0.0.1:8081/` → `200`, тело содержит `<title>phpMyAdmin</title>` (вход с логином, анонимного доступа нет — но утекший пароль сразу превращается в доступ).
- **Фикс:** считать оба пароля скомпрометированными безусловно (без «если»): сменить оба; из `db/README.md` оставить только шаблон (`DB_PASS=...`) без значений; зачистить историю (BFG/filter-repo) либо пересоздать репозиторий без секрета и отозвать все клоны/форки; включить проверку секретов в pre-commit.

### M6. MEDIUM — нет защитных HTTP-заголовков; для прод-экспорта фикс только хостинговый

- **Место:** ответы `http://localhost:3100/` (конфиг — `next.config.js`, там только `poweredByHeader: false`; прод — `next.config.js:2,6-7`: `output: "export"` при `STATIC_EXPORT=1`).
- **Проверка (живой probe):** `curl.exe -sSI http://localhost:3100/` возвращает:
  ```
  HTTP/1.1 200 OK
  Cache-Control: no-store, must-revalidate
  Content-Type: text/html; charset=utf-8
  ```
  Нет `Content-Security-Policy`, `X-Frame-Options`/`frame-ancestors`, `Strict-Transport-Security`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`. Заголовка `X-Powered-By` нет (держится). Сайт встраиваемый: любой чужой сайт может открыть его в iframe (кликджекинг кнопки «Принять» или формы). Честное ограничение: `headers()` в `next.config.js` при статическом экспорте Next игнорирует, а `<meta http-equiv>` не умеет выставлять `X-Frame-Options`, `HSTS` и `frame-ancestors` — зашиться только кодом на GitHub Pages нельзя.
- **Фикс (применимый):** заголовки настраивать на уровне хостинга, а не Next. Вариант А (рекомендован): вынести прод за CDN/хостинг, умеющий в заголовки (Cloudflare Pages / Netlify с `_headers`, либо Cloudflare перед GitHub Pages), и задать там: `frame-ancestors 'self'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy` (минимум), базовый CSP (`default-src 'self'`, картинки/iframe по allowlist, `mc.yandex.ru` и `yandex.ru/map-widget` только после согласия). Вариант Б (частичная компенсация в коде, не замена): `<meta http-equiv>` для того, что meta умеет (CSP, Referrer-Policy) + frame-busting `if (top !== self) top.location = self.location`. Без переезда хостинга кликджекинг остаётся частично открытым — это остаточный риск.

### M7. MEDIUM — iframe предпросмотра PDF без `sandbox`, домен не ограничен (возможна top-навигация)

- **Место:** `components/DocsFilter.tsx:50-56` (источник — `DocsFilter.tsx:42`: `setPreview(safeHref(d.file_local)!)`).
- **Проверка (инспекция):** `safeHref` режет только схему, домен — любой `https://`. Запись `file_local=https://чужой-домен/фишинг.html` пройдёт фильтр и откроется в iframe внутри оформления сайта под заголовком «Просмотр PDF». Iframe без `sandbox` (текущий `DocsFilter.tsx:56`) top-навигацию умеет (`top.location=` или ссылки с `target=_top` из чужой страницы) — возможен увод всей вкладки на фишинговую страницу под видом доверенного сайта.
- **Фикс (точный):** `sandbox=""` (пустое: скрипты, формы и top-навигация запрещены; перед деплоем проверить предпросмотр легитимного `/docs/*.pdf`); плюс allowlist: site-relative `/docs/*.pdf` — всегда можно, внешний `https` — только из явного списка доверенных доменов; чужое — новой вкладкой (`target=_blank rel="noreferrer noopener"`), а не в iframe. Fallback, если пустой `sandbox` сломает просмотрщик: `sandbox="allow-same-origin"` без `allow-scripts` и без `allow-top-navigation`, с тем же allowlist.

### M8. MEDIUM — два `<img src>` из БД идут мимо `safeHref` (трекинг, подмена, битые картинки)

- **Место:** `app/honor/page.tsx:14` (`<img src={h.photo} ...>`), `components/PartnersStrip.tsx:11` (`<img src={p.logo} ...>`).
- **Проверка (инспекция):** фильтр `lib/url.ts:3-9` режет `javascript:`/`data:`/`//evil`, через него идут URL партнёров (`PartnersStrip.tsx:21`), файлы документов (`DocsFilter.tsx:42-43`), соцсети (`app/contacts/page.tsx:9-11`). Но `h.photo` и `p.logo` подставляются сырыми. Честно: `javascript:alert(1)` в `<img src>` в современных браузерах не исполняется (JS-URL в контексте `<img>` игнорируется, скрипт в SVG через `<img>` не выполняется) — это не хранимый XSS с исполнением JS. Реальный эффект компрометации этих полей — подмена картинки на чужой трекер (`https://evil/pixel`), битая картинка, подмена логотипа (фишинг доверия), перенос значения в исполняемый контекст при будущем рефакторинге.
- **Фикс:** пропустить `h.photo`/`p.logo` через тот же `safeHref` (site-relative + `https:`), при `null` — существующую заглушку; осмысленный `alt`, явные размеры, `referrerpolicy="no-referrer"`; на уровне БД — CHECK-ограничение формата (`/^(\/|https:\/\/)/`).

### M9. MEDIUM (право) — локализация и трансграничная передача не подтверждены; текст политики не проверен (ч. 5 ст. 18, ст. 12 152-ФЗ)

- **Место:** прод-хостинг (статический экспорт, `next.config.js:2,6-7`) + `public/docs/politika.pdf` + внешние запросы (Метрика, карта).
- **Проверка:** файл `politika.pdf` доступен (`200`, 3392427 байт), но это скан без текстового слоя: побайтовый разбор показывает `%PDF-1.4` с image-объектами (`/Subtype /Image`, `/Filter /DCTDecode`), извлекаемого текста нет — что там про хранение в РФ и трансграничную передачу, из байтов не следует. Хостинг продакшена по задаче — GitHub Pages (раздача вне РФ) — юридически не оценивался. Поэтому прежний вывод «нарушения не установлено» снят. Частично подтверждено: форма ничего никуда не отправляет (`ConsultForm` — `preventDefault`), БД локальная (`127.0.0.1:3306`, база `hkoop`), используемые внешние сервисы — Яндекс (юрлицо РФ). Но без чтения текста политики и без оценки хостинга соответствие ч. 5 ст. 18 и ст. 12 152-ФЗ недоказуемо.
- **Фикс:** распознать/вычитать текст политики вручную, зафиксировать в ней место хранения ПДн (РФ) и условия трансграничной передачи (ст. 12); оценить размещение продакшена с юристом (GitHub Pages = инфраструктура вне РФ: либо перенос/зеркалирование в РФ, либо явное основание и отражение в политике); после закрытия M1–M2 передача аналитических данных Яндексу будет легитимной по согласию.
