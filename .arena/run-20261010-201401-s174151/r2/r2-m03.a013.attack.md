ATTACK 1 [MAJOR] Предложенный CSP-meta ломает инлайн-скрипты сайта
Where: F8, фикс: `<meta http-equiv="Content-Security-Policy" content="default-src 'self'; script-src 'self' https://mc.yandex.ru; frame-src 'self' https://yandex.ru">` против `app/layout.tsx:19` (`<script dangerouslySetInnerHTML={{ __html: "document.documentElement.classList.add('js')" }} />`) и `app/layout.tsx:29` (инлайн-инит `ym(...)`)
Problem: оба скрипта инлайновые без nonce/hash. Под `script-src 'self'` без `'unsafe-inline'` браузер их заблокирует (контрпример: применить фикс как написан — пропадёт класс `js` и инициализация Метрики). Фикс в таком виде неприменим; нужен `'unsafe-inline'`/nonce/hash либо исключение инлайна.

ATTACK 2 [MAJOR] F5 — вывод об избыточных правах без факта из БД
Where: F5: "Живой вывод `SHOW GRANTS` в отчёте не приводится и фактом БД не считается — вывод о правах опирается только на декларацию README"
Problem: задача требует "права mysql-пользователя" проверять кодом И живыми пробами, а каждая находка — с "проверкой (инспекция кода или живой probe с командой и выводом)" и фактом. Здесь факта из БД нет: только строка README "все права" + SELECT-only код. Контрпример: если реальные гранты уже `SELECT`-only, находка ложна, а читатель не может это понять — действовать не на что.

ATTACK 3 [MAJOR] Пропущена требуемая оценка авторских прав по открытым данным
Where: F12: "разрешений партнёров, лицензий фото, оснований воспроизведения в репозитории/открытых данных не предъявлено — проверка по открытым данным не проводилась"
Problem: задача прямо требует: "Авторские права: логотипы партнёров, фото — использование правомерно (оценка по открытым данным)". Отчёт признаёт, что эту проверку не делал, но всё равно сдаёт раздел как находку. Требование не выполнено.

ATTACK 4 [MAJOR] F2 ранжирует HIGH при доказанном отсутствии утечки сейчас
Where: F2: "Живой probe `/` в dev счётчика не нашёл (`mc.yandex.ru` отсутствует — переменной нет), т.е. утечки сейчас нет, но первая же прод-сборка со счётчиком включит трекинг"
Problem: вменено нарушение ч. 1 ст. 9 152-ФЗ (обработка/передача Яндексу без согласия), хотя собственный probe доказывает: обработки нет — в HTML нет `mc.yandex.ru`, ничей IP/user-agent никуда не уходит. Гипотетическая будущая сборка с заданным `NEXT_PUBLIC_YM_ID` — не текущий факт; задача требует факт "с цитатой/выводом". HIGH и блокировка вердикта ("только после ... F2–F3") построены на будущем, а не на настоящем.

ATTACK 5 [MAJOR] F9 выводит нарушение из отсутствия согласий в репозитории, где их быть не должно
Where: F9: "документов согласия в репозитории нет (их там и не должно быть, но регламента нет тоже)"
Problem: отсутствие бумажных согласий в git ничего не доказывает — согласия оператора хранятся в офисе, никогда в коде. Нет ни цитаты избыточных ПДн из SELECT, ни проверки архива оператора, ни команды с выводом. Контрпример: публикация 7 персон с согласия в папке у оператора неотличима от нарушения по этому "доказательству", а ярлык ст. 10.1 (отдельное согласие + отзыв) вводит в заблуждение вплоть до снятия законного раздела.

ATTACK 6 [MINOR] Содержимое politika.pdf не проверено
Where: "Допущения": "Содержимое `public/docs/politika.pdf` по существу (полнота политики) ... не аудировались — проверены доступность, ссылка и факт логина"
Problem: задача требует проверить "политик[у] конфиденциальности (`public/docs/politika.pdf`, ссылка с формы и баннера)" в связке с 152-ФЗ (оператор, цели, состав). Проверен только HTTP 200 `application/pdf`, содержимое не открыто. Поэтому ссылки F3/F6/F10 на ст. 9/18 висят без знания того, что политика реально говорит.

ATTACK 7 [MINOR] Конкретные CVE-номера без подтверждения выданы за находку HIGH
Where: F4: "по публичным бюллетеням это включает ... CVE-2025-29927 ... CVE-2024-39328, CVE-2024-46982 — номера требуют подтверждения командой `npm audit` ... без сети ни подтвердить, ни опровергнуть их по этому тексту нельзя"
Problem: задача требует "Зависимости: `package.json` — известные CVE" с проверкой командой и выводом; вывода `npm audit` нет. Одновременно отчёт сам доказывает отсутствие middleware/API-роутов и статический прод-экспорт ("прямой эксплуатации сегодня почти наверняка нет"). Немаркированные как гипотеза ID в заголовке HIGH заставляют читателя перепроверять всё заново.
