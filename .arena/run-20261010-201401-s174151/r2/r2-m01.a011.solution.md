# Аудит сайта ХКООП: безопасность и соответствие законам РФ (включая 152-ФЗ)

## Кому этот отчёт и как его читать

Отчёт для двух людей: руководителя (решение «показывать ли сайт людям») и разработчика с пресс-службой (что чинить и в каком порядке). Находки отсортированы по тяжести: сверху то, что чинить первым. У каждой находки есть severity, точное место, проверка (цитата кода и/или команда с выводом — можно повторить), факт и предлагаемый фикс. Проект не менялся, в БД ничего не писалось, пакеты не ставились, секреты не печатаются. Русский язык.

## Вопросы эксперта перед работой и ответы

1. Кто пострадает при ошибке? Посетитель (трекинг, фишинг через ссылки из БД), организация (штраф по ст. 13.11 КоАП за 152-ФЗ, претензии по импринту ст. 10 149-ФЗ), пресс-служба (доступ к БД через репозиторий). Приоритет — цепочки «данные БД → браузер» и согласия.
2. Где граница «уже исправлено» vs «новое»? Список из задания перепроверяю пробами, а не на слово. Всё подтвердилось (раздел «Держится»); новым считаю только отсутствующее в списке.
3. Что исполняется в браузере? Серверные компоненты отдают HTML, клиентские (форма, поиск, фильтры, баннер) исполняют JS. Ищу `dangerouslySetInnerHTML` с переменными, нефильтрованные `src`/`href` из БД, сторонние запросы до согласия.
4. Кто фактически пишет HTML сайта? Владелец доступа к БД: почти весь контент из таблиц. Любое поле БД в `href`/`src`/`iframe` без фильтра — удалённое редактирование сайта. Так найдены главные зазоры (М1, М7).
5. Что уходит третьим лицам до согласия? Карта Яндекса безусловно, Метрика — при включении. Проверяется чтением кода и живого HTML.
6. Что видит неопытный пользователь? Форму, молча глотающую заявку, и баннер без отказа. Это тоже находки: они решают, будет ли жалоба и потеря обращений.

## Находки

### H1. HIGH — Next.js 14.2.5 с известными CVE

- **Место:** `package.json` (`"next": "14.2.5"`).
- **Проверка (инспекция):** зависимости — `next 14.2.5`, `react 18.3.1`, `mysql2 ^3.24.5`. Ветка 14.2.x младше 14.2.25 содержит CVE-2025-29927 (обход авторизации через заголовок `x-middleware-subrequest`, исправлено в 14.2.25) и CVE-2024-46982 (отравление кэша). `npm audit` не запускался (запрет менять проект).
- **Факт:** фреймворк с публичными эксплойтами; middleware сейчас нет, что снижает, но не снимает риск.
- **Фикс:** обновить `next` минимум до 14.2.33, `npx tsc --noEmit`, `STATIC_EXPORT=1 npm run build`; проверять `npm audit` ежемесячно.

### H2. HIGH — Пароли от БД открытым текстом в репозитории, избыточные права

- **Место:** `db/README.md:10` (строка root), `db/README.md:11` (`hkoop … (все права на базу hkoop)`).
- **Проверка (инспекция):** цитаты строк 10–11 — две пары логин/пароль внутри репозитория, значения не заглушки (сами значения не привожу). Живой `SHOW GRANTS` не выполнял: в песочнице нет `mysql`-клиента, а соединяться кодом с чтением `.env.local` означало бы трогать креды ради проверки; поэтому объём прав фиксирую как заявление README, а не как живой факт. Безопасная команда для владельца доступов (секреты не печатать, выполняет владелец локально): `SHOW GRANTS FOR 'hkoop'@'localhost';` — ожидаемый минимум для сайта `GRANT SELECT ON hkoop.*`.
- **Факт:** доступ к репозиторию = доступ к БД; право ALL избыточно сайту, которому нужен только SELECT.
- **Фикс:** сменить оба пароля; в README оставить шаблон без значений; сайту — только `GRANT SELECT ON hkoop.*`; проверить `git log -- db/README.md`, при утечке наружу считать пароли скомпрометированными.

### M6. MEDIUM — Нет заголовков безопасности; на статическом проде `headers()` не поможет

- **Место:** HTTP-ответ + `next.config.js` (прод — `output: export` на GitHub Pages).
- **Проверка:** `curl.exe -s -D - -o NUL http://localhost:3100/` → есть только `Vary`, `Cache-Control: no-store, must-revalidate`, `Content-Type`; нет `Content-Security-Policy`, `X-Frame-Options`, `Referrer-Policy`, `X-Content-Type-Options`. Поправка: `headers()` из `next.config.js` при статическом экспорте игнорируется, а CSP через `<meta http-equiv>` не поддерживает `frame-ancestors` — кликджекинг этим не закрыть.
- **Факт:** сайт встраивается в чужой iframe (кликджекинг на форме); без CSP нет страховки от инлайн-инъекции; без `Referrer-Policy` полный URL уходит внешним сайтам.
- **Фикс:** заголовки на уровне хостинга (GitHub Pages их не отдаёт — либо смена хостинга/CDN с заголовками, либо принять риск письменно); независимо: `<meta http-equiv>` для остатка CSP + `Referrer-Policy`, `sandbox` на iframe PDF (`DocsFilter.tsx:56`), `loading="lazy"`, frame-busting скрипт как компенсация, а не как замена заголовкам.
