# Аудит сайта ХКООП: безопасность и соответствие законам РФ (включая 152-ФЗ)

Дата: 10.10.2026. Объект: `hkoop-site`, ветка `backup-2026-10-10` (рабочее дерево как есть), Next.js 14.2.5 + React 18 + MariaDB `hkoop`. Живые пробы — только безопасные GET к `http://localhost:3100` и `http://127.0.0.1:8081`, плюс read-only `SHOW GRANTS` через локальное подключение (секреты нигде не печатаются). Проект не менялся.

## Допущения и границы

- Dev-сервер на `:3100` собран из того же дерева, что и прод-экспорт (разница только в `STATIC_EXPORT`), поэтому выводы по коду переносимы на прод.
- Поиск реализован парой `components/HeaderSearch.tsx` + `app/search/page.tsx`; проверены оба.
- `public/docs/politika.pdf` (3 392 427 байт) не имеет текстового слоя: чтение PDF возвращает пустой текст, маркеров `/Font` ноль — это скан-изображения. Бинарно доказана только сканированность; содержательная проверка выполняется визуально в просмотрщике (чек-лист — в F10), здесь OCR не применялся.
- Точная версия phpMyAdmin не аудировалась — проверены доступность и факт требования логина.
- CVE по `next` проверены 10.10.2026 через NVD API (запросы по идентификаторам, см. F5); полный `npm audit` остаётся командой перепроверки перед каждой сборкой.
- Вывод `SHOW GRANTS` снят живым подключением с учётными данными из `.env.local`; в отчёте приводится в обезличенном виде (имена/хосты БД — можно, секреты и хеши — нет).

- Длинный ввод: `?q=` из 2000 символов → 200, длина ответа штатная, страница рендерится («Ничего не найдено» / результаты), падений нет.
- API-роутов нет (`app/**/route.ts` — пусто), мутаций из клиента нет.
- phpMyAdmin `http://127.0.0.1:8081/` отвечает страницей входа (требует логин).
- Импринт есть: адрес, телефон, email и наименование союза — в `components/Footer.tsx:6-11` и на `/contacts` (живой probe подтверждает).

Версия для слабовидящих работает (переключатель в шапке, классы `vi-mode`/`vi-big`/`vi-noimg` в `app/globals.css:206-212`, skip-link в `app/layout.tsx:20`).

### F9. MEDIUM — Нет заголовков безопасности; на GitHub Pages кликджекинг заголовками неустраним

- **Место:** ответ `/` (живой probe): `Content-Security-Policy`, `X-Frame-Options`, `X-Content-Type-Options` — отсутствуют (все null); `Cache-Control: no-store, must-revalidate`.
- **Проверка:** живой probe заголовков `/` подтверждает отсутствие перечисленных заголовков.
- **Компромисс — честно:** «за»: без CSP/X-Frame-Options сайт можно встроить в чужой iframe (кликджекинг обёртки) и грузить что угодно откуда угодно. «Против»: GitHub Pages не отдаёт кастомные заголовки, а на сайте нет авторизации и денежных действий — ущерб от кликджекинга низкий. Синтез: MEDIUM. Отдельно честно: `frame-ancestors` через `<meta http-equiv>` не работает (браузеры игнорируют эту директиву в meta, она действует только в HTTP-заголовке), поэтому выдавать meta за замену заголовка от кликджекинга нельзя.
- **Фикс (не применять, исправленный):** голый `script-src 'self'` из прошлой редакции неприменим — он заблокирует оба инлайн-скрипта `app/layout.tsx:19` (класс `js`) и `app/layout.tsx:29` (init `ym`). Рабочий вариант: либо вынести оба скрипта во внешние файлы и тогда `<meta http-equiv="Content-Security-Policy" content="default-src 'self'; script-src 'self' https://mc.yandex.ru; img-src 'self' https://mc.yandex.ru data:; frame-src 'self' https://yandex.ru; object-src 'none'; base-uri 'self'">` (без `frame-ancestors` — его в meta не ставить), либо оставить инлайн только с хешами (`'sha256-…'` под каждое содержимое) или nonce; iframe карты — с минимальным `sandbox`. Полный набор заголовков (включая `frame-ancestors 'self'` / `X-Frame-Options`) — только при переезде на хостинг с настраиваемыми заголовками; до тех пор риск кликджекинга фиксировать как принимаемый (низкий ущерб: нет авторизации/платежей).

## Что прямо НЕ является проблемой (чтобы не чинили зря)

- Параметризация SQL — везде, включая `news/[id]`; «SQL-инъекция в `q()`» отсутствует как класс (живой probe подтверждает).
- Отражённый XSS через `?q=` и фильтры — экранируется React (два payload-probe с выводом подтверждают); `javascript:`/`data:` в href/iframe из БД режутся `safeHref`.
- Инъекции путей (`../`, `%2e%2e`) в `/news/<id>` — id идёт только параметром в SQL и никогда в файловую систему.
- Активной утечки в Яндекс.Метрику сейчас нет (счётчик не задан) — нарушения ст. 9 по этому пункту сейчас нет, есть латентный дефект под будущее включение (F4). Активная утечка есть только у карты (F2) — не путать.
- Тексты книги почёта сейчас — заглушки, а не биографии; отсутствие согласий в git — не доказательство нарушения (F12).
- CVE-2025-29927 затрагивает 14.2.5, но без middleware не эксплуатируется; CVE-2024-46982 и CVE-2025-32421 к App Router неприменимы (F5) — обновляться нужно, но не как на пожар.
- Партнёрские ссылки — информационные (ФНПР, правительство края, фонды, вузы, надзор), признаков скрытой рекламы нет; маркировка (erid) не требуется.
- Импринт по ст. 10 Закона № 149-ФЗ (наименование, адрес, телефон, email) — присутствует.
- Пустой `alt` новостных миниатюр (`app/page.tsx:52`) — корректный декоративный паттерн, а не дефект доступности.
