# Аудит сайта ХКООП: безопасность и соответствие законам РФ (включая 152-ФЗ)

## Допущения и метод

- Аудит по рабочему дереву на ветке `backup-2026-10-10` как есть; проект не менялся, БД — только чтением через рендер, секреты не печатаются.
- Живые пробы — только безопасные GET к `http://localhost:3100` (dev) и `http://127.0.0.1:8081` (phpMyAdmin). Инструмент — `curl.exe -s`, разбор поиском подстрок.
- `NEXT_PUBLIC_YM_ID` локально не задан (в HTML главной нет `mc.yandex.ru`) — поведение при заданном ID читается из кода.
- CVE сверяются по открытым бюллетеням ветки 14.2.x.

## Как устроена система (карта связей)

1. **БД → рендер → браузер.** `lib/db.ts (q)` → `app/*/page.tsx` → `components/*` → HTML. Пишущий в БД через phpMyAdmin де-факто пишет HTML, поэтому `lib/url.ts (safeHref)` — главный шлюз, и важна каждая щель мимо него (`img src`, iframe-превью).
2. **Согласие → сторонние ресурсы.** `CookieBanner` (флаг `hkoop-cookie` в localStorage) против `app/layout.tsx` (Метрика) и `app/contacts/page.tsx` (iframe Яндекс-карты). Баннер обещает одно, код согласия не читает — системный разрыв.
3. **Dev SSR → статический экспорт.** Прод — `output: export` на GitHub Pages: серверных заголовков и `headers()` там нет по архитектуре. Проверяются обе конфигурации; фиксы заголовков даются под хостинг, а не под next-конфиг.

## Что уже исправлено и держится (как новое не засчитывается)

Параметризация SQL (единственный запрос с параметром — `app/news/[id]/page.tsx:17` `WHERE id=?`); `safeHref` режет `javascript:`/`data:`/`//evil`, применён к партнёрским ссылкам, соцсетям, путям PDF и iframe-превью; `poweredByHeader: false` (`next.config.js:5`, заголовка нет); `.env*` и `.next-export` в `.gitignore`; `.env.local` отдаёт 404; API-роутов и мутаций нет; отражённый XSS в поиске экранируется; `../` и `%2e%2e` дают 404/«Не найдено»; phpMyAdmin за логином (П12); импринт полный (адрес, телефон, email, часы — `Header`, `Footer`, страница контактов) — ст. 10 Закона № 149-ФЗ соблюдена; партнёрские ссылки информационные (органы власти, ФНПР, вузы) — признаков немаркированной рекламы нет.

## Ранжированный список находок

### 1. HIGH — Метрика вставляется без проверки согласия

- **Место:** `app/layout.tsx:15,27-31`; `components/CookieBanner.tsx:5-27`.
- **Проверка:** инспекция + probe. Команда: `curl.exe -s http://localhost:3100/`. Условие вставки — только `ym && (...)`, флаг `hkoop-cookie` нигде не читается; noscript-пиксель `https://mc.yandex.ru/watch/${ym}` тоже безусловный. Сегодня в HTML `mc.yandex.ru` нет (счётчик не задан), но достаточно задать `NEXT_PUBLIC_YM_ID` — и трекер с `clickmap:true,trackLinks:true` встанет у всех посетителей до клика по баннеру.
- **Факт:** текст баннера («сайт использует cookie и Яндекс.Метрику. Продолжая, вы соглашаетесь») обещает согласие, код его не требует.
- **НПА:** ст. 9, 18–18.1 Федерального закона № 152-ФЗ (обработка только с согласия при его необходимости, информирование и разъяснение порядка обработки).
- **Фикс (описать):** грузить скрипт и пиксель Метрики только после флага согласия (`hkoop-cookie=1`); до согласия — ничего не вставлять. Компромисс: доля согласия в аналитике упадёт, но снимается главный риск по 152-ФЗ; альтернатива «трекать всех молча» дешевле, но нарушает закон.

### 2. HIGH — Уязвимый `next 14.2.5`: старше security-фиксов ветки

- **Место:** `package.json:12` (`"next": "14.2.5"`).
- **Проверка:** инспекция + сверка с открытыми бюллетенями. Ветка затронута как минимум CVE-2025-29927 (обход middleware-авторизации через `x-middleware-subrequest`, CVSS 9.1, исправлено в 14.2.25/15.2.3) и бюллетенями 2024 года по кэшу (CVE-2024-39328, CVE-2024-46982 — исправлены в 14.2.8+). Смягчает: `middleware.*` и API-роутов нет (файлы отсутствуют), прод — статика.
- **Факт:** dev-сервер и сборочный конвейер крутят уязвимый рантайм; любой будущий middleware/API унаследует дыру.
- **Фикс (описать):** обновить `next` минимум до `14.2.25+`, затем `npx tsc --noEmit`, `STATIC_EXPORT=1 npm run build`, пересборка и деплой. Компромисс: обновление отдельным окном с проверкой 390/768/1440, т.к. есть риск сломать экспорт.

### 3. MEDIUM — Нет защитных заголовков; страницы встраиваются в чужой iframe

- **Место:** `next.config.js:3-5` (нет блока `headers()`); подтверждение — `GET /`: только `Vary, Cache-Control, Content-Type, Date`, нет `X-Frame-Options/CSP/X-Content-Type-Options/Referrer-Policy`.
- **Проверка:** живой probe заголовков. Команда: `curl.exe -s -D - http://localhost:3100/ -o NUL`.
- **Факт:** внешний сайт может встроить страницы в `<iframe>` (кликджекинг); `nosniff` отсутствует; `Referer` с внутренними URL уходит на habprof.ru и в Яндекс.
- **НПА:** напрямую не статья; отсутствие мер — отягчающее при инциденте (ст. 19 Закона № 152-ФЗ — обеспечение безопасности).
- **Фикс (описать):** т.к. прод — `output: export` (`next.config.js:6-7`) и Next игнорирует `headers()` в статике, защиту ставить на уровне хостинга/CDN поверх GitHub Pages (`X-Frame-Options: SAMEORIGIN` / `frame-ancestors 'self'`, `nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, минимальная CSP в report-only с белым списком `yandex.ru`), плюс `<meta http-equiv>` там, где заголовки недоступны. Компромисс: строгая CSP может сломать инлайн-скрипт `classList.add('js')` и карту — вводить постепенно.

### 4. MEDIUM — Два `img src` из БД идут мимо `safeHref`

- **Место:** `app/honor/page.tsx:14` (`<img src={h.photo}>`); `components/PartnersStrip.tsx:11` (`<img src={p.logo}>`; `safeHref` применён только к `p.url`, строка 21).
- **Проверка:** инспекция. Соседние рендеры фильтруются (`app/contacts/page.tsx:9-11`, `DocsFilter.tsx:42-43`), эти два — сырые `VARCHAR(500)`. Живой HTML сегодня benign. Готового XSS нет (`javascript:` в `img src` современные браузеры не исполняют, `onerror`-вектора в коде нет) — класс stored-дефейс/трекинг.
- **Факт:** пишущий в `honor.photo`/`partners.logo` кладёт произвольный `src` (внешний трекер, mixed-content, `data:`-шлейф) на главную и `/partners` в обход allowlist.
- **Фикс (описать):** пропускать оба `src` через `safeHref` (строже — только site-relative `/images/…` + allowlist доменов), при `null` — существующая заглушка; внешним логотипам — `referrerpolicy="no-referrer"` и осмысленный `alt`.

### 5. MEDIUM — PDF-превью в iframe без песочницы; любой `https://` из БД встанет в iframe

- **Место:** `components/DocsFilter.tsx:42,50-56` (`setPreview(safeHref(d.file_local)!)`, `<iframe src={preview} width height title>` без `sandbox`).
- **Проверка:** инспекция. `safeHref` режет только схему, домен не проверяет: `file_local=https://evil.example/phish.html` пройдёт и отрендерится внутри chrome сайта.
- **Факт:** превью доверяет любому `https://`-значению из БД без проверки префикса `/docs/` и суффикса `.pdf`.
- **Фикс (описать):** для превью разрешать только site-relative `/docs/*.pdf`; внешние `file_old` — только новой вкладкой с `rel="noopener noreferrer"` и плашкой «внешний ресурс»; iframe — с `sandbox` без `allow-top-navigation`/`allow-scripts` шире необходимого.

### 6. MEDIUM — Cookie-баннер и форма юридически неполны по 152-ФЗ

- **Место:** `components/CookieBanner.tsx:12-24`; `components/ConsultForm.tsx:4-12`; `app/docs/page.tsx:11-16`.
- **Проверка:** инспекция + probe. Команда: `curl.exe -s http://localhost:3100/docs/politika.pdf -o NUL -w "%{http_code}"` → `200`. У баннера только «Принять», кнопки «Отклонить» нет; ссылка ведёт на `/docs`, а не прямо на `/docs/politika.pdf`. Чекбокс формы — голый текст без ссылки на политику и оператора; после «Отправить» нет пояснения, что данные никуда не уходят. Позитив: форма действительно ничего не отправляет (`onSubmit={e.preventDefault()}`, бэкенда нет) — минимизация соблюдена, трансграничной передачи нет.
- **НПА:** ст. 9, 18–18.1 Закона № 152-ФЗ (конкретное информированное согласие, право на отзыв, разъяснение последствий); позиция Роскомнадзора: отказ не сложнее согласия.
- **Фикс (описать):** кнопка «Отклонить» (без Метрики при отказе); ссылки баннера и чекбокса — прямо на `/docs/politika.pdf`; рядом с формой — «Оператор: Союз ХКООП, адрес, email; данные никуда не отправляются (демо-режим)»; в политику вписать cookie/Метрику и срок согласия. Компромисс: «Отклонить» снизит охват аналитики, но снимает юридический риск.

### 7. LOW — Яндекс-карта на `/contacts` грузится до согласия (улучшение приватности)

- **Место:** `app/contacts/page.tsx:23` (iframe `https://yandex.ru/map-widget/...`); подтверждение — `GET /contacts` содержит `map-widget` до любого клика.
- **Проверка:** живой probe. Команда: `curl.exe -s http://localhost:3100/contacts | Select-String "map-widget"`. Вывод: подстрока найдена. Метрика здесь ни при чём: требование задачи гейтить согласием относится к Метрике (нах. 1), карта — функциональный виджет.
- **Факт:** посетитель контактов отдаёт IP/User-Agent Яндексу до согласия; баннер про карту не говорит.
- **НПА:** ст. 19 Закона № 152-ФЗ (минимизация и безопасность) как основание для улучшения, не как нарушение запрета.
- **Фикс (описать):** до согласия — статичная заглушка с кнопкой «Показать карту (загрузит Яндекс)», iframe с `loading="lazy"`, `referrerpolicy="no-referrer"`. Компромисс: один лишний клик ради честной приватности.

### 8. LOW — Фолбэк `docHref` клеит habprof.ru по одному `startsWith("/")`

- **Место:** `app/page.tsx:37` (`safeHref(d.file_local) || safeHref(d.file_old) || (old_url.startsWith("/") ? https://habprof.ru+old_url : "/docs")`).
- **Проверка:** инспекция. Домен доверенный, React экранирует атрибут — дыры нет; риск — только невалидный путь с пробелами/управляющими символами.
- **Фикс (описать):** проверять `old_url` по `^/[a-z0-9/_\-.]*$`i, иначе фолбэк на `/docs`.

### 9. LOW — В полях поиска/фильтров/формы нет `maxLength`

- **Место:** `components/HeaderSearch.tsx:50-56`, `app/search/page.tsx:34`, `components/DocsFilter.tsx:28`, `components/ConsultForm.tsx:5-7`.
- **Проверка:** инспекция. `HeaderSearch.tsx:44` корректно использует `encodeURIComponent`; рендер результатов — JSX-текст (`{r.title}`, `{d.title}`), без `dangerouslySetInnerHTML`, поэтому вставка `<img src=x onerror=…>` в `DocsFilter`/`HeaderSearch` уходит в текст, а `?q=` в `/search` экранируется (`&lt;script&gt;`, П3). Остаток — 100-КБ строка делает лишнюю работу клиента.
- **Фикс (описать):** добавить `maxLength={200}` всем текстовым полям.

## Проверено отдельно: отражённый XSS в фильтрах

- `app/search/page.tsx:34` — `defaultValue={sp.get("q")}` (React-атрибут, экранируется); probe `?q=<script>alert(1)</script>` → `value="&lt;script&gt;`, сырого `<script>alert` нет.
- `components/HeaderSearch.tsx:44,65-67` — переход через `encodeURIComponent`, выпадашка рендерит `{r.title}` как текст.
- `components/DocsFilter.tsx:20-23,28,36-40` — фильтр по `includes()` в памяти, рендер `{d.title}` как текст; `onChange={setQ}` без HTML-парсинга.
- Вывод: хранимого/отражённого XSS в фильтрах нет; класс ограничен DoS уровня браузера (нах. 9).

## Проверено отдельно: phpMyAdmin и права MySQL

- Probe: `GET http://127.0.0.1:8081/` → `200`, тело — страница входа phpMyAdmin 5.2.2 (`logged_in:false`, `auth_type:"cookie"`). Данных без логина не отдаёт — «закрыт логином» держится.
- Права пользователя `hkoop` (`lib/db.ts:3-11`, пул только читает через `SELECT` в `app/*/page.tsx`) командой `SHOW GRANTS` не проверялись — пароль только в gitignored `.env.local`, печатать и трогать его нельзя. Остаточный риск: неизвестно, ограничен ли пользователь только `SELECT ON hkoop.*`.
- **Фикс (описать):** отдельной операцией вне аудита выполнить `SHOW GRANTS FOR 'hkoop'@...` и ужать до `GRANT SELECT ON hkoop.*`, отозвать `ALL/PRIVILEGES`, зафиксировать в `db/README.md`.

## Замечания по гигиене (не ranked-находки)

- `rel="noreferrer"` без явного `noopener` (`PartnersStrip.tsx:29`, `app/page.tsx:95`, `DocsFilter.tsx:43`): по спецификации HTML `noreferrer` имплицирует `noopener` в современных браузерах, сценария `window.opener` нет. Унифицировать на `rel="noopener noreferrer"` при ближайшем касании.
- `app/layout.tsx:15,29` (`ym(${ym},"init",...)` в `dangerouslySetInnerHTML`): `ym` серверная переменная окружения, пользовательским вводом недостижима; при компрометации окружения игра уже проиграна. Как hardening — валидировать `/^\d+$/` и вставлять через `JSON.stringify`. Строка `# NEXT_PUBLIC_YM_ID=...` в `.env.example:6` — документация примера, не утечка; не удалять.
- Версия для слабовидящих работает (`ViProvider`, кнопка в шапке) — наличие по ГОСТ Р 52872-2019 закрыто; точечно добавить видимый фокус и проверку контраста панели.
- Логотипы/фото третьих лиц — зафиксировать письменные разрешения отдельным реестром (ст. 1274 ГК РФ).

## Компромиссы

1. Строгость vs честность: Метрика и Next стоят HIGH без эксплуатации сегодня — иначе читатель включит счётчик одной строкой и получит сюрприз.
2. Целое vs точечное: чинить связку «согласие → загрузка» целиком (баннер + layout + карта), а не по файлам.
3. Dev vs прод: заголовки — через хостинг/CDN, а не через next-конфиг, иначе защита исчезнет в статике.

## Вердикт

Показывать людям можно только после пунктов 1 и 6 (согласие должно реально управлять Метрикой; у баннера и формы — отказ и прямые ссылки на политику); первым чинить связку согласия целиком, вторым — обновить Next и закрыть `img src`/iframe-песочницу.
