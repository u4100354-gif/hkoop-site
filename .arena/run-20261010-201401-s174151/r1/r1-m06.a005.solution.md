## Как устроена система (карта цепочек — читать первой)

- **Цепочка A «БД → рендер → браузер»**: `lib/db.ts (q)` → `app/*/page.tsx` → `components/*` → HTML. Параметризация SQL держится везде, allowlist `safeHref` покрывает href/iframe из БД — но НЕ покрывает `img src` (фото книги почёта, логотипы партнёров). Тот, кто пишет в БД (через phpMyAdmin), — де-факто автор HTML сайта.
- **Цепочка B «согласие → Метрика/карта → передача данных»**: `CookieBanner` (флаг `hkoop-cookie`) никак не связан с загрузчиком Метрики в `app/layout.tsx:27-31` и картой в `app/contacts/page.tsx:23`. Включение счётчика по инструкции из `.env.example` запустит передачу в Яндекс до и без согласия.
- **Цепочка C «dev → export → Pages»**: dev-раздача Next не отдаёт security-заголовки; статический экспорт на Pages их тоже не добавит сам. Что не заложено в код/конфиг, в проде не появится; серверный рантайм Next в проде не исполняется.
- **Цепочка D «админ → БД → сайт»**: phpMyAdmin 5.2.2 за логином (держится), но светит версией, работает по HTTP; пароли к БД лежат в отслеживаемом `db/README.md` (см. F0). Взлом админки или утечка пароля из git = запись в БД = stored-контент через цепочку A.
