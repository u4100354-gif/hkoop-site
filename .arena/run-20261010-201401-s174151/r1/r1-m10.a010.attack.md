ATTACK 1 [FATAL] H3: фикс заголовков через `_headers`/headers() не работает на GitHub Pages
Where: a006 §H3: "Для GitHub Pages — через `_headers`/Cloudflare-правила, для dev — `headers()` в `next.config.js`"; `next.config.js:1-27` (секции `headers()` нет, `output: export` при `STATIC_EXPORT=1`); допущение a006 №1 (прод — статический экспорт на GitHub Pages).
Problem: фикс неприменим там, где должен действовать. `headers()` из `next.config.js` игнорируется при `output: export`, а GitHub Pages не поддерживает файл `_headers` (это механизм Netlify/Cloudflare Pages, не GitHub Pages — там кастомные заголовки вообще не задаются средствами репозитория). То есть для прод-окружения из допущения №1 предложенный путь не даёт ни CSP, ни `frame-ancestors`, ни HSTS. Оценка HIGH "эффект — все URL сайта" при этом снята с dev-сервера `http://localhost:3100` (localhost без сетевой угрозы), а прод-фикс нерабочий — находка неactionable.

ATTACK 2 [FATAL] C1: CRITICAL с неверным обоснованием про "уязвимый рантайм" статического экспорта
Where: a006 §C1: "Даже статическому экспорту это важно: сборка и dev-сервер используют уязвимый рантайм, а будущие middleware/API унаследуют дыру"; `package.json:12` (`"next": "14.2.5"`).
Problem: неверно фактически. Собранный статический экспорт на GitHub Pages — это HTML/CSS/JS без Next-сервера: эксплуатировать CVE-2025-29927 (требует middleware и заголовок `x-middleware-subrequest`) там негде — `middleware.*` в проекте отсутствует (glob `**/middleware.*` пуст), `app/api/**` пуст (сам a006 это фиксирует). Dev-сервер слушает только localhost:3100 и не выставлен наружу. Аргумент "будущие middleware унаследуют" — гипотетическое будущее, а не текущая CRITICAL-уязвимость прод-сайта. Приоритизация "обновить в первую очередь" выше реально открытых секретов и consent-разрывов тем самым вводит в заблуждение.

ATTACK 4 [MAJOR] H1 выдаёт условный путь кода за активное нарушение без живой пробы
Where: a006 §H1 (`app/layout.tsx:15,27-31`, `components/CookieBanner.tsx:1-27`): "достаточно задать `NEXT_PUBLIC_YM_ID`, и трекер ... встанет у всех посетителей до клика «Принять»"; собственное допущение №3 ("счётчик считается запланированным ... в примере закомментирован").
Problem: нарушен стандарт задачи: "каждая находка — severity, файл:строка или URL+команда проверки, факт (что именно не так, с цитатой/выводом)". У H1 нет ни одной команды/вывода (только цитата кода), а факт — сослагательный ("достаточно задать"). То же относится к M2 (карта): заявлен "трансграничный след" без пробы `Set-Cookie`/запросов и без разбора, что оператор через чужой iframe сам ПДн не обрабатывает.

ATTACK 5 [MAJOR] Неверные статьи НПА в юридических пунктах

Problem: задача требует "статья НПА для юридических пунктов". Ст. 16 закона № 149-ФЗ — про защиту информации обладателем, а не про встраивание информационной карты; передача IP/User-Agent браузером третьему лицу (Яндексу) не становится "обработкой ПДн оператором" по ст. 9 152-ФЗ без собственного сбора. Ссылка на "разъяснения Роскомнадзора" без даты/названия/пункта непроверяема и неactionable.

ATTACK 6 [MAJOR] M3 — признанная не-дыра с рангом MEDIUM, без контрпримера и пробы
Where: a006 §M3 (`app/honor/page.tsx:14`, `components/PartnersStrip.tsx:11`): "React экранирует текст/кавычки, поэтому это не «дыра сегодня», а отсутствующий второй рубеж".
Problem: MEDIUM требует эксплуатируемого факта. Его нет: не приведён ни один вход из БД, который исполнится (например, какое значение `h.photo`/`p.logo` даст XSS, если `lib/url.ts:3-8` соседние href режет, а React экранирует атрибуты и современные браузеры не исполняют `javascript:` в `<img src>`). Проверки "команда и вывод" нет — только инспекция. Предлагаемый фикс "пропускать через тот же `safeHref`" при этом сломает легитимные кейсы, которые сам автор признаёт (IDN `хабаровсккурорт.рф`, кириллические пути — `safeHref` пропускает только `https?://` и `/[^/\\]`, `data:` режет, `encodeURI`-нормализация не протестирована). Это hardening-идея, а не MEDIUM-находка по стандарту задачи.
