ATTACK 3 [FATAL] Фото книги почёта названы биометрией по ст. 11 152-ФЗ
Where: `r0/a015.md:82-84` — «Фото — биометрические ПД (ст. 11 152-ФЗ, нужно письменное согласие)»
Problem: фото как иллюстрация в галерее — не биометрические ПД. По позиции Роскомнадзора ст. 11 применяется только когда изображение используется для установления личности через биометрические системы; обычная публикация портрета регулируется ст. 152.1 ГК РФ (изображение гражданина) и ст. 10.1 152-ФЗ (данные, разрешённые для распространения). Требование «письменного согласия по ст. 11» неверно по НПА и ведёт к неверному фиксу (архивировать не ту форму согласия). Контрпример: любое новостное фото на сайте подпадало бы под ст. 11, что абсурдно и противоречит практике.

ATTACK 4 [MAJOR] Фикс Н5 неработоспособен: frame-ancestors в <meta> игнорируется
Where: `r0/a015.md:54` — «для GitHub Pages — `<meta http-equiv="Content-Security-Policy" content="default-src 'self'; ... frame-ancestors 'self' ..."»`
Problem: по спецификации CSP директива `frame-ancestors` игнорируется при доставке через `<meta http-equiv>`. Предложенный мета-тег не закроет кликджекинг («сайт можно встроить в чужой iframe»), о котором сам пункт заявляет. Рабочий вариант для статики — только `X-Frame-Options` на хостинге/Cloudflare либо JS frame-busting как слабый костыль, но не meta frame-ancestors. Фикс вводит в заблуждение и не чинит заявленную угрозу.
