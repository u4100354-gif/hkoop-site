# Аудит сайта ХКООП: безопасность и соответствие законам РФ (включая 152-ФЗ)

## Кому этот отчёт и как его читать

Отчёт написан для двух людей: председателя (решение «показывать ли сайт людям») и разработчика с пресс-службой (что чинить и в каком порядке). Находки отсортированы по тяжести: сверху то, что чинить первым. У каждой находки есть severity, точное место, проверка (команда и вывод, можно повторить), факт и предлагаемый фикс. Проект при аудите не менялся, в БД ничего не писалось (только чтение кода и безопасные GET), секреты не печатаются.

## Допущения

- Аудит по рабочему дереву ветки `backup-2026-10-10` как есть; dev-сервер http://localhost:3100; phpMyAdmin http://127.0.0.1:8081.
- Живые пробы — только безопасные GET. Пакеты не ставились, `npm audit` не запускался.
- Текст `politika.pdf` построчно не экспертизировал (проверены наличие, доступность, ссылки); содержательную проверку политики отдаю юристу.
- Права MySQL-юзера живой командой `SHOW GRANTS` не проверял (нет права светить креды и менять БД); оценка прав — по `db/README.md`, это ограничение честно зафиксировано в H2.

## Вопросы эксперта перед работой и ответы

1. Кто пострадает при ошибке? Посетитель (трекинг, фишинг), организация (штраф по ст. 13.11 КоАП за 152-ФЗ, претензии по импринту ст. 10 149-ФЗ), пресс-служба (доступ к БД). Приоритет — цепочки «данные БД → браузер» и согласия.
2. Где граница «уже исправлено» vs «новое»? Список из задания перепроверяю пробами, а не на слово. Всё подтвердилось (раздел «Держится»); новым считаю только отсутствующее в списке.
3. Что исполняется в браузере? Серверные компоненты отдают HTML, клиентские (форма, поиск, фильтры, баннер) исполняют JS. Ищу `dangerouslySetInnerHTML` с переменными, нефильтрованные `src`/`href` из БД, сторонние запросы до согласия.
4. Кто фактически пишет HTML сайта? Владелец доступа к БД: почти весь контент из таблиц. Любое поле БД в `href`/`src`/`iframe` без фильтра — удалённое редактирование сайта. Так найдены главные зазоры (М1, М7).
5. Что уходит третьим лицам до согласия? Карта Яндекса безусловно, Метрика — при включении. Проверяется чтением кода и живого HTML.
6. Что видит неопытный пользователь? Форму, молча глотающую заявку, и баннер без отказа. Это тоже находки: они решают, будет ли жалоба.

## Находки

### H1. HIGH — Next.js 14.2.5 с известными CVE

- **Место:** `package.json` (`"next": "14.2.5"`).
- **Проверка (инспекция):** зависимости — `next 14.2.5`, `react 18.3.1`, `mysql2 ^3.24.5`. Ветка 14.2.x младше 14.2.25 содержит CVE-2025-29927 (обход авторизации через заголовок `x-middleware-subrequest`, исправлено в 14.2.25) и CVE-2024-46982 (отравление кэша). `npm audit` не запускался (запрет менять проект).
- **Факт:** фреймворк с публичными эксплойтами; middleware сейчас нет, что снижает, но не снимает риск.
- **Фикс:** обновить `next` минимум до 14.2.33, `npx tsc --noEmit`, `STATIC_EXPORT=1 npm run build`; проверять `npm audit` ежемесячно.

### H2. HIGH — Пароли от БД открытым текстом в репозитории, избыточные права

- **Место:** `db/README.md:10-11` (две пары логин/пароль), `db/README.md:12` («все права на базу hkoop»).
- **Проверка (инспекция):** файл внутри репозитория, значения не заглушки. Сами значения не привожу. Живой `SHOW GRANTS` не выполнял (ограничение — не светить креды и не трогать БД), поэтому объём прав фиксирую как заявление README, а не как живой факт.
- **Факт:** доступ к репозиторию = доступ к БД; право ALL избыточно сайту, которому нужен только SELECT.
- **Фикс:** сменить оба пароля; в README оставить шаблон без значений; сайту — только `GRANT SELECT ON hkoop.*`; проверить `git log -- db/README.md`, при утечке наружу считать пароли скомпрометированными.

### M1. MEDIUM — Два `img src` из БД без фильтра; голый `safeHref` для картинок недостаточен

- **Место:** `app/honor/page.tsx:14` (`<img src={h.photo}>`), `components/PartnersStrip.tsx:11` (`<img src={p.logo}>`; рядом в строке 21 `href` уже через `safeHref`). Фильтр `lib/url.ts:7`: `if (/^(https?:\/\/|\/[^/\\])/i.test(v)) return v;` — пропускает любой https-домен.
- **Проверка (инспекция + живой probe):** `curl.exe -s http://localhost:3100/honor | Select-String "img src"` → сегодня 7 вхождений, все site-relative (`src="/images/honor/vorona.jpg"`, `didukh.jpg`, `nesterova.jpg`, `Скакун_1.jpg`, `photo_5190505369661280600_y.jpg`, `Сушко_Г.jpg`, `yanchenko-s_n_.jpeg`), посторонних доменов нет. Контрпример: значение `https://tracker.evil/pixel.png` проходит `safeHref` как есть — фильтр трекинг не режет. Эксплуатации сегодня нет.
- **Факт:** не готовый XSS (`javascript:` в `src` браузеры не исполняют, `on*` нет), а stored-дефейс и скрытый трекинг (IP/UA третьему лицу без согласия): пишущий в таблицы кладёт произвольный `src` на все страницы с `PartnersStrip` (главная + `/partners`) и `/honor`.
- **Фикс:** для картинок НЕ голый `safeHref`, а строгий allowlist: только site-relative `/images/…` (проверка `startsWith("/images/")` + `encodeURI` для кириллицы), всё остальное — `null` с заглушкой «★»; внешним пикселям — запрет. Общий allowlist доменов для ссылок — см. М7.

### M2. MEDIUM — Метрика включится всем без проверки согласия (152-ФЗ, ст. 9)

- **Место:** `app/layout.tsx:15,27-32` (скрипт `tag.js` + `ym(...,"init",...)` + `noscript`-пиксель).
- **Проверка:** рендер всем при заданной `NEXT_PUBLIC_YM_ID`, без чтения `hkoop-cookie`. Живой факт: `curl.exe -s http://localhost:3100/ | Select-String "mc.yandex"` → совпадений нет — нарушения сегодня нет, но включение «в один клик» соберёт cookie `_ym` без согласия.
- **Факт:** cookie-идентификаторы — персональные данные по позиции Роскомнадзора; сбор до «Принять» — типовое нарушение ст. 9 Федерального закона от 27.07.2006 № 152-ФЗ.
- **Фикс:** грузить Метрику (и пиксель) только при `lsGet("hkoop-cookie")==="1"`; в политике перечислить Метрику, срок cookie, отказ.

### M3. MEDIUM — Карта Яндекса стучится третьему лицу до согласия

- **Место:** `app/contacts/page.tsx:23` (`<iframe src="https://yandex.ru/map-widget/…">`).
- **Проверка (инспекция):** рендерится каждому посетителю `/contacts` безусловно; `title` есть, `sandbox`/`loading="lazy"` нет.
- **Факт:** IP/UA уходят в Яндекс без согласия (ст. 9 152-ФЗ).
- **Фикс:** клик-заглушка («Показать карту» → iframe по клику), `loading="lazy"`, упомянуть карту в политике.

### M4. MEDIUM — Баннер без отказа (152-ФЗ, ст. 9); ссылка на каталог — лишь юзабилити

- **Место:** `components/CookieBanner.tsx:12-24` (одна кнопка «Принять», ссылка `<a href="/docs">`).
- **Проверка:** кода + живой факт: `curl.exe -s http://localhost:3100/docs | Select-String "politika"` → `<a href="/docs/politika.pdf">Политика конфиденциальности (PDF)</a>`; `curl.exe -s -o NUL -w "%{http_code} %{size_download}\n" http://localhost:3100/docs/politika.pdf` → `200 3392427`. Документ опубликован и находится в два клика (баннер → `/docs` → PDF).
- **Факт:** нарушения ст. 18.1 152-ФЗ (неопубликование политики) здесь нет — поправка к прежней формулировке. Остаются: (а) согласие без равнодоступного отказа не свободно (ст. 9 152-ФЗ); (б) ссылка ведёт в каталог, а не прямо на PDF — лишняя ступень. Пункт (б) — LOW-замечание, пункт (а) держит MEDIUM.
- **Фикс:** кнопка «Отклонить» (`hkoop-cookie=0`, без Метрики/карты), ссылку вести прямо на `/docs/politika.pdf`.

### M5. MEDIUM — Согласие в форме без ссылки на политику; заявка уходит в пустоту

- **Место:** `components/ConsultForm.tsx:4-11` (только `preventDefault`, бэкенда нет).
- **Проверка:** чекбокс `required` есть, ссылки на политику рядом нет; после «Отправить» — никакого сообщения.
- **Факт (ст. 9 152-ФЗ):** согласие должно быть информированным — политика доступна в момент дачи. Отдельно: человек решит, что заявка отправлена, и не позвонит; потеря обращений.
- **Фикс:** ссылка «Политика конфиденциальности» под чекбоксом; до запуска бэкенда — честное сообщение («Форма демонстрационная. Позвоните: …» + `tel:`).

### M6. MEDIUM — Нет заголовков безопасности; на статическом проде `headers()` не поможет

- **Место:** HTTP-ответ + `next.config.js` (прод — `output: export` на GitHub Pages).
- **Проверка:** `curl.exe -s -D - -o NUL http://localhost:3100/` → есть только `Vary`, `Cache-Control: no-store, must-revalidate`, `Content-Type`; нет `Content-Security-Policy`, `X-Frame-Options`, `Referrer-Policy`, `X-Content-Type-Options`. Поправка: `headers()` из `next.config.js` при статическом экспорте игнорируется, а CSP через `<meta http-equiv>` не поддерживает `frame-ancestors` — кликджекинг этим не закрыть.
- **Факт:** сайт встраивается в чужой iframe (кликджекинг на форме); без CSP нет страховки от инлайн-инъекции; без `Referrer-Policy` полный URL уходит внешним сайтам.
- **Фикс:** заголовки на уровне хостинга (GitHub Pages их не отдаёт — либо смена хостинга/CDN с заголовками, либо принять риск письменно); независимо: `<meta http-equiv>` для остатка CSP + `Referrer-Policy`, `sandbox` на iframe PDF (`DocsFilter.tsx:56`), `loading="lazy"`, frame-busting скрипт как компенсация, а не как замена заголовкам.

### M7. MEDIUM — `safeHref` пускает любой https-домен

- **Место:** `lib/url.ts:3-9`, потребители `DocsFilter.tsx:42-43,56`, `page.tsx:37,95`.
- **Проверка:** схема режется (`javascript:`, `data:`, `//evil`, граничные `JaVaScRiPt:`, `/\` отклоняются), домен не проверяется; iframe-превью без `sandbox`.
- **Факт:** строка в БД = фишинговая ссылка/iframe в дизайне ХКООП. Вероятность низкая, ущерб высокий. Этот же зазор делает недостаточным прежний фикс M1.
- **Фикс:** allowlist доменов партнёров + только site-relative для `file_local`; `sandbox="allow-same-origin"` без `allow-scripts`; CHECK-ограничение в БД.

### L2. LOW — ID Метрики в `dangerouslySetInnerHTML` без валидации

- **Место:** `app/layout.tsx:29`. Переменная серверная, риск только при подмене окружения.
- **Фикс:** рендерить только при `/^\d+$/`.

### L3. LOW — Поля формы без `maxLength`

- **Место:** `ConsultForm.tsx:5-7`. Вреда сейчас нет (бэкенда нет).
- **Фикс:** 100/100/2000 уже сейчас + проверка на будущем бэкенде.

### L4. LOW — Пустые `alt` у картинок (ГОСТ Р 52872-2019)

- **Место:** `PartnersStrip.tsx:11`, `page.tsx:52` (`alt=""`); положительно: `honor/page.tsx:14` (`alt={h.fio}`).
- **Фикс:** `alt={p.name}`, осмысленные alt новостей. Версия для слабовидящих (кнопка `Header.tsx:55`, `ViProvider`, skip-link `layout.tsx:20`) работает.

### L5. LOW — Футер «Локальный прототип», нет ОГРН/ИНН

- **Место:** `Footer.tsx:27`. Импринт ст. 10 Федерального закона от 27.07.2006 № 149-ФЗ в остальном есть (адрес, телефон, email, соцсети).
- **Фикс:** полное наименование + ОГРН/ИНН; контакты оператора в политике (ст. 18.1 152-ФЗ).

### L6. LOW — `safeHref` без нормализации не-ASCII; фолбэк клеит внешний URL

- **Место:** `lib/url.ts:5`, `page.tsx:37` (фолбэк `https://habprof.ru${d.old_url}` по одному `startsWith("/")`).
- **Фикс:** `encodeURI` перед проверкой; фолбэк — на `/docs`.

## Законы РФ коротко

- **152-ФЗ:** политика опубликована (`GET /docs/politika.pdf` → 200, 3392427 байт) и связана со страницы `/docs`; чекбокс есть; зазоры — М2–М5. Форма ничего не отправляет (минимизация de facto); трансграничную передачу и локализацию отразить в политике.
- **Ст. 10 149-ФЗ:** адрес/телефон/email есть; до прода — ОГРН/ИНН, убрать «прототип» (Л5).
- **ГОСТ Р 52872-2019:** кнопка, панель (шрифт/картинки), skip-link — есть; добить alt (Л4).
- **38-ФЗ:** партнёрские блоки информационные, маркировка не нужна; держать вывеску «Полезные ссылки».
- **Авторские права:** логотипы и фото — информационное использование; собрать письменные разрешения превентивно.

## Вердикт одной строкой

Показывать сайт людям можно только после H1–H2 и М2–М5 (обновить Next.js, убрать пароли из репозитория и урезать права БД, закрыть согласия по 152-ФЗ и починить форму), остальное — второй очередью до прода.
