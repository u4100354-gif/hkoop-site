ATTACK 1 [FATAL] H2 хранимый XSS через `<img src="javascript:...">` не срабатывает, «единственная граница» — ложь
Where: r0/a012.md H2: «Достаточно одной вредоносной правки... например `photo = javascript:alert(1)`... и полезная нагрузка окажется в разметке» + «то есть это единственная открытая граница для хранимого XSS»
Problem: контрпример — `photo = javascript:alert(1)` в `<img src>` в современных браузерах не исполняется (JS-URL в `img` игнорируется; `data:image/svg+xml` со скриптом в контексте `<img>` тоже не исполняет скрипт). Реальный эффект — битая картинка/трекер, а не выполнение JS, т.е. заявленный PoC не стреляет. «Единственная» прямо противоречит собственным M1/M6/M7 того же отчёта (iframe с любым https-доменом, открытый `https://` в `safeHref`, фолбэк `habprof.ru`), где та же компрометация строки БД даёт фишинг/навигацию. Проверка: `app/honor/page.tsx:14` (`<img src={h.photo}>`), `components/PartnersStrip.tsx:11` (`<img src={p.logo}>`) — сырые, верно; неверны exploit-механика и claim уникальности.

ATTACK 2 [MAJOR] Фикс M3 не работает на заявленном проде (статика на GitHub Pages)
Where: r0/a012.md M3: «в dev-режиме — `headers()` в `next.config.js` (для статического экспорта на Pages — эквивалентные `<meta http-equiv>`...)»
Problem: задача фиксирует прод — «статический экспорт (Next `output: export`) на GitHub Pages», а `next.config.js:6-7` включает `output: "export"` при `STATIC_EXPORT=1`, где `headers()` Next.js игнорируется (заголовки отдаёт хостинг, не Next). `<meta http-equiv>` не может выставить `X-Frame-Options`, `Strict-Transport-Security` и `frame-ancestors` — т.е. именно кликджекинг, ради которого написан M3, этим фиксом на проде не закрывается. Исполнитель не сможет применить совет без догадок, где реально крутить заголовки Pages.
