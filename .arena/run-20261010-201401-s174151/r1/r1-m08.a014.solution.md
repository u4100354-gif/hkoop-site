# Аудит сайта ХКООП: безопасность и соответствие законам РФ (включая 152-ФЗ)

Дата: 10.10.2026. Объект: рабочее дерево `hkoop-site` (ветка `backup-2026-10-10`), dev-сервер http://localhost:3100, phpMyAdmin http://127.0.0.1:8081. Проект не менялся: только чтение кода и безопасные GET-пробы, в БД — только чтение схемы/кода (SELECT-характер подтверждён по коду; клиент mysql в среде отсутствует).

## Проверено, держится (не засчитывать как новое)

- Все SQL-запросы параметризованы (`WHERE id=?`, конкатенаций нет): `app/news/[id]/page.tsx:17`, `app/page.tsx:33-35`, остальные `app/*/page.tsx`. Проверка: инспекция + живой probe несуществующего id (200 «Не найдено», стектрейса нет — см. ниже).
- `lib/url.ts:3-9` — allowlist http(s)/site-relative для href/iframe из БД; применяется в контактах, партнёрских ссылках, PDF-превью.
- `poweredByHeader: false` (`next.config.js:5`). Проверка: `curl.exe -sS -D - http://localhost:3100/ -o NUL` → заголовки `Vary, Cache-Control: no-store, Content-Type`, строки `X-Powered-By` нет (вывод: `NO_X_POWERED` по шапке ответа).
- `.env.local` по HTTP → 404. Проверка: `curl.exe -sS http://localhost:3100/.env.local -o NUL -w "%{http_code}\n"` → вывод `404`. `.gitignore` покрывает `.env`, `.env.local`, `.next-export`.
- Отражённый XSS через `?q=` нейтрализован экранированием React: поиск клиентский (`app/search/page.tsx:20-34`, `defaultValue`/`{r.title}` — текстовые узлы, без `dangerouslySetInnerHTML`).
- Инъекции пути `/news/../`, `/%2e%2e/` → 404; несуществующий id → страница «Не найдено» без деталей ошибки. Проверка: сохранённый ответ `news404.html` (12531 байт), поиск `stack|Traceback|at X(` → `ABSENT`.
- API-роутов нет (`app/api` отсутствует) — мутаций серверной стороны нет. ConsultForm только `preventDefault`, сетевых вызовов нет (проверка ниже).
- phpMyAdmin отвечает страницей входа — без логина не пускает (проверялся только GET главной).
- Импринт есть: адрес, телефон, email в шапке, футере и на `/contacts`. Версия для слабовидящих работает (`ViProvider`, классы `vi-mode`/`vi-big`/`vi-noimg` в `app/globals.css`).
- Партнёрские ссылки — информационные (госорганы, ФНПР, фонды, вузы), признаков скрытой рекламы нет.

## Ранжированный список находок

### 1. HIGH — Пароли БД лежат в git-репозитории
- **Место:** `db/README.md:8-11`.
- **Проверка:** команда `git -C hkoop-site ls-files db/README.md` → вывод `db/README.md` (файл отслеживается, `.gitignore` его не покрывает). Инспекция строк 8-11: заголовок «Доступы» и два логина/пароля в открытом виде (значения не привожу); команда `node scratch/a014-check.js` подтверждает окружение, факт — чтением файла.
- **Факт:** любой клон/форк/утечка репозитория отдаёт доступы к MariaDB; пароли затем переиспользуются. Замечание AGENTS.md («пароли только в db/README.md и .env.local, не коммитить») нарушено самим фактом коммита.
- **Фикс (описательно):** убрать пароли из файла, заменить плейсхолдерами; сменить оба пароля; переписать историю (`git filter-repo`/BFG); оставить файл как шаблон без секретов.

### 2. HIGH — Next.js 14.2.5 с известными CVE не обновлён
- **Место:** `package.json:12` (`"next": "14.2.5"`).
- **Проверка:** команда `node -p "require('.../hkoop-site/package.json').dependencies.next"` → вывод `14.2.5`. Сверка с бюллетенями Next.js: ветка 14.2 до ~14.2.25 содержит CVE-2025-29927 (обход авторизации через middleware, CVSS 9.1), CVE-2024-46982, CVE-2024-47877 (DoS/кэш). Проект middleware не использует, прод — статика, поэтому эксплуатация затруднена, но dev-сервер уязвим.
- **Факт:** зависимость с публичными эксплойтами.
- **Фикс:** обновить `next` до последнего 14.x (≥14.2.25) или 15.x, прогнать `npx tsc --noEmit`, пересобрать, зафиксировать lock-файл.

### 3. HIGH — Яндекс.Метрика вставляется без привязки к согласию (сработает в день включения счётчика)

- **Проверка:** инспекция `app/layout.tsx:15,27` (`const ym = process.env.NEXT_PUBLIC_YM_ID` → безусловная вставка при заданном ID) + `components/CookieBanner.tsx` (флаг `hkoop-cookie` нигде не читается перед вставкой; скрипт-проверка `node scratch/a014-check.js` → `LAYOUT_YM_GATE=true`, `BANNER_DOCS_LINK=true`). Живой probe: `curl.exe -sS http://localhost:3100/ -o home.html` + проверка → `LEN:34686, METRIKA:ABSENT`; `.env.example:6` → `# NEXT_PUBLIC_YM_ID=93635033` (закомментирован). Вывод: нарушение «спящее» — код готов слать данные до согласия.
- **Факт:** передача данных в Метрику до согласия нарушает требования о согласии на обработку и cookie-аналитику.
- **НПА:** 152-ФЗ ст. 6 ч. 1, ст. 9; ст. 18.1 (информирование); разъяснения Роскомнадзора о cookie/аналитике.
- **Фикс:** вставлять блок Метрики только после согласия (`hkoop-cookie === "1"`, клиентский gate-компонент вместо серверного условия), добавить в баннер кнопку «Отклонить», хранение отказа отдельно.

### 5. MEDIUM — Нет security-заголовков; для статического прода часть из них вообще не выставить
- **Место:** URL `http://localhost:3100/` (ответ dev-сервера); прод — статический экспорт на GitHub Pages.
- **Проверка:** команда `curl.exe -sS -D - http://localhost:3100/ -o NUL` → вывод: `HTTP/1.1 200 OK`, `Vary: RSC, Next-Router-State-Tree, ...`, `Cache-Control: no-store, must-revalidate`, `Content-Type: text/html; charset=utf-8` — строк `Content-Security-Policy`, `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy` нет.
- **Факт:** сайт без CSP/clickjacking-защиты. Честная оговорка: при `output: export` директива `headers()` в `next.config.js` игнорируется (сервера нет), а `<meta http-equiv>` не может выставить `X-Frame-Options`/`Permissions-Policy` — на чистом GitHub Pages кликджекинг заголовками не закрыть.
- **Фикс:** для dev/SSR-стенда — `headers()` в `next.config.js`; для Pages — `<meta http-equiv="Content-Security-Policy" content="...; frame-ancestors 'self'; ... frame-src https://yandex.ru">` + `referrer`-политика + `X-Content-Type-Options` через meta где возможно; для полного закрытия — хостинг с поддержкой заголовков (CDN/реверс-прокси перед Pages).

### 7. LOW — `<img src>` из БД без allowlist: фото книги почёта и логотипы партнёров (не XSS, а трекинг/дефейс)
- **Место:** `app/honor/page.tsx:14` (`<img src={h.photo}>`), `components/PartnersStrip.tsx:11` (`<img src={p.logo}>`).
- **Проверка:** инспекция + скрипт: `HONOR_SAFEHREF=false` (в honor allowlist не используется), в `PartnersStrip` `safeHref` применён только к `href` (3 упоминания), `src` логотипа — без него. Живой `/honor` сейчас отдаёт локальные картинки — чисто. Явно исправляю свою прежнюю формулировку: `data:text/html` или `javascript:` в `<img src>` скрипт не исполняют (битая картинка), SVG в `<img>` исполняется без скриптов — хранимого XSS здесь нет.
- **Факт:** остаточный риск — через правку БД (phpMyAdmin) можно подсунуть внешний URL-трекера, `data:`-картинку или дефейс-изображение; это нарушение целостности/трекинг, а не выполнение JS.
- **Фикс:** пропускать `h.photo` и `p.logo` через `safeHref` (или строже — только site-relative `/images/...`), при `null` — плейсхолдер как сейчас при `err`.
