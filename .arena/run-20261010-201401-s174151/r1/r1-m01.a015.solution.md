# Аудит сайта ХКООП: безопасность и соответствие законам РФ (включая 152-ФЗ)

Дата: 10.10.2026. Объект: рабочее дерево `hkoop-site` (ветка `backup-2026-10-10`), dev-сервер http://localhost:3100, phpMyAdmin http://127.0.0.1:8081. Проект не изменялся: только чтение кода и безопасные GET-пробы. Секреты не печатаются.

## Допущения

- Прод — статический экспорт (`output: export`) на GitHub Pages: серверные заголовки там недоступны, это учтено в фиксах.
- Прямой SELECT к БД не выполнялся; содержимое живых таблиц оценено через код, живой рендер страниц и инспекцию. Файлы `data/*.json` — исходные сиды (сайт читает БД, не их), поэтому утверждения вида «текущие данные безвредны» носят условный характер и требуют подтверждения штатным SELECT (`SELECT id,url,logo FROM partners`, `SELECT id,photo FROM honor`, `SELECT id,file_local,file_old FROM documents`) перед продом.
- CVE-данные — по публичным бюллетеням Next.js на дату аудита.

## Проверено и чисто (не находки)

- **SQL-инъекции отсутствуют.** Все 11 вызовов `q()` — статический SQL без конкатенации пользовательского ввода: `app/page.tsx:33,34,35` (3 запроса в `Promise.all` без `await` у каждого вызова), `app/news/page.tsx:6`, `app/news/[id]/page.tsx:12,17`, `app/docs/page.tsx:6`, `app/partners/page.tsx:6`, `app/honor/page.tsx:5`, `app/contacts/page.tsx:7`, `app/events/page.tsx:5`. Единственный запрос с параметром — `app/news/[id]/page.tsx:17` (`WHERE id=?`, `[params.id]`). Живая проба `GET /news/1' OR '1'='1` → HTTP 200, страница «Не найдено», следов ошибок БД нет.
- **Отражённый XSS отсутствует.** Проба `GET /search?q=<script>alert(1)</script>` → значение отражено только как `value="&lt;script&gt;alert(1)&lt;/script&gt;"` (экранировано React-атрибутом). Длинная проба (100×`A` + `<img src=x onerror=alert(1)>`) → сырого тега `<img src=x` в ответе нет, только `&lt;img …&gt;` внутри `value`. Ошибка/пустой результат — «Ничего не найдено».
- **Инъекции в путях.** `GET /news/..%2F..%2Fetc%2Fpasswd` → 200 «Не найдено»; `GET /news/<script>…` → штатный 404 без трейса. Несуществующий id → «Не найдено», без 500 и стектрейсов (в ответах нет `SQL`, `stack`, `Traceback`, `Unhandled`).
- **`safeHref` (`lib/url.ts:3-9`) работает.** Allowlist `https?://` + site-relative `/[^/\\]`; `javascript:`, `data:`, `//evil`, `/\` — отклоняются. Применён к партнёрским href (`components/PartnersStrip.tsx:21`), соцсетям (`app/contacts/page.tsx:9-11`), PDF (`components/DocsFilter.tsx:42-43`, `app/page.tsx:37`).
- **Секреты.** `GET /.env.local` → 404. `poweredByHeader: false` (`next.config.js:5`); заголовка `X-Powered-By` у сайта нет (проверено `curl -sI /`). `.gitignore:4-5` покрывает `.env` и `.env.local`. Хардкода паролей в коде нет (`lib/db.ts:3-11` — только `process.env`).
- **API-роутов и мутаций нет.** `route.ts` в `app/` отсутствует; все страницы — серверные SELECT или клиентские фильтры. `ConsultForm` (`components/ConsultForm.tsx:4`) делает только `preventDefault` (см. Н11 — это UX-заглушка, а не утечка).
- **phpMyAdmin закрыт.** `GET http://127.0.0.1:8081/` → 200 с формой логина, `Set-Cookie … HttpOnly; SameSite=Strict`, `X-Frame-Options: DENY`, собственный CSP. Логин не подбирался.
- **Партнёрские ссылки — не реклама.** Информационный характер (логотип + ссылка на ФНПР, правительство края, фонды, вузы), без призывов и вознаграждения — маркировка по ст. 16 закона 38-ФЗ не требуется.
- **Импринт по ст. 10 149-ФЗ выполнен.** Адрес, телефон, email и часы есть (`components/Footer.tsx`, `app/contacts/page.tsx:14-24`, верхняя плашка `components/Header.tsx:52-54`). Публикация ИНН/ОГРН и контактов ответственного за обработку ПДн законом для сайта не требуется (ст. 22.1 152-ФЗ требует назначения ответственного, а не публикации) — это лишь рекомендация (см. «Рекомендации вне ranked-списка»).

## Находки (по убыванию критичности)

### Н1. HIGH — Next.js 14.2.5 с известными CVE, включая критический обход middleware

- **Место:** `package.json:12` (`"next": "14.2.5"`).
- **Проверка (инспекция):** версия зафиксирована ниже патчей. Публичные бюллетени: CVE-2025-29927 (CVSS 9.1, обход авторизации через заголовок `x-middleware-subrequest`, исправлено в 14.2.25/15.2.3), CVE-2024-46982 (отравление кэша, DoS через `Cache-Control`), CVE-2024-47831 (DoS через Image Optimizer), CVE-2025-49819 (DoS кэша). Сейчас middleware в проекте нет, поэтому CVE-2025-29927 не эксплуатируется напрямую, но любое будущее middleware (админка пресс-службы — в планах, `CONTEXT.md`) унаследует дыру.
- **Фикс:** обновить `next` минимум до 14.2.33 (лучше 15.x), затем `package-lock.json`, `npx tsc --noEmit`, `STATIC_EXPORT=1 npm run build`, регресс-тест экспорта.

### Н2. HIGH — Яндекс.Метрика подключается без проверки согласия из cookie-баннера

- **Место:** `app/layout.tsx:15,27-31` (скрипт `https://mc.yandex.ru/metrika/tag.js` + пиксель `watch/${ym}` при любом заданном `NEXT_PUBLIC_YM_ID`); `components/CookieBanner.tsx:1-27` (флаг `hkoop-cookie` никто не читает).
- **Проверка (инспекция + живой факт):** в `layout.tsx` нет ни одного чтения `hkoop-cookie`; условие — только наличие env-переменной. Живой факт: `GET /` сейчас не содержит `mc.yandex`/`metrika` (0 вхождений в сохранённом HTML) — переменной в окружении нет, утечки сегодня нет. Но счётчик «запланирован» (`CONTEXT.md:65`), а `NEXT_PUBLIC_*` запекается в статику при сборке: первая же прод-сборка со счётчиком включит трекинг до клика «Принять», вопреки тексту баннера. НПА: 152-ФЗ ст. 9, 18.1 и практика Роскомнадзора по cookie.
- **Фикс:** грузить `tag.js` и пиксель только если `lsGet("hkoop-cookie")==="1"` (клиентский компонент-обёртка, по умолчанию выключено); кнопку «Принять» дополнить кнопкой «Отклонить»; смену решения — повторным вызовом баннера из футера.

### Н3. MEDIUM — Виджет Яндекс.Карт грузится каждому посетителю до согласия

- **Место:** `app/contacts/page.tsx:23` (`<iframe src="https://yandex.ru/map-widget/v1/?ll=…">`).
- **Проверка (живая):** `GET /contacts` → 200, в теле вхождения `map-widget`; iframe захардкожен, рендерится безусловно. IP, User-Agent и cookie Яндекса уходят до любого клика по баннеру. НПА: 152-ФЗ ст. 9, 18.1.
- **Фикс:** фасад — статичная картинка + кнопка «Загрузить карту»; создавать iframe только после согласия; добавить `referrerpolicy="no-referrer"`; альтернатива — текстовая ссылка «Открыть в Яндекс.Картах».

### Н4. MEDIUM — Нет защитных заголовков; на статике Pages их нечем отдать

- **Место:** весь сайт. Фактические заголовки `GET /` (`curl -sI /`): только `Cache-Control: no-store, must-revalidate`, `Content-Type`, `Vary`. Нет `Content-Security-Policy`, `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`.
- **Проверка (живая):** перечисленных заголовков нет; в HTML нет `<meta http-equiv>`-компенсаций; сайт можно встроить в чужой iframe (кликджекинг обёртки формы/баннера). Ущерб ограничен (нет авторизации и платежей), поэтому MEDIUM, а не HIGH.
- **Фикс:** для dev/будущего Node-хостинга — `headers()` в `next.config.js` (`Content-Security-Policy` с `frame-ancestors 'self'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy: camera=(), microphone=(), geolocation=()`). Для GitHub Pages заголовки недоступны: `frame-ancestors` через `<meta http-equiv>` не работает по спецификации CSP и не предлагается; вместо этого — `<meta http-equiv="Content-Security-Policy" content="default-src 'self'; script-src 'self' https://mc.yandex.ru; frame-src https://yandex.ru; img-src 'self' data:">` (без `frame-ancestors`) в `layout.tsx` + JS frame-busting на страницах с формой как слабый костыль.

### Н5. MEDIUM — `img src` из БД идут мимо `safeHref`: фото книги почёта и логотипы партнёров

- **Место:** `app/honor/page.tsx:14` (`<img src={h.photo}>`), `components/PartnersStrip.tsx:11` (`<img src={p.logo}>`).
- **Проверка (инспекция + оговорка о данных):** поле из БД попадает в `src` без фильтра: запись вида `https://tracker.evil/p.png` превратит каждую страницу в маяк (IP/UA посетителей третьему лицу без согласия — см. Н2/Н3). Крайний случай: строка `javascript:…` в `src` картинки не исполняется, но ломает рендер; `onError`-вектора в React-пропсах нет, однако сама утечка реальна. Живой рендер сегодня показывает локальные `/images/…`, но без прямого SELECT утверждать безвредность всех строк БД нельзя — требуется проверка из допущений.
- **Фикс:** `src={safeHref(h.photo) ?? "/images/placeholder.png"}` и то же для `p.logo`; для картинок разрешить только site-relative; добавить `referrerPolicy="no-referrer"` и осмысленный `alt` (сейчас у логотипов `alt=""`, у фото — ФИО, это нормально).

### Н6. MEDIUM — PDF-превью в iframe без `sandbox`, внешний https разрешён

- **Место:** `components/DocsFilter.tsx:42,56` (`preview` из `safeHref(d.file_local)`, `<iframe src={preview} …>` без `sandbox`).
- **Проверка (инспекция):** `safeHref` пропускает любой `https://`-URL, поэтому скомпрометированная строка `file_local` откроет чужой сайт в полноразмерном iframe (фишинг «документа»). Живой рендер сегодня показывает локальные `/docs/*.pdf`, но без прямого SELECT полноту гарантировать нельзя.
- **Фикс:** `<iframe sandbox="">` (без `allow-scripts`/`allow-same-origin`), для превью разрешить только site-relative `/docs/*.pdf`; внешние URL — только обычной ссылкой с пометкой внешнего ресурса.

### Н7. MEDIUM — Cookie-баннер: нет отказа, ссылка ведёт не на политику, согласие «продолжением»

- **Место:** `components/CookieBanner.tsx:12-25`.
- **Проверка (инспекция + живая):** одна кнопка «Принять», кнопки «Отклонить» нет; ссылка «политикой конфиденциальности» ведёт на `/docs` (каталог), а не на `/docs/politika.pdf` (файл существует — `GET /docs/politika.pdf` → 200, `application/pdf`); текст «Продолжая, вы соглашаетесь» — implied consent, не явное согласие по ст. 9 152-ФЗ и разъяснениям Роскомнадзора (требуются отдельное действие и возможность отказа; Метрика — аналитическая cookie, а не строго необходимая). НПА: 152-ФЗ ст. 9, 18.1.
- **Фикс:** две кнопки (Принять/Отклонить), прямая ссылка на `/docs/politika.pdf`, хранение выбора (`hkoop-cookie=1/0`), повторный вызов настроек из футера.

### Н8. MEDIUM — Чекбокс согласия в форме без ссылки на политику

- **Место:** `components/ConsultForm.tsx:8-10` («Даю согласие на обработку персональных данных», `required`, но без ссылки и без указания оператора).
- **Проверка (инспекция):** рядом нет ни ссылки на `/docs/politika.pdf`, ни наименования оператора, ни целей обработки. Формальное согласие «вслепую» не соответствует ч. 4 ст. 9 152-ФЗ (субъект должен знать оператора, цель, перечень данных).
- **Фикс:** «Даю согласие на обработку персональных данных [Оператором — Союз ХКООП, цель — обратная связь] согласно <a href="/docs/politika.pdf">Политике</a>»; саму политику дополнить разделом о форме.

### Н9. LOW — Книга почёта публикует персональные данные без описанного регламента согласий

- **Место:** `app/honor/page.tsx:11-22`, таблица `honor` (`db/schema.sql:29-36`: `fio`, `photo`, `text` — полные биографии).
- **Проверка (инспекция):** публикуются ФИО + фото + год + биография 7 человек. Обычная публикация портрета и биографии регулируется ст. 152.1 ГК РФ (изображение гражданина) и ст. 10.1 152-ФЗ (данные, разрешённые для распространения, — согласие по форме Роскомнадзора); ст. 11 152-ФЗ о биометрических ПД здесь неприменима (нет идентификации через биометрическую систему). Самих согласий в репозитории нет (и не должно быть — но должен быть регламент).
- **Фикс:** получить/архивировать согласия на публикацию и распространение (включая фото по ст. 152.1 ГК и ст. 10.1 152-ФЗ) у каждого лица; в инструкцию пресс-службе добавить пункт «без согласия — не публикуем»; по заявлению — снимать карточку в установленный срок.

### Н10. LOW — Версия для слабовидящих есть, но с дефектами доступности

- **Место:** `components/Header.tsx:55-57` (кнопка переключения), `components/ViProvider.tsx:1-46`, `app/layout.tsx:20-21` (skip-link + провайдер), `app/globals.css:203-212` (классы `vi-mode`/`vi-big`/`vi-noimg`).
- **Проверка (инспекция):** наличие подтверждено: кнопка «Версия для слабовидящих» в шапке, `ViProvider` ставит/снимает `body.vi-mode`, сохраняет `hkoop-vi` в localStorage, панель с настройками шрифта и картинок (`vi-big`, `vi-noimg`), skip-link «Перейти к содержанию», CSS-контраст и крупный шрифт. Дефекты: у кнопки нет `aria-pressed` (`Header.tsx:55` — обычный `<button>` без состояния для скринридера); настройки `big`/`noimg` не сохраняются между визитами (в localStorage пишется только `hkoop-vi`, `ViProvider.tsx:19`); панель видна только после включения, повторный вход зависит от localStorage. НПА: ГОСТ Р 52872-2019 (доступность сайтов), опосредованно — требования к удобству для инвалидов.
- **Фикс:** добавить `aria-pressed={vi}` кнопке; сохранять `big`/`noimg` в localStorage; проверить клавиатурную достижимость панели и контраст в `vi-mode`; зафиксировать ручной тест (вкл/выкл, перезагрузка, скринридер).

### Н11. LOW — Форма консультации — немая заглушка: обращения теряются

- **Место:** `components/ConsultForm.tsx:1-14` (используется на `/` — `app/page.tsx:112` — и на `/contacts` — `app/contacts/page.tsx:28`).
- **Проверка (инспекция):** `onSubmit={(e) => e.preventDefault()}` — данные никуда не уходят (это статус прототипа by design, утечки ПДн нет), нет `mailto:`, нет fetch, нет состояний success/error, поля не валидируются (`required` нет ни у одного поля, кроме чекбокса). Пользователь жмёт «Отправить» и видит тишину: обращение исчезает. Это функциональный/UX-дефект, а не уязвимость и не обман по закону о защите прав потребителей.
- **Фикс:** честная заглушка («Форма скоро заработает, звоните 8 (4212) 32-87-18», кнопку переименовать, данные не собирать) либо `mailto:`/бэкенд с явным сообщением «открылся почтовый клиент / заявка принята». Добавить `required`, `maxLength`, `type="tel"`, статус отправки.

## Самопроверка: 5 враждебных сценариев (сделано → сломано → закрыто)

1. **SQL-инъекция в `/news/<id>`.** Ввод `1' OR '1'='1` → связанный параметр, «Не найдено». Не сломано; перечень вызовов исправлен на 11 (ранее было ошибочно 8).
2. **XSS через `?q=` и фильтры.** `<script>`, `<img onerror>`, строки 100+ символов → всё экранировано React; сырого HTML в ответе нет. Не сломано.
3. **Траверс `../`, `%2e%2e`, спецсимволы в id.** Параметр уходит в `WHERE id=?`, файловой операции нет → траверс невозможен. Не сломано.
4. **Включение Метрики без согласия.** Сценарий «завтра добавили `NEXT_PUBLIC_YM_ID`» → трекинг до клика (Н2). Сломано при проверке чтением кода → закрыто фиксом Н2.
5. **Отравление БД (злоумышленник с доступом к phpMyAdmin пишет внешний URL в `partners.url`, `honor.photo`, `documents.file_local`).** `url`/`file_*` режутся `safeHref`, но `photo`/`logo` в `img src` и произвольный https в iframe-превью проходят (Н5, Н6). Сломано → закрыто фиксами Н5/Н6; утверждение о чистоте текущих строк ослаблено до условного до прямого SELECT.

## Вердикт

Показывать людям можно только после Н1–Н2: обновить Next.js и включать Метрику/карту лишь с согласия, затем починить баннер с отказом (Н7), sandbox/фильтр картинок (Н5–Н6) и регламент согласий книги почёта (Н9).
