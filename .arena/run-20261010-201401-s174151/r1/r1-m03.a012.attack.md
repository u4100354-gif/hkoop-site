ATTACK 1 [FATAL] C-4 ложно заявляет единственность дыры, пропуская второй сырой <img src> из БД
Where: a004 С-4: «`app/honor/page.tsx:14` (`<img src={h.photo} ...>` напрямую из БД) — единственное место, где данные из БД уходят в URL-атрибут мимо фильтра»
Problem: Это фактически неверно. Второе такое же место — `components/PartnersStrip.tsx:11`: `<img src={p.logo} ...>` подставляется сырым из БД без `safeHref`, при том что `p.url` строкой ниже (`PartnersStrip.tsx:21`) через фильтр идёт. Контрпример: одна правка через phpMyAdmin `partners.logo = "javascript:alert(1)"` или `data:text/html,...` попадает в разметку доверенного сайта тем же вектором, что описан для `h.photo`. Задача прямо требует проверить «всё, что рендерится из БД», включая партнёров, — половина этого класса пропущена, а заявление о полноте («единственное место») делает вывод о покрытии хранимого XSS недостоверным.

ATTACK 2 [MAJOR] Пропущен iframe-превью PDF без sandbox и без ограничения домена
Where: a004 нигде не упоминает `components/DocsFilter.tsx:50-56` (`<iframe src={preview} ...>`), хотя карта покрытия заявляет «пути PDF, iframe-превью — проверено»
Problem: Задача требует: «хранимый (всё, что рендерится из БД: ... пути PDF, iframe-превью ...)». По коду `DocsFilter.tsx:42` `setPreview(safeHref(d.file_local)!)`, а `safeHref` (`lib/url.ts:3-9`) режет только схему — любой `https://` проходит. Контрпример: `file_local=https://evil.example/phish.html` проходит фильтр и открывается в iframe внутри оформления сайта под заголовком «Просмотр PDF» без `sandbox`, без allowlist site-relative `/docs/*.pdf`. Находки об этом нет, фикс (пустой `sandbox`, внешний домен — новой вкладкой) не предложен.

ATTACK 3 [MAJOR] Фикс С-3 (`headers()` в next.config.js) не работает на заявленном проде
Where: a004 С-3: «в `next.config.js` добавить `headers()` для всех роутов ... Учли прод-статику: для GitHub Pages заголовки задаются meta/`_headers`-аналогами»
Problem: Прод по задаче — «статический экспорт (Next `output: export`) на GitHub Pages», что подтверждено `next.config.js:6-7`. `headers()` в next.config.js при `output: export` игнорируется (заголовки отдаёт статический хостинг, а не Next-сервер). Замена «meta-аналогами» не эквивалентна: у `X-Frame-Options` вообще нет meta-эквивалента, `frame-ancestors` в `<meta http-equiv="Content-Security-Policy">` игнорируется браузерами, GitHub Pages не читает `_headers`. Пользователь не может применить фикс как написано для прод-URL; проверка `curl -I` прод-URL после такого «фикса» ничего не изменит. Это VAGUE + BREAKS на проде.
