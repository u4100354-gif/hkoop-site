ATTACK 1 [FATAL] M1-фикс не закрывает заявленную утечку трекинга
Where: a011 «M1. MEDIUM» — «Фикс: `h.photo` и `p.logo` через `safeHref`», при «Факт: … скрытый трекинг (IP/UA третьему лицу без согласия)»; `lib/url.ts:7` — `if (/^(https?:\/\/|\/[^/\\])/i.test(v)) return v;`
Problem: `safeHref` пропускает любой https-домен, поэтому контрпример `p.logo="https://tracker.evil/pixel.png"` проходит фильтр и трекинг сохраняется. Фикс не достигает собственной цели; для неё нужен allowlist доменов (что у a011 вынесено в другой пункт M7), а не голый `safeHref`.

ATTACK 2 [FATAL] M6-фикс не работает на статическом проде и не чинит кликджекинг
Where: a011 «M6. MEDIUM» — «Фикс: заголовки через `headers()` в `next.config.js` для dev; для статического прода — минимум `<meta http-equiv="Content-Security-Policy">`»
Problem: прод — статический экспорт (`output: export` на GitHub Pages): `headers()` из `next.config.js` там игнорируется, а CSP через `<meta http-equiv>` по спецификации игнорирует `frame-ancestors` (и report/sandbox). То есть заявленная угроза «сайт встраивается в чужой iframe (кликджекинг)» этим фиксом на проде не закрывается. Фикс неприменим к цели, которую сам ставит.

ATTACK 6 [MINOR] Живые утверждения M1/M2/M6 без повторяемой команды и вывода
