ATTACK 1 [FATAL] Недопустимая severity INFO ломает ranked-список
Where: `### 12. INFO — ...`, `### 13. INFO — ...` в r0/a014.md:95-107
Problem: задача требует «каждая с severity (CRITICAL / HIGH / MEDIUM / LOW)». INFO в таксономии нет. Пользователь (председатель/разработчик) не может отсортировать «от важного к мелкому», если два пункта вне шкалы; это нарушение формата отчёта, а не мелочь.

ATTACK 2 [FATAL] Ложный «хранимый XSS» через <img src=data:text/html>
Where: находка 5: «хранимый XSS второго порядка (`data:text/html`, внешний трекер в `src`)" (r0/a014.md:54)
Problem: `<img src="data:text/html,...">` не исполняется браузером как HTML/JS — это битая картинка, а не выполнение скрипта. SVG через `<img>` тоже без скриптов, `javascript:` в `src` не выполняется (что автор сам признаёт строкой выше). Контрпример: ` <img src="data:text/html,<script>alert(1)</script>"> ` — алерта нет ни в одном современном браузере. Реальный остаточный риск — дефейс/трекинг, а не XSS; severity и факт завышены неверной механикой.

ATTACK 5 [MAJOR] Фикс security-заголовков неработоспособен для заявленного прода
Where: находка 6, «Фикс: добавить `headers()` в `next.config.js` ... для GitHub Pages — `<meta http-equiv>`-минимум» (r0/a014.md:62)
Problem: прод по задаче — «статический экспорт (Next `output: export`) на GitHub Pages». `headers()` в next.config игнорируется при `output: export` (нет сервера), а `<meta http-equiv>` не может выставить `X-Frame-Options` / `Permissions-Policy`. Проверка делалась на dev (`localhost:3100`), а фикс подаётся как закрытие для прода — разработчик не сможет им воспользоваться, кликджекинг на Pages останется.

ATTACK 6 [MAJOR] У находок нет требуемых команды и вывода проверки
Where: находка 2 («инспекция + сверка с бюллетенями», без команды/вывода, r0/a014.md:34); находка 1 («команда `git ls-files | findstr README` показывает файл в индексе» — вывод не приведён, r0/a014.md:28); находка 5 («Живой `/honor` сейчас отдаёт локальные картинки — чисто» — команды и вывода нет, r0/a014.md:54)
Problem: задача требует для КАЖДОЙ находки «проверкой (инспекция кода или живой probe с командой и выводом)». Без команды+вывода проверка невоспроизводима: председатель не отличит факт от мнения, разработчик не повторит. Минимум три находки (включая оба HIGH) условию не удовлетворяют.
