# Аудит сайта ХКООП: безопасность и соответствие законам РФ (включая 152-ФЗ)

Дата: 10.10.2026. Объект: `hkoop-site`, ветка `backup-2026-10-10` (рабочее дерево как есть), Next.js 14.2.5 + React 18 + MariaDB `hkoop`. Живые пробы — только безопасные GET к `http://localhost:3100` и `http://127.0.0.1:8081`. Проект не менялся. Секреты не печатаются.

## Допущения

- Dev-сервер на `:3100` собран из того же дерева, что и прод-экспорт (разница только в `STATIC_EXPORT`), поэтому выводы по коду переносимы на прод.
- Поиск реализован парой `components/HeaderSearch.tsx` + `app/search/page.tsx`; проверены оба.
- Содержимое `public/docs/politika.pdf` по существу (полнота политики) и точная версия phpMyAdmin не аудировались — проверены доступность, ссылка и факт логина.
- CVE-номера по `next` ниже — по публичным бюллетеням безопасности; сеть для перепроверки была недоступна, поэтому номера маркированы как требующие подтверждения командой `npm audit` при наличии сети. Локально повторяемо проверены только пин версии и отсутствие middleware/API.

## Что проверено и держится (ранее исправленное — как новое не засчитывается)

- Все вызовы `q()` — статические строки без конкатенации; единственный параметр (`app/news/[id]/page.tsx:17`, `WHERE id=?`) идёт через placeholder. Живой probe `/news/1' OR '1'='1` → 200 «Не найдено», без ошибок БД.
- `lib/url.ts` (allowlist `http(s)` + site-relative) применён ко всем href из БД (партнёры, соцсети) и к iframe-превью PDF.
- `poweredByHeader: false` (`next.config.js:5`); живой probe `/` → заголовка `X-Powered-By` нет.
- `/.env.local` → 404, `/package.json` → 404, `/.env.example` → 404.
- Отражённый XSS в `/search?q=`: payload `<script>alert(1)</script>` вернулся экранированным (`value="&lt;script&gt;alert(1)&lt;/script&gt;"`), кавычки — как `&quot;`; скрипт не исполняется (React-эскейпинг + `defaultValue`). В `HeaderSearch` нет `innerHTML`.
- Несуществующий `/news/nonexistent-xyz-123` и траверс `/news/%2e%2e%2f..%2fetc%2fpasswd` → штатная страница «Не найдено», без стектрейсов и деталей SQL.
- API-роутов нет (`app/**/route.ts` — пусто), мутаций из клиента нет.
- phpMyAdmin `http://127.0.0.1:8081/` отвечает страницей входа (требует логин).
- Импринт есть: адрес, телефон, email и наименование союза — в `components/Footer.tsx:6-11` и на `/contacts` (живой probe подтверждает).
- Cookie-баннер и чекбокс согласия в форме есть; политика доступна: `/docs/politika.pdf` → 200 `application/pdf`. Версия для слабовидящих работает (переключатель в шапке, классы `vi-mode`/`vi-big`/`vi-noimg` в `app/globals.css:206-212`, skip-link в `app/layout.tsx:20`).
- Данные в БД сейчас чистые: все `partners.url/logo`, `honor.photo`, `documents.file_*` соответствуют allowlist (проверено `SELECT`, посторонних схем нет).
- `app/page.tsx:52` (`alt=""` у новостных миниатюр) — не нарушение: `img` лежит в `div.thumb`, а ссылка — отдельно в `h3 > a` (`app/page.tsx:57`); пустой alt у декоративного дубля заголовка — корректный паттерн, дублирующий alt был бы хуже. Аналогично `app/honor/page.tsx:14` (`alt={h.fio}`) корректен.

### F4. HIGH — Next.js 14.2.5 ниже security-фиксов ветки (гигиена, требует перепроверки по сети)

- **Место:** `package.json:12` (`"next": "14.2.5"`, август 2024).
- **Проверка (инспекция, повторяемо локально):** команда `grep '"next"' package.json` → `"next": "14.2.5"`; команда `grep -rn "middleware" app middleware.ts 2>/dev/null` → пусто (middleware нет); команда `ls app/**/route.ts` → файлов нет (API-роутов нет). Синтез: оставить HIGH как гигиену, а не как пожар, — чинить плановым обновлением, а не ночью.
- **Фикс (не применять):** обновить `next` до свежего 14.2.x (или 15.x) + `npm audit fix`, включить Dependabot/регулярный `npm audit` перед сборкой.

### F6. MEDIUM — Форма консультации вводит в заблуждение: согласие «в никуда» и молчаливая кнопка (нарушения ст. 9 152-ФЗ сейчас нет)

### F8. MEDIUM — Нет заголовков безопасности; на GitHub Pages кликджекинг заголовками неустраним

- **Место:** ответ `/` (живой probe): `Content-Security-Policy`, `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `HSTS` — отсутствуют; `Cache-Control: no-store, must-revalidate`.
- **Проверка:** живой probe заголовков `/` подтверждает отсутствие перечисленных заголовков.
- **Компромисс — честно:** «за»: без CSP/X-Frame-Options сайт можно встроить в чужой iframe (кликджекинг обёртки) и грузить что угодно откуда угодно. «Против»: GitHub Pages не отдаёт кастомные заголовки, а на сайте нет авторизации и денежных действий — ущерб от кликджекинга низкий. Синтез: MEDIUM. Отдельно честно: `frame-ancestors` через `<meta http-equiv>` не работает (браузеры игнорируют эту директиву в meta, она действует только в HTTP-заголовке), поэтому выдавать meta за замену заголовка от кликджекинга нельзя.
- **Фикс (не применять):** `<meta http-equiv="Content-Security-Policy" content="default-src 'self'; script-src 'self' https://mc.yandex.ru; frame-src 'self' https://yandex.ru">` (уточнить под фактуру; без `frame-ancestors` — его в meta не ставить), iframe карты — с минимальным `sandbox`; полный набор заголовков (включая `frame-ancestors 'self'` / `X-Frame-Options`) — только при переезде на хостинг с настраиваемыми заголовками; до тех пор риск кликджекинга фиксировать как принимаемый (низкий ущерб: нет авторизации/платежей).

## Что прямо НЕ является проблемой (чтобы не чинили зря)

- Параметризация SQL — везде, включая `news/[id]`; «SQL-инъекция в `q()`» отсутствует как класс.
- Отражённый XSS через `?q=` и фильтры — экранируется React; `javascript:`/`data:` в href/iframe из БД режутся `safeHref`.
- Инъекции путей (`../`, `%2e%2e`) в `/news/<id>` — id идёт только параметром в SQL и никогда в файловую систему.
- Партнёрские ссылки — информационные (ФНПР, правительство края, фонды, вузы, надзор), признаков скрытой рекламы нет; маркировка (erid) не требуется.
- Импринт по ст. 10 Закона № 149-ФЗ (наименование, адрес, телефон, email) — присутствует.
- Пустой `alt` новостных миниатюр (`app/page.tsx:52`) — корректный декоративный паттерн, а не дефект доступности.
