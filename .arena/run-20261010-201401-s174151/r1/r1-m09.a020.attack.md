ATTACK 1 [FATAL] Ложное "только статические строки" про dangerouslySetInnerHTML
Where: a009.md п.7: "`dangerouslySetInnerHTML` используется только со статическими строками (`app/layout.tsx:19,29`)".
Problem: это фактически неверно. `app/layout.tsx:29` интерполирует переменную окружения прямо в инлайн-скрипт: ``ym(${ym},"init",{clickmap:true,...})`` где `const ym = process.env.NEXT_PUBLIC_YM_ID` (строка 15). Второй sink — `app/layout.tsx:30` `<img src={`https://mc.yandex.ru/watch/${ym}`}>`. Значение не валидируется (`/^\d+$/` нет, `JSON.stringify` нет). Контрпример: `NEXT_PUBLIC_YM_ID=1);alert(1);//` собирается в скрипт `ym(1);alert(1);//,"init",...)` — классический sink. Переменная серверная, поэтому не REFLECTED-XSS от `?q=`, но утверждение "только статические" снимает с рассмотрения единственный нестатический sink в проекте и прямо противоречит требованию задачи проверять "всё, что рендерится" и XSS.

ATTACK 5 [MAJOR] Фикс HIGH-3 (`headers()` в next.config.js) не работает в проде-статике
Where: a009.md HIGH-3 Фикс: "добавить `async headers()` в `next.config.js` (для dev/прод-сервера) и/или `<meta http-equiv>`".
Problem: прод по условию задачи — "статический экспорт (Next `output: export`) на GitHub Pages". `headers()` игнорируется при `output: export` (в проекте ветка `isExport` в `next.config.js:6-7` вообще не содержит `headers`/`redirects`). Контрпример: `STATIC_EXPORT=1 npm run build` — кастомные заголовки из `headers()` в `.next-export/*.html` не попадут, на GitHub Pages их отдавать нечему. Отчёт сам фиксирует "прод — статический экспорт" в допущениях, но продаёт dev-фикс как закрытие сайт-wide находки без указания, что для прода нужен уровень хостинга/CDN. Пользователь применит рецепт и не получит защиты в проде.

ATTACK 6 [MINOR] MEDIUM-1 завышает эксплуатацию: SVG-JS и onError-векторы через img
Where: a009.md MEDIUM-1: "`data:image/svg+xml` с JS, `onError`-векторы через битые URL ... — реальны".
Problem: неверный exploit-анализ. SVG, загруженный через `<img src>`, по спецификации не исполняет скрипты (контрпример: `<img src="data:image/svg+xml,<svg onload=alert(1)>">` — alert не срабатывает). `onError` в `components/PartnersStrip.tsx:11` — захардкожен `onError={() => setErr(true)}`, а не контролируется значением из БД; битый URL лишь гасит логотип, а не выполняет код атакующего. В `app/honor/page.tsx:14` обработчика `onError` вообще нет. Ядро находки (два `img src` мимо `safeHref`) верно, но описанный механизм XSS нереализуем и завышает severity-обоснование.

ATTACK 7 [MINOR] LOW-3 выдаёт dev-артефакты за находку без места и проверки на экспорте
Where: a009.md LOW-3: "Раскрытие структуры Next.js в HTML (`self.__next_f`, имена чанков) + `Cache-Control: no-store` на всё".
Problem: оба симптома — дефолты `next dev` на `http://localhost:3100` (flight-пейлоад и `no-store`), в статическом экспорте `.next-export` flight-мусора нет.
