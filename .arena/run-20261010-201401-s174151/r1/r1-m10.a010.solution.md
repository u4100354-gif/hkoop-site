# Аудит сайта ХКООП: безопасность и законы РФ (включая 152-ФЗ)

Дата: 10.10.2026. Аудит по рабочему дереву ветки `backup-2026-10-10` как есть, проект не менялся, БД — только чтением через HTTP-рендер и инспекцией кода (записи/GRANT-запросы не выполнялись). Живые пробы — только безопасные GET к `http://localhost:3100` и `http://127.0.0.1:8081`. Секреты не печатаются.

## Сквозной пример (образец проверки)

Беру cookie-баннер против трекеров от кода до живого поведения. Код: `components/CookieBanner.tsx:12-24` обещает «сайт использует cookie и Яндекс.Метрику. Продолжая, вы соглашаетесь», флаг — `localStorage hkoop-cookie`. Но `app/layout.tsx:27-31` встраивает Метрику при любом `NEXT_PUBLIC_YM_ID` без проверки согласия, а `app/contacts/page.tsx:23` всегда грузит `iframe https://yandex.ru/map-widget/...`. Пробы:

```
curl.exe -s "http://localhost:3100/contacts" → 200, фрагмент тела:
<iframe src="https://yandex.ru/map-widget/v1/?ll=135.0711%2C48.4739..."> (есть до клика по баннеру)
curl.exe -s "http://localhost:3100/" → 200, подстроки mc.yandex/metrika отсутствуют (счётчик не задан — повезло, но ветка кода безусловна)
```

Вывод: разрыв между текстом согласия и фактической загрузкой сторонних ресурсов — главный класс проблем сайта. Остальные находки проверены так же: цитата + команда и вывод.

## Что проверено и держится (не находки)

- SQL: все `q()` параметризованы; `app/news/[id]/page.tsx:17` — `WHERE id=?`. Проба `curl.exe -s "http://localhost:3100/news/nonexistent-id-xyz"` → 200, тело содержит `<h1>Не найдено</h1>`, стектрейса/Traceback нет. `GET /news/%2e%2e%2f` → 404-страница Next, без ошибок.
- `lib/url.ts:3-9` — allowlist `https?://` и site-relative; `javascript:`/`data:`/`//evil` → null. Партнёрские `href` (`PartnersStrip.tsx:21`), соцсети (`contacts/page.tsx:9-11`) идут через `safeHref`.
- `.env.local` по HTTP: `curl.exe -s -o NUL -w "%{http_code}" "http://localhost:3100/.env.local"` → `404`, тело — стандартная 404-страница Next (`404: This page could not be found.`). Заголовка `X-Powered-By` нет (`poweredByHeader: false`, `next.config.js:5`; проверка `curl.exe -s -D - -o NUL http://localhost:3100/` показывает только `HTTP/1.1 200 OK`, без `X-Powered-By/CSP/X-Frame-Options`).
- Отражённый XSS в поиске закрыт: `curl.exe -s "http://localhost:3100/search?q=%3Cscript%3Ealert(1)%3C/script%3E"` → 200, в теле `value="&lt;script&gt;alert(1)&lt;/script&gt;"`, сырого `<script>alert(1)</script>` нет; RSC-поток несёт `\u003cscript\u003e` (экранировано). Рендер — текстовые узлы React (`app/search/page.tsx:42`, `components/HeaderSearch.tsx:65-67`), `dangerouslySetInnerHTML` с пользовательскими данными нигде нет (только `app/layout.tsx:19` статика и `:29` env, см. находку 9).
- API-роутов нет (`app/api/**` отсутствует), `middleware.*` отсутствует, мутаций нет — формы клиентские. `public/docs/politika.pdf`: `curl.exe -s -o NUL -w "%{http_code} %{content_type}" .../docs/politika.pdf` → `200 application/pdf`.
- phpMyAdmin закрыт логином: `curl.exe -s "http://127.0.0.1:8081/"` → 200, тело — страница входа (`<title>phpMyAdmin</title>`, `<body id=loginform>`, `auth_type:"cookie"`, `logged_in:false`, версия 5.2.2). Без пароля данные недоступны.
- Хранимые тексты из БД безопасны при текущем коде: `{h.fio}`, `{h.title || h.text}` (`app/honor/page.tsx:18-19`), `{p.name}` (`PartnersStrip.tsx:12`), `{n.title}`/`{n.excerpt}` — JSX-текст, React экранирует; `dangerouslySetInnerHTML` с данными БД нет ни одного (grep по `app/ components/` даёт только `layout.tsx:19,29`). Вредонос вида `<img src=x onerror=...>` в `honor.text` ушёл бы в текст, а не в исполнение. Открыта только `img src`-граница (находка 8).

## Ranked-список находок

### 1. HIGH — Пароли БД лежат в git: `db/README.md`
- Место: `db/README.md:8-12` + `.gitignore:1-8` (файл не исключён).
- Проверка (инспекция): `CONTEXT.md:4` требует «пароли только в `db/README.md` и `.env.local` (не коммитить)», но `db/README.md` — коммитимый файл, репозиторий публичный. Цитата содержимого не приводится (секрет), факт — логин/пароль root и пользователя в открытом тексте.
- Фикс (без применения): сменить оба пароля в MariaDB; вычистить файл и историю (`git filter-repo`/BFG), добавить `db/README.md` в `.gitignore`, в репозитории оставить только шаблон без значений.

### 2. HIGH — Устаревший Next.js 14.2.5 с известными CVE
- Место: `package.json:12` (`"next": "14.2.5"`).
- Проверка (инспекция + бюллетени): открыты CVE-2025-29927 (обход через `x-middleware-subrequest`, испр. в 14.2.25), CVE-2024-46982/CVE-2024-39332 (cache-poisoning/DoS, испр. в 14.2.9+), CVE-2025-55182 (RCE через RSC, испр. в 14.2.33, дек. 2025). Смягчает: `middleware.*` отсутствует, прод — статика; dev-сервер и будущий SSR уязвимы.
- Фикс: обновить `next` до последнего 14.2.x (14.2.33+), `npx tsc --noEmit`, пересобрать экспорт.

### 3. MEDIUM — Пользователь БД с избыточными правами (`db/README.md`: «все права»)
- Место: `db/README.md:11` («hkoop ... (все права на базу hkoop)»), использование — `lib/db.ts:3-11` (пул от имени `hkoop`).
- Проверка (инспекция; прямых GRANT-запросов к БД не делалось по ограничениям): сайт выполняет только SELECT через `q()`, но учётка, по документации, имеет ALL PRIVILEGES на `hkoop` — нарушение принципа наименьших привилегий. При компрометации ключа из `.env.local` атакующий получит запись/удаление.
- Фикс: `REVOKE ALL ...; GRANT SELECT ON hkoop.* TO 'hkoop'@...`, CRUD — отдельной учётке будущей админки; зафиксировать гранты в `db/schema.sql` комментарием.

### 4. MEDIUM — Трекеры грузятся без согласия: карта на «Контактах», Метрика по коду безусловна
- Место: `app/contacts/page.tsx:23`, `app/layout.tsx:27-31`, `components/CookieBanner.tsx:5-27`.
- Проверка (код + probe): `curl.exe -s "http://localhost:3100/contacts"` → 200, тело содержит `<iframe src="https://yandex.ru/map-widget/v1/...` до любого согласия. `curl.exe -s "http://localhost:3100/"` → подстрок `mc.yandex.ru` нет (счётчик не задан), но ветка `layout` проверяет только наличие `NEXT_PUBLIC_YM_ID`, флаг `hkoop-cookie` не читается. НПА: ст. 9, 18–18.1 Федерального закона от 27.07.2006 № 152-ФЗ (обработка только с согласия, информирование); ст. 10.1 Федерального закона от 27.07.2006 № 149-ФЗ и практика Роскомнадзора по cookie (отказ так же лёгок, как согласие).
- Фикс: грузить iframe карты (клик-заглушка «показать карту») и скрипт/пиксель Метрики только после согласия; без согласия — ни одного запроса к `yandex.ru`/`mc.yandex.ru`.

### 5. MEDIUM — Баннер: нет кнопки «Отклонить», флаг в localStorage, ссылка ведёт не на политику
- Место: `components/CookieBanner.tsx:11-25` (только «Принять», `href="/docs"`).
- Проверка (инспекция; баннер клиентский, в SSR отсутствует — рендерится после `lsGet`): отказа в один клик нет; флаг в `localStorage`, а не в cookie (серверный учёт невозможен); ссылка ведёт на каталог, а не на `/docs/politika.pdf`. НПА: ст. 9 152-ФЗ (согласие должно быть конкретным, отказ — равнодоступным); разъяснения Роскомнадзора о недопустимости «согласия продолжением пользования».
- Фикс: добавить «Отклонить», писать выбор в cookie (`SameSite=Lax`, срок), ссылку — прямо на `/docs/politika.pdf`, перечислить цели (аналитика/карта).

### 6. MEDIUM — Форма консультации вводит в заблуждение, согласие не по ч. 4 ст. 9 152-ФЗ
- Место: `components/ConsultForm.tsx:1-14` (`onSubmit={(e) => e.preventDefault()}`, чекбокс стр. 9 — голый текст), используется в `app/page.tsx:112`, `app/contacts/page.tsx:28`.
- Проверка (инспекция + проба): `curl.exe -s "http://localhost:3100/contacts"` → тело содержит `<form class="consult-form">` с кнопкой «Отправить» без success/error-состояний; обработчик только `preventDefault` — данные молча теряются (в `CONTEXT.md:62` упомянута mailto-заглушка, в коде её нет). Текст согласия не содержит элементов ч. 4 ст. 9 152-ФЗ (наименование оператора, цель, перечень данных, срок). Смягчает: данные никуда не уходят (минимизация по факту). НПА: ч. 4 ст. 9, ст. 18–18.1 152-ФЗ.
- Фикс: убрать форму до бэкенда (оставить телефон/email/часы) либо честно подписать «демо» + `mailto:`; добавить ссылку на `/docs/politika.pdf` и полный текст согласия (оператор — Союз ХКООП, цель — обратная связь, состав — имя+контакт+вопрос, срок), `maxLength` полям, состояния success/error.

### 7. MEDIUM — Нет защитных заголовков; сайт встраивается в чужой iframe (кликджекинг)
- Место: `next.config.js:1-27` (секции `headers` нет); живой ответ `/`.
- Проверка: `curl.exe -s -D - -o NUL "http://localhost:3100/"` → только `HTTP/1.1 200 OK`, нет `Content-Security-Policy`, `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `HSTS`. Iframe-защита отсутствует — форму/баннер можно встроить.
- Фикс (без применения, с учётом статики): для dev/SSR — `headers()` (`frame-ancestors 'self'` из заголовка, `nosniff`, `Referrer-Policy`, минимальная CSP с `script-src 'self' 'unsafe-inline' https://mc.yandex.ru` — `'unsafe-inline'` оставлен сознательно, иначе заблокируются собственные инлайн-скрипты `layout.tsx:19,29`; долгосрочно — хеши и отказ от `'unsafe-inline'`). Для GitHub Pages (статика, кастомных заголовков нет): честно зафиксировать, что `frame-ancestors` через `<meta http-equiv>` не работает (директива игнорируется в meta по спецификации CSP) и кликджекинг там заголовками не закрыть — риск низкий (кабинетов/секретов нет); дать meta-CSP без `frame-ancestors`. Cloudflare-правила — только если сайт реально за Cloudflare.

### 8. LOW — `safeHref` покрывает `href`/соцсети, но не `img src` из БД (`honor.photo`, `partners.logo`)
- Место: `app/honor/page.tsx:14` (`<img src={h.photo}>`), `components/PartnersStrip.tsx:11` (`<img src={p.logo}>`); ср. `:21` где `href` фильтруется.
- Проверка (инспекция): React экранирует атрибуты, `javascript:` в `img src` современные браузеры не исполняют — поэтому LOW. Остаточный риск: трекинг-пиксель/подмена от привилегированного редактора БД (доступ через phpMyAdmin по инструкции).
- Фикс: пропускать `h.photo`/`p.logo` через `safeHref` (site-relative + `https:`), при `null` — плейсхолдер.

### 9. LOW — `NEXT_PUBLIC_YM_ID` интерполируется в inline-скрипт без проверки формата
