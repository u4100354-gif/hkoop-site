Аудит по рабочему дереву ветки `backup-2026-10-10` как есть. Проект не менялся (ни файлы, ни БД кроме чтения, ни git, ни пакеты, ни процессы). Секреты не печатаются. Живые пробы — только безопасные GET к `http://localhost:3100` и `http://127.0.0.1:8081`. Отчёт на русском.

## Ranked-список находок (новое)

### HIGH-1. Next.js 14.2.5 содержит известные критические CVE (особенно CVE-2025-29927)
- Место: `package.json` (`"next": "14.2.5"`).
- Проверка: инспекция кода + сверка с открытыми бюллетенями. Версия августа 2024, младше исправлений линейки 14.2.x: CVE-2025-29927 (обход middleware-авторизации, CVSS ~9.1, исправлено в 14.2.25 / 15.2.3), плюс бюллетени по кэшу/Server Functions для 14.x; для React-экосистемы — CVE-2025-55182 (RSC, декабрь 2025). Смягчает: своего `middleware.*` и API-роутов в проекте нет (glob пуст), прод — статический экспорт, поэтому прямого обхода авторизации нечему бить. Остаток: права mysql-пользователя (`DB_USER=hkoop` из `.env.example:3`, пароль только в `.env.local`) не подтверждены выводом `SHOW GRANTS` — не выполнялся из-за ограничения «только SELECT».
- Факт: dev-сервер и сборочный конвейер крутят уязвимый рантайм; любой будущий middleware/API унаследует дыру; сканеры красят сборку в красное.
- Фикс: обновить `next` минимум до последней 14.2.x (14.2.25+), прогнать `npx tsc --noEmit`, пересобрать экспорт, затем плановый переезд на поддерживаемую ветку; `react/react-dom 18.3.1` и `mysql2 ^3.24.5` проверить через `npm audit`; отдельно выполнить (админу БД, чтением) `SHOW GRANTS FOR 'hkoop'@...` и урезать до минимума (только нужные `SELECT` на базу `hkoop`, без `GRANT/FILE/SUPER`).

### HIGH-2. Яндекс.Метрика в layout подключается безусловно, без проверки согласия
- Место: `app/layout.tsx:15,27-31`.
- Проверка: инспекция кода + живой probe. Сейчас `NEXT_PUBLIC_YM_ID` не задан (в `.env.example:6` закомментирован), probe `/contacts` не нашёл `ym()/metrika` — счётчик молчит. Но код `ym && (...)` вставляет скрипт `https://mc.yandex.ru/metrika/tag.js` сразу при наличии ID, а `CookieBanner.tsx:7-9,17-22` лишь пишет флаг `hkoop-cookie` в localStorage, который серверный `layout` никогда не читает. Стоит задать ID — Метрика поедет до клика «Принять».
- НПА: 152-ФЗ ст. 9 (согласие), ст. 18 (информирование); требования о cookie-согласии; позиция Роскомнадзора о метрике как обработке ПДн.
- Фикс: грузить скрипт Метрики только после согласия — клиентская обёртка читает `hkoop-cookie`, при отсутствии не вставляет скрипт и `noscript`-пиксель; поведение при недоступном localStorage — считать «нет согласия».

### HIGH-3. Яндекс-карта на /contacts грузится безусловно до согласия (тот же класс, что HIGH-2)
- Место: `app/contacts/page.tsx:23` (`<iframe src="https://yandex.ru/map-widget/v1/?ll=...">`).
- Проверка: живой probe `curl.exe -s http://localhost:3100/contacts` → в теле `src="https://yandex.ru/map-widget/v1/?ll=135.0711%2C48.4739..."` до любого клика «Принять»; флаг `hkoop-cookie` нигде не читается. Раньше ошибочно помечалось «ок».
- НПА: 152-ФЗ ст. 9 (согласие на обработку, IP/User-Agent уходят третьему лицу), ст. 18; текст баннера обещает согласие, фактически передача идёт сразу.
- Фикс: заменить iframe на заглушку-кнопку «Показать карту» (click-to-load): iframe создавать только после согласия/клика; добавить `loading="lazy"` и ссылку на политику рядом; статичный доверенный хост оставить.

### HIGH-4. Нет security-заголовков: CSP, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, HSTS
- Место: `next.config.js` (нет блока `headers()`), `app/layout.tsx`.
- Проверка: живой probe `curl.exe -sI http://localhost:3100/` → только `Vary`, `Cache-Control: no-store, must-revalidate`, `Content-Type`. Нет `Content-Security-Policy`, `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Strict-Transport-Security`.
- Факт: сайт уязвим к кликджекингу, MIME-sniffing и подстановке сторонних скриптов. Уточнение к прежнему рецепту: `async headers()` в `next.config.js` работает только для dev/Node-сервера и игнорируется при `output: export` (в ветке `isExport`, `next.config.js:6-7`, заголовков нет) — на GitHub Pages его отдавать нечему.
- Фикс (с учётом статики): для dev/серверного режима — `async headers()` в не-экспортной ветке; для прода-экспорта — `<meta http-equiv>` (`X-Content-Type-Options` через meta не ставится — выставить на уровне хостинга/CDN Pages: `X-Frame-Options: DENY` / `frame-ancestors 'none'`, `nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, базовый CSP `default-src 'self'; img-src 'self' data: https:; script-src 'self' https://mc.yandex.ru; frame-src https://yandex.ru`); HSTS — на уровне хостинга при HTTPS.

### MEDIUM-1. `img src` из БД не проходят `safeHref`: логотипы партнёров и фото книги почёта
- Место: `components/PartnersStrip.tsx:11` (`<img src={p.logo}>`), `app/honor/page.tsx:14` (`<img src={h.photo}>`). Ссылки там же фильтруются (`PartnersStrip.tsx:21`).
- Проверка: инспекция кода + чтение текущих значений: все `partners.logo` — вида `/images/...`, все `honor.photo` — `/images/honor/...` (benign). Сегодня эксплуатации нет, но правка через phpMyAdmin может положить внешний URL. Исправление прежней ошибки: SVG, загруженный через `<img src>` (включая `data:image/svg+xml`), скрипты не исполняет; `onError` в `PartnersStrip.tsx:11` захардкожен (`() => setErr(true)`) и значением из БД не контролируется, в `honor/page.tsx:14` его нет — «SVG-JS/onError-инъекция» как XSS-механизм нереализуема.
- Факт (действительный остаток): внешний URL в `src` — трекер и утечка `Referer` на чужой хост + подмена картинки (фишинг/дефейс контента).
- Фикс: пропускать `p.logo` и `h.photo` через `safeHref` (убедившись, что фильтр не режет кириллицу/пробелы — в БД есть `Скакун_1.jpg`, `Сушко_Г.jpg`), при `null` — плейсхолдер как уже сделано для пустого фото; при желании — allowlist доверенных хостов картинок.

### MEDIUM-4. Iframe предпросмотра PDF без `sandbox`; preview-URL зависит только от `safeHref`
- Место: `components/DocsFilter.tsx:56` (`<iframe src={preview}>` без `sandbox`).

### MEDIUM-5. `NEXT_PUBLIC_YM_ID` интерполируется в инлайн-скрипт без валидации (раньше описывалось как «только статика»)
- Место: `app/layout.tsx:15,29-30` (`ym(${ym},"init",...)`, `watch/${ym}`).
- Проверка: инспекция кода. Значение не проверяется (`/^\d+$/` нет, `JSON.stringify` нет). Контрпример: `NEXT_PUBLIC_YM_ID=1);alert(1);//` собрался бы в `ym(1);alert(1);//,"init",...)`. Эксплуатация — только через контроль окружения сборщиком/оператором (не посетителем сайта), пользовательского reflected-XSS здесь нет.
- Фикс: валидировать `ym` как `/^\d+$/` (иначе не рендерить блок), либо подставлять через `JSON.stringify(ym)`; в `.env.example:6` держать закомментированным до гейта согласием (HIGH-2).

### LOW-1. Внешние ссылки партнёров: `rel="noreferrer"` без явного `noopener`, любой `https://` разрешён
- Место: `components/PartnersStrip.tsx:29`, `app/page.tsx`, `lib/url.ts:7`.
- Проверка: инспекция кода. Современные браузеры трактуют `noreferrer` как `noopener`, но явного `noopener` нет; `safeHref` пропускает любой `https://`. Один URL — IDN `https://хабаровсккурорт.рф/` — легитимен, опечатки в таких доменах вероятны.
- Фикс: `rel="noreferrer noopener"`, при желании — allowlist доверенных доменов партнёров поверх `safeHref`.

### LOW-2. `safeHref` не нормализует IDN; `docHref`-фолбэк клеит `habprof.ru + old_url` без валидации origin
- Место: `lib/url.ts:3-9`, `app/page.tsx`.
- Проверка: инспекция кода. Лимит 2000 и trim есть; не-ASCII пути при прогоне через фильтр могут вести себя неожиданно; `old_url` проверяется только на `startsWith("/")`, хотя React экранирует его в атрибуте — реальной дыры сегодня нет.
- Фикс: нормализовать через `encodeURI` + IDN→punycode на вставке; фолбэк строить через `new URL(old_url, "https://habprof.ru")` с проверкой `origin`.

- **Импринт (ст. 10 149-ФЗ):** адрес, телефон, email, часы в `Header.tsx:52-54` и `Footer` — соответствует.
- **Версия для слабовидящих (ГОСТ Р 52872-2019):** есть и работает (`ViProvider`, кнопка `Header.tsx:55-57`, классы `vi-mode/vi-big/vi-noimg`). Замечание: настройка только в localStorage — при запрете сбрасывается; не критично.
- **Метрика:** сейчас выключена (ID не задан) — претензий нет; при включении — только через согласие (HIGH-2 + MEDIUM-5).
- **Реклама (38-ФЗ):** партнёрские ссылки информационные (лого+название, без призывов и трекеров), маркировка не требуется.
