Where: a020 §8 «`NEXT_PUBLIC_YM_ID` интерполируется в инлайн-скрипт без проверки формата» (`app/layout.tsx:15,29`) + «убрать реальный ID из комментария в `.env.example:6`»

ATTACK 6 [MINOR] `noreferrer` без `noopener` — не уязвимость
Where: a020 §7 «Внешние ссылки `target="_blank"` без явного `noopener`» (`PartnersStrip.tsx:29`, `app/page.tsx:95`, `DocsFilter.tsx:43`, «NOOP 0»)
Problem: по спецификации HTML `noreferrer` имплицирует `noopener` во всех современных браузерах — сам a020 это признаёт («современные браузеры трактуют `noreferrer` как `noopener`»). Контрпример с доступным `window.opener` при `rel="noreferrer"` не приведён и невозможен в современном движке. Дополнительно `app/page.tsx:95` ставит `target={d.file_local ? undefined : "_blank"}`, т.е. при внутреннем файле `rel` вообще не при деле. Запись в ranked-списке — шум без сценария эксплуатации.

ATTACK 7 [MINOR] П6 выдумывает требование блокировать карту до согласия и mis-cites НПА
Where: a020 П6 «`GET /contacts` содержит `yandex.ru/map-widget` до согласия | не должен» (строка 25) + §1 «НПА: ст. 9, 18–18.1 152-ФЗ; ст. 10.1 149-ФЗ в части информирования»
Problem: задача требует гейтить согласием только Метрику («cookie-баннер и согласие на Метрику»), про функциональный iframe карты до согласия требования нет; текст баннера «Продолжая, вы соглашаетесь» — модель implied consent, а не opt-in. Ожидание «не должен» в П6 — выдуманное требование без цитаты. Ст. 10.1 149-ФЗ регулирует новостные агрегаторы, а не трекеры/информирование — ссылка ошибочна.
