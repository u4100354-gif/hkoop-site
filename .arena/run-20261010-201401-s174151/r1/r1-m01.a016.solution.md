Дата: 10.10.2026. Аудит по рабочему дереву ветки `backup-2026-10-10` как есть, проект не менялся (только чтение кода и безопасные GET к `http://localhost:3100` и `http://127.0.0.1:8081`). Секреты не печатаются.

## Коротко для руководства

Главная юридическая работа: согласие на cookie, Метрику и виджет карт, честная форма, согласия на публикацию книги почёта.

### 1. HIGH — Уязвимый Next.js 14.2.5

**Место:** `package.json:12` (`"next": "14.2.5"`).

**Проверка (инспекция):** зафиксирован `next 14.2.5` (август 2024). С тех пор ветка 14.2.x получала критические патчи, главная — CVE-2025-29927 (обход авторизации через заголовок `x-middleware-subrequest`, затрагивает все 14.x до 14.2.25). У сайта нет middleware с авторизацией, прямой эксплуатации этой CVE здесь нет, но остаются более поздние патчи 14.2.x (отравление кеша, DoS-векторы), которых в 14.2.5 нет.

**Фикс:** обновить `next` минимум до `14.2.25+` (лучше до последнего 14.x), затем `npx tsc --noEmit` и `STATIC_EXPORT=1 npm run build`, проверить экспорт. Добавить `npm audit` перед каждым деплоем.

### 2. HIGH — Пароли в версионированном `db/README.md`

**Место:** `db/README.md:8-11`.

**Факт:** в файле, который лежит в git, записаны логин и пароль двух пользователей БД в открытом виде. Цитата (пароли скрыты):

```
- root / <скрыто>
- hkoop / <скрыто> (все права на базу hkoop)
```

Кто угодно с доступом к репозиторию (а при публикации на GitHub Pages — потенциально весь интернет через историю git) получает доступы к локальной и любой однотипной базе. Это тот же класс нарушения, что и убранный ранее хардкод пароля в коде, но в другом файле.

**Фикс:** убрать пароли из `db/README.md`, заменить на ссылки на `.env.local` и менеджер секретов; вычистить из истории git (`git filter-repo` или пересоздание истории) и сменить оба пароля; добавить проверку секретов в pre-commit (например, gitleaks).

### 4. MEDIUM — Метрика подключается мимо согласия (152-ФЗ)

**Место:** `app/layout.tsx:27-31`.

**Факт:** скрипт `https://mc.yandex.ru/metrika/tag.js` и `ym(..., "init", ...)` рендерятся всем посетителям, как только задан `NEXT_PUBLIC_YM_ID`, — флаг `hkoop-cookie` нигде не читается:

```tsx
{ym && (<><script dangerouslySetInnerHTML={{__html: `...(window,document,"script","https://mc.yandex.ru/metrika/tag.js","ym");ym(${ym},"init",...`}} />...
```

**Проверка (живой probe):** `GET http://localhost:3100/` — строки `mc.yandex` в HTML нет, в dev счётчик не задан, нарушение сейчас спящее; но стоит задать ID для прода — трекинг включится у всех, включая отказавшихся.

**Норма:** ст. 9 ФЗ-152 (согласие на передачу данных третьей стороне — Яндексу), п. 5 ч. 1 ст. 18.1 ФЗ-152.

**Фикс:** грузить тег только если `lsGet("hkoop-cookie")==="1"` (клиентская обёртка вместо безусловного рендера в layout); при отказе не грузить вообще, включая `noscript`-пиксель.

### 5. MEDIUM — Виджет Яндекс.Карт до согласия (152-ФЗ)

**Место:** `app/contacts/page.tsx:23`, живой probe `GET http://localhost:3100/contacts`.

**Факт:** iframe захардкожен безусловно, флаг согласия не читается:

```tsx
<iframe src="https://yandex.ru/map-widget/v1/?ll=135.0711%2C48.4739&z=16&..."></iframe>
```

Проверка: в HTML страницы `/contacts` строка `yandex.ru/map-widget` есть у любого посетителя, включая того, кто не нажимал «Принять». При загрузке браузер отдаёт Яндексу IP, User-Agent и факт визита — та же передача третьей стороне, что в № 4.

**Норма:** ст. 9, п. 5 ч. 1 ст. 18.1 ФЗ-152.

**Фикс:** фасад click-to-load: вместо iframe — статичная заглушка с кнопкой «Показать карту (данные передаются Яндексу)», iframe создавать только после согласия (или после отдельного клика); добавить `referrerpolicy="no-referrer"` и `loading="lazy"`, обернуть в link на карту для отказавшихся.

### 6. MEDIUM — Iframe-превью PDF без sandbox

**Место:** `components/DocsFilter.tsx:42` (`setPreview(safeHref(d.file_local)!)`), `:56` (`<iframe src={preview} width="100%" height="600" title="PDF" />` без `sandbox`).

**Факт:** `safeHref` режет только схему — любой `https://` проходит. Если в БД окажется `file_local=https://evil.example/phish.html` (через скомпрометированную учётку редактора), он откроется в iframe внутри оформления сайта под заголовком «Просмотр PDF» с возможностью top-навигации и фишинга от имени профсоюзов.

**Фикс:** iframe — только `sandbox=""` (пустой, без `allow-top-navigation` и без `allow-scripts`, если нужен только просмотр PDF); превью в iframe открывать только для site-relative `/docs/*.pdf`, внешнее — ссылкой в новой вкладке с `rel="noreferrer"`.

### 7. MEDIUM — Привилегированная учётка для чтения сайта

**Место:** `lib/db.ts:3-11`, `db/README.md:11`.

**Факт:** сайт делает только SELECT-запросы (все вызовы `q()` — чтение), но пул подключается пользователем, у которого, по README, «все права на базу hkoop». Отдельной read-only учётки нет. Проверка прямым чтением грантов не выполнялась сознательно (не трогать БД и секреты); вывод — по коду и документации. Компрометация сайта или утечка `.env.local` даст запись, удаление и выдачу FILE-привилегий вместо только чтения.

**Фикс:** завести пользователя БД только с `SELECT` на нужные таблицы и перевести пул сайта на него; админские операции оставить отдельной учётке, не хранить её в окружении сайта; отозвать у сайтовой учётки ALL/FILE/GRANT.

### 8. MEDIUM — Книга почёта: публикация ПДн без видимых согласий (152-ФЗ)

**Место:** `app/honor/page.tsx:11-22` (`SELECT * FROM honor`, рендер `h.fio`, `h.photo`, `h.title || h.text`).

**Факт:** на странице массово публикуются ФИО, фото и биографии людей. В коде нет ни пометки о согласиях, ни отдельного текста согласия. Проверка локализации: БД `hkoop` на 127.0.0.1 — данные хранятся в РФ, это хорошо, но публикация биометрических (фото) и общедоступных данных требует письменных согласий.

**Норма:** ст. 10.1 ФЗ-152 (условия обработки ПДн, разрешённых для распространения), ст. 11 ФЗ-152 (биометрические ПДн — фото), ст. 152.1 ГК РФ (изображение гражданина — согласие на публикацию), ст. 18.1 ФЗ-152 (документы оператора).

**Фикс:** собрать и хранить письменные согласия каждого лица (или наследников для ветеранов) на публикацию ФИО, фото и биографии; добавить в дело срок и условие отзыва; при отзыве — снимать карточку; в футер — «Фото и биографии публикуются с согласия указанных лиц».

### 9. MEDIUM — Форма консультации вводит в заблуждение; согласие без реквизитов (152-ФЗ)

**Место:** `components/ConsultForm.tsx:1-14` (на `/` и `/contacts`).

**Факт:** кнопка «Отправить» при `onSubmit={e => e.preventDefault()}` ничего не отправляет и ничего не сообщает — посетитель уходит уверенным, что обращение принято. Чекбокс согласия (`required`) есть, но рядом нет ссылки на политику, названия оператора, целей обработки. Подтверждаю: пока форма ничего не отправляет, обработки ПДн нет, но текст обещает обработку, которой нет, а при появлении бэкенда нынешнего чекбокса не хватит.

**Норма:** ст. 9 ФЗ-152 (содержание согласия), ст. 10 ФЗ от 27.07.2006 № 149-ФЗ (достоверность информации на сайте).

**Фикс:** сейчас — текст под кнопкой «Демо-версия: форма пока никуда не отправляется, звоните 8 (4212) 32-87-18» и ссылка на политику рядом с чекбоксом; при появлении бэкенда — согласие с оператором, целями, сроком + состояния success/error + `maxLength` (см. № 13).

### 10. MEDIUM — Нет заголовков безопасности (прод — статика)

**Место:** `next.config.js` (нет секции `headers`), живой probe.

**Проверка (живой probe):**

```
GET http://localhost:3100/ → 200
Заголовки: Vary, Cache-Control: no-store, must-revalidate, Content-Type — и всё.
Нет: content-security-policy, strict-transport-security, x-frame-options,
x-content-type-options, referrer-policy. X-Powered-By отсутствует (хорошо).
```

**Факт:** `poweredByHeader: false` держится. Но внешние iframe/скрипты (карта, Метрика) ничем не ограничены; страницу можно встроить в чужой iframe (кликджекинг формы).

**Фикс (основной, для статики на GitHub Pages):** meta-CSP в `app/layout.tsx` (allowlist `mc.yandex.ru`, `yandex.ru/map-widget`, `frame-ancestors 'self'`, `object-src 'none'`), JS frame-busting (`if (top !== self) top.location = self.location`), `Referrer-Policy` мета-тегом, cookie только `SameSite=Lax`. Секция `headers()` в `next.config.js` — только как дополнение для dev/preview, потому что при `output: export` Next её игнорирует, а Pages своих заголовков не отдаёт. Для полного закрытия — хостинг с заголовками (Cloudflare/выделенный) вместо чистых Pages; HSTS — только если прод за HTTPS.

### 11. MEDIUM — Пути картинок из БД идут в `src` без проверки (152-ФЗ, приватность)

**Место:** `app/honor/page.tsx:14` (`<img src={h.photo}>`), `components/PartnersStrip.tsx:11` (`<img src={p.logo}>`).

**Факт:** `href` и iframe PDF идут через `safeHref`, а `src` картинок — нет. Уточнение механики: в `<img>`-контексте `javascript:` не исполняется, `data:text/html` как страница не исполняется, скрипты SVG не запускаются — XSS через `img src` здесь нет. Реальный остаточный риск — внешний `https:`-URL из скомпрометированной БД: браузер каждого посетителя запросит чужой сервер и отдаст ему IP и User-Agent (трекинг-пиксель), т.е. передача данных третьей стороне без согласия.

**Проверка (инспекция):** в `PartnersStrip` через `safeHref` идёт только `p.url` (строка 21), `p.logo` — как есть (строка 11); в `honor/page.tsx` `h.photo` не фильтруется.

**Норма:** ст. 9, п. 5 ч. 1 ст. 18.1 ФЗ-152 (передача данных третьей стороне требует согласия).

**Фикс:** пропускать `h.photo` и `p.logo` через `safeHref` (или отдельный `safeImgSrc`: только site-relative и доверенные CDN), при `null` — заглушка (в honor она уже есть).

### 12. LOW — `safeHref` пропускает любой `https:` (фишинг доверия)

**Место:** `lib/url.ts:3-9`.

**Факт:** регулярка `/^(https?:\/\/|\/[^/\\])/i` корректно режет `javascript:`, `data:`, `//evil`, ограничивает длину 2000. Но `https://любой-фишинг.example` из скомпрометированной БД отрендерится как доверенная ссылка сайта (партнёрские идут в `_blank` с `rel="noreferrer"` — табнаббинг закрыт, фишинг доверия остаётся).

**Фикс:** для соцсетей держать точный allowlist (`vk.com`, `t.me`, `max.ru`, `yandex.ru`), для партнёров — ручная модерация и периодическая сверка `partners.url` с известным списком глазами (только SELECT, без изменений).

### 13. LOW — Поля форм без `maxLength` и типов

**Место:** `components/ConsultForm.tsx:5-7`, `components/HeaderSearch.tsx:50-61`, `components/DocsFilter.tsx:28`, `components/NewsFilter.tsx:27-34`, `app/search/page.tsx:34`.

**Факт:** ни у одного текстового поля нет `maxLength`; у «Телефон или email» нет `type="tel"`. Сейчас урона нет (форма никуда не шлёт, поиск — клиентский фильтр по статике).

**Проверки (живые пробы):**
- `GET /search?q=<img src=x onerror=alert(1)>` — в HTML только экранированное `&lt;img`, живого `onerror`-исполнения нет; рендер результатов идёт через текстовые узлы React (`{r.title}`), `defaultValue` экранируется.
- `GET /search?q=` + 1200 символов «A» → 200, без падения и без стектрейса.
- `GET /api/test` → 404 (поверхности записи через сайт нет).
- `GET /news/../..`, кривые id → дружелюбное «Не найдено», файлового чтения по `id` нет (всё уходит параметром `WHERE id=?` в `app/news/[id]/page.tsx:17`).

**Фикс:** `maxLength={200}` имени/контакту/поискам, `maxLength={2000}` вопросу; контакту — `type="tel"` + `autoComplete="tel email"`; лимиты продублировать серверной валидацией при появлении приёма данных.

### 14. LOW — Версия для слабовидящих есть, но недожата (ГОСТ Р 52872-2019)

**Место:** `components/ViProvider.tsx`, `components/Header.tsx:55-57`.

**Норма:** ГОСТ Р 52872-2019 (доступность сайтов для слабовидящих).

**Фикс:** сохранять все флаги, добавить 2–3 цветовые схемы по ГОСТ, кнопке — `aria-pressed`, проверить контраст (WCAG AA 4.5:1).

### 15. LOW — Логотипы и фото: оформить права (оргмера)

**Факт:** используются чужие товарные знаки (логотипы партнёров) и фото людей. Признаков нарушения в коде нет, ссылки — обычные информационные без `utm_*` и призывов покупать, что соответствует позиции ФАС: простое упоминание партнёра не реклама по ст. 16 ФЗ от 13.03.2006 № 38-ФЗ. Но согласия должны лежать в папке.

**Норма:** ст. 1229, 1484 ГК РФ (товарные знаки), ст. 152.1 ГК РФ (изображение гражданина).

**Фикс:** собрать согласия правообладателей и лиц с фото в дело; в футер — «Использование материалов — с разрешения правообладателей».
