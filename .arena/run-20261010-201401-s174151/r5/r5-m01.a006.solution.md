# Аудит сайта ХКООП: безопасность и соответствие законам РФ (включая 152-ФЗ)

Дата: 10.10.2026. Объект: рабочее дерево `hkoop-site` (ветка `backup-2026-10-10`), dev http://localhost:3100. Проект не менялся: только чтение кода и безопасные GET-пробы. Секреты не печатаются. Язык отчёта — русский.

## Допущения

1. Прод — статический экспорт (`output: export` при `STATIC_EXPORT=1`, `next.config.js:6-7`) на GitHub Pages; заголовки ниже замерены только на dev и помечены «замер dev». Вывод о проде — по коду (заголовки нигде не задаются), а не по прод-замеру.
2. В проекте нет `middleware.*` и нет `app/api/**` — серверных мутаций нет; это смягчает, но не снимает supply-chain риск сборки/dev.
3. Счётчик Метрики через `NEXT_PUBLIC_YM_ID` в проверяемом окружении не задан (проба: `mc.yandex` в `/` отсутствует) — дефект согласия латентный.
4. Пароли из `db/README.md`/`docs/` никуда не вводились; phpMyAdmin проверен только безопасным GET без входа.
5. CVE-данные — по версии в `package.json` и открытым бюллетеням Next.js; воспроизводимая команда аудита приведена в H3 (полный вывод сверить повторным прогоном).

## Как читать отчёт

Каждая находка: severity → место → проверка (команда и вывод/цитата) → факт → фикс (описать, не применять). Юридические пункты содержат статью НПА. Порядок — HIGH → MEDIUM → LOW. В конце — чек-лист покрытия требований и вердикт одной строкой.

## HIGH

### H1. Пароли БД открытым текстом в отслеживаемых файлах
- **Место:** `db/README.md:8-11,20,22`; дубль в `docs/ИНСТРУКЦИЯ-ПРЕСС-СЛУЖБЕ.md:28`.
- **Проверка (инспекция):** оба файла лежат в рабочем дереве с логином/паролем root и `hkoop` + готовыми командами `mysql -u hkoop -p'...'`. `.gitignore:1-8` закрывает только `.env`/`.env.local`, эти `.md` — нет.
- **Факт:** любой `git push`/копия архива уносит секреты; после утечки обязательна ротация. «Только локальные» не снимает риска: dev-пароли переезжают в прод, а в связке с H4 дают перезапись БД.
- **Фикс (долговечный):** секреты только в `.env.local`; в документации плейсхолдеры `mysql -u $DB_USER -p"$DB_PASS"`; сменить оба пароля; проверить историю (`git log -p -- db/README.md docs/ИНСТРУКЦИЯ-ПРЕСС-СЛУЖБЕ.md`), ушедшие считать скомпрометированными; pre-commit-хук на секреты (gitleaks).

### H2. Нет охранных HTTP-заголовков (замер только dev; в коде заголовки нигде не задаются)
- **Место:** `next.config.js:1-27` (секции `headers()` нет); эффект — все URL сайта.
- **Проверка (живая проба, только dev):**
  ```
  GET / → 200; Content-Security-Policy: нет; X-Frame-Options: нет;
  X-Content-Type-Options: нет; Referrer-Policy: нет; X-Powered-By: нет (держится)
  ```
  Прод-замер не выполнялся — вывод о проде следует из кода, а не из прод-пробы.
- **Факт:** встраивание в чужой `iframe` (кликджекинг), нет барьера для инлайн-скриптов и сниффинга типов.
- **Фикс (два трека, без применения):** (А) внутри репозитория: `rel="noreferrer noopener"` на внешних ссылках, `sandbox`+`referrerpolicy="no-referrer"`+`loading="lazy"` на iframe, клик-ту-загрузка карты (см. M3), `<meta name="referrer" content="strict-origin-when-cross-origin">` и `<meta http-equiv="Content-Security-Policy">` как частичная компенсация. Честные ограничения meta-CSP: директива `frame-ancestors` в `<meta>` игнорируется по спецификации (кликджекинг ею не закрыть); `script-src 'self'` без хешей заблокирует собственные инлайн-скрипты `app/layout.tsx:19` (`classList.add('js')`) и `:29` (инициализация Метрики) — поэтому в meta-CSP инлайн закрыть только хешами (`'sha256-...'` обоих скриптов) либо оставить их вне директивы до переезда. (Б) опционально, вне репозитория: прод за прокси/CDN с заголовками `Content-Security-Policy` (с `frame-ancestors 'self'`), `X-Content-Type-Options: nosniff`, `Referrer-Policy`, HSTS. Трек А — в любом случае.

### H3. Next.js 14.2.5 с известными уязвимостями + транзитивный postcss — обновить (HIGH, не CRITICAL: серверного вектора в проде сегодня нет)
- **Место:** `package.json:12` (`"next": "14.2.5"`); прямых зависимостей только `mysql2/next/react/react-dom` (`package.json:10-15`).
- **Проверка (инспекция + воспроизводимая команда):** версия `14.2.5` (август 2024), Dependabot-конфига нет; `middleware.*` отсутствует, `app/api/**` пуст. Воспроизводимая проверка (вывод сверить повторным прогоном):
  ```
  npm ls next  →  hkoop-new@0.1.0 -- next@14.2.5
  npm audit --audit-level=high  →  блок next (Severity: critical, диапазон включает 14.2.5)
    + блок postcss <=8.5.22 (Severity: high, транзитивный через next)
    итог: 2 vulnerabilities (1 high, 1 critical); рецепт: next@14.2.35
  ```
  Ключевые бюллетени ветки: CVE-2025-29927 (обход через `x-middleware-subrequest`, требует middleware — в проекте негде, исправлен в 14.2.25+), семейство cache-poisoning/DoS (напр. CVE-2024-46982, закрыто в 14.2.9–14.2.15). CVE-2024-39332 к Next.js не относится и не вменяется.
- **Факт:** прямого RCE/обхода в статическом проде сегодня нет (CRITICAL был бы завышением), но сборка и dev крутятся на уязвимом рантайме, а будущее middleware/API унаследует дыру молча.
- **Фикс:** поднять `next` до `14.2.35` (рецепт аудита, не ниже), затем свежие 18.x `react/react-dom`; прогнать `npx tsc --noEmit`, `npm audit --audit-level=high`, `STATIC_EXPORT=1 npm run build`; включить Dependabot monthly + `npm audit` в CI. `npm audit fix --force` — только в отдельной ветке (может прыгнуть мажором).

### H4. MySQL-пользователь `hkoop` имеет ALL PRIVILEGES при SELECT-only коде (least privilege нарушен)
- **Место:** `lib/db.ts:3-11` (пул от имени `DB_USER`, по умолчанию `hkoop`).
- **Проверка (инспекция, без подключения к БД):** `grep GRANT db/schema.sql` пуст — ожидаемо (`schema.sql:1-48` содержит только `CREATE TABLE`, грантов там быть не может, доказательством не является). Доказательство избыточности: `db/README.md:11` — «все права на базу hkoop» (`GRANT ALL PRIVILEGES ON hkoop.*`), а весь код сайта делает только `SELECT` через `q()` (INSERT/UPDATE/DELETE/DROP отсутствуют; единственный параметр — `WHERE id=?`). Прямой `SHOW GRANTS` в рамках аудита не выполнялся (дисциплина «БД только SELECT»); владельцу перепроверить read-only `SHOW GRANTS;` тем же соединением из `.env.local` (секреты не печатать).
- **Факт:** компрометация читающего сайта (особенно в связке с H1) превращается в перезапись/сброс схемы; сайту достаточно `SELECT`.
- **Фикс:** `REVOKE ALL PRIVILEGES ON hkoop.* FROM 'hkoop'@'localhost'; GRANT SELECT ON hkoop.* TO 'hkoop'@'localhost';` записи/миграции — отдельной учёткой; вывод грантов хранить закрыто.

### M4. Второй dangerouslySetInnerHTML с интерполяцией env без валидации (XSS-sink при контроле окружения)

Значение вида `1);alert(1);//` разрывает вызов и инжектит скрипт. Это не пользовательский ввод из запроса (эксплуатация требует контроля env при сборке), поэтому не HIGH/CRITICAL.

### M5. Политика конфиденциальности — скан без текстового слоя: информированность согласия не проверена
- **Место:** `public/docs/politika.pdf` (`GET /docs/politika.pdf → 200`).

- **Факт:** полноту по ст. 9/18.1 Закона № 152-ФЗ (оператор, цели, сроки, права субъекта, cookies/Метрика) машинно проверить нельзя; ссылки баннера и чекбокса ведут на нечитаемый текст — согласие нельзя признать информированным.

- **Фикс:** опубликовать текстовую версию (HTML-раздел + PDF с текстовым слоем/OCR) с покрытием ст. 18.1, версионировать вместе с баннером; скан оставить подписанной копией.

## LOW

### L1. Два img-src из БД без allowlist (defense-in-depth, эксплуатируемого PoC нет)
- **Место:** `app/honor/page.tsx:14` (`<img src={h.photo}>`); `components/PartnersStrip.tsx:11` (`<img src={p.logo}>`).
- **Проверка:** соседние рендеры фильтруются `safeHref`, эти два `src` — нет. React экранирует атрибуты, браузеры не исполняют `javascript:` в `<img src>` — активного XSS нет; риск — чужой/битый путь при правке БД. Кириллические https-домены `lib/url.ts:7` не ломает (первая альтернатива `https?://`).
- **Факт:** отсутствует второй рубеж там, где `<a href>` уже закрыт.
- **Фикс:** `safeSrc` рядом с `safeHref` (тот же allowlist, без переписывания кириллицы), при `null` — плейсхолдер; `referrerPolicy="no-referrer"` для внешних логотипов.

### L2. Внешние ссылки партнёров без явного `noopener`; блок информационный
- **Место:** `components/PartnersStrip.tsx:29`; `app/page.tsx:95`. Проба: `noreferrer=13, noopener=0, _blank=13`.
- **Проверка:** `rel="noreferrer"` в современных браузерах включает поведение `noopener` (reverse-tabnabbing закрыт); явный `noopener` — второй рубеж для старых движков. `safeHref` пускает любой `https://`.
- **НПА (смежно):** ст. 10 Закона № 149-ФЗ; блок информационный (без «купить/скидка», без трекеров) — маркировка по ст. 18.1 Закона № 38-ФЗ не требуется, зафиксировать регламентом.
- **Фикс:** `rel="noreferrer noopener"` везде с `_blank`; платные размещения — только с пометкой «Реклама» + erid.

### L3. PDF-превью без песочницы; внешний https допустим как src iframe
- **Место:** `components/DocsFilter.tsx:42,56` (`<iframe src={preview} ...>` без `sandbox`).
- **Факт:** `preview` отфильтрован `safeHref`, но любой `https://` из `file_local` встанет в iframe — при компрометации БД фишинг-окно внутри доверенного домена.
- **Фикс:** `sandbox=""`, `referrerPolicy="no-referrer"`, `loading="lazy"`; превью только для site-relative `/docs/*.pdf`, внешние — ссылкой через `file_old`.

### L4. Поля форм и поиска: странные/длинные вводы не ломают сайт, но лимитов нет (живые пробы)
